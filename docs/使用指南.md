## 1. 项目简介与适用场景

### 1.1 这是什么

InSAR Studio 是一个完全本地运行的 InSAR 时序形变处理工作台。它把数据接入、五个处理阶段（配准、网络、干涉、大气、反演）和成果输出串成一条可复现的处理链：

```text
数据接入 → 配准 → 干涉网络 → 差分干涉 → 大气校正 → 时序反演 → 成果输出
```

软件提供中文分步向导，默认参数可以直接跑完演示项目；专家模式可以调整基线、滤波、解缠、反演和 PS/DS 的关键参数。所有项目、数组、图件、报告和导出包都保存在本地 `workspace/` 下，不依赖数据库、消息队列或云服务。

### 1.2 四条技术路线

| 路线 | 处理方式 | 适用场景 | 默认网络 | 主要输出 |
| --- | --- | --- | --- | --- |
| **SBAS-InSAR** | 小基线集 + 加权最小二乘 + 时间正则 | 区域沉降、滑坡、城市形变，默认推荐 | 最大时间基线 72 天 | 时序位移、速率、相干性、残差 |
| **PS-InSAR** | 单主影像星形 + 相邻对闭环，按 ADI 和相干性选点 | 城市建筑、桥梁、裸岩、强散射点 | 全星形 + 相邻对；关闭全星形后受 96 天时间基线限制 | PS 候选点、时序位移、速率 |
| **DS-InSAR** | 局部相干矩阵 + 特征分解相位链接，再联合解算 | 植被、农田、裸土等低相干区 | 小基线集，最大时间基线 72 天 | DS 相干性、时序位移、速率 |
| **D-InSAR** | 单干涉对差分，解缠相位直接转 LOS 位移 | 同震、突发滑坡、应急踏勘 | 单对，默认第 `n//3` 景与最后一景 | 单帧位移、相干性、缠绕相位 |

四条路线共用同一套配准、干涉、滤波、解缠和成果输出代码。路线差异主要在网络构造、PS 选点、DS 相位链接和反演输入。

### 1.3 适合什么场景

| 场景 | 推荐路线 | 说明 |
| --- | --- | --- |
| 第一次接触 InSAR，想理解完整链路 | SBAS | 演示项目默认路线，网络稳健，结果容易解读 |
| 城市建筑、桥梁、岩石裸露区的点目标监测 | PS | 强散射点保留，适合做毫米级变化趋势的算法验证 |
| 植被、农田、裸土等低相干区 | DS | 相位链接可以提升低相干区的覆盖，但计算量更大 |
| 同震、滑坡、单次事件的快速差分 | D-InSAR | 单对最快，适合快速查看空间形态 |
| 教学、课程设计、算法回归 | 任意路线 | 合成数据有真值，可量化检查链路 |
| 离线环境、数据不能出本机 | 任意路线 | 软件默认只监听 `127.0.0.1`；不使用在线下载或任何 GACOS 时可以完全离线运行 |

### 1.4 不适合什么场景

- 不作为生产级、计量认证的形变监测系统。
- 不执行 Sentinel-1 burst 级 TOPS 配准、去斜和拼接；可在导入后用本地 EOF 精密轨道估计垂直基线，但不做轨道误差改正。真实 TOPS 数据应先在 SNAP、ISCE 或 Gamma 中预处理。
- 可在导入后对具备参考轨道和完整几何元数据的整景栈做距离-多普勒地理编码，输出 EPSG:4326 地图网格；大网格会自动按行分块并用最多 4 个线程求解查找表。不做 burst 级 TOPS 配准、去斜、拼接、轨道误差改正、投影变换或跨 180° 经线处理。真实 TOPS 数据仍应先在 SNAP、ISCE 或 Gamma 中预处理。
- 不做升轨/降轨联合分解、方位向/距离向分解、GNSS 或水准融合。
- 不做断层滑动反演、震源参数反演、角反射器识别。
- 不提供用户认证、权限隔离、审计日志和多租户能力；不要直接暴露到公网。
- 不保证 GACOS 官方服务、自定义在线 GACOS、Copernicus Data Space、ASF 等外部服务的长期可用性。

### 1.5 实测性能与容量边界

以下数字来自本机 `Intel 16 逻辑核 / 15.7 GB RAM / Windows` 的合成数据压力测试，使用的是独立 `stress/workspace`，不是真实 SLC：

| 项目 | 实测结果 | 使用含义 |
| --- | --- | --- |
| 历史演示 SBAS 全流程 B0 | `18.96 s` | 单用户交互式处理可以接受 |
| 历史基准四路线 | SBAS `23.11 s`、PS `47.18 s`、DS `24.38 s`、D-InSAR `4.15 s` | 路线耗时差异主要来自网络对数和 PS/DS 计算 |
| 4 个作业并发 | 单作业中位 `56.61 s`，并行效率 `0.334` | 进程内线程并发几乎没有吞吐收益 |
| 8 个作业并发 | 小数据单作业中位 `100.56 s`，为小数据单实例 `12.13 s` 的 `8.29×` | 不建议把 8 个作业同时提交 |
| 16 线程 API 压测 | 总 p95 `11.31 s`；`/api/projects` 端点 p95 `11.96 s` | 项目列表全量扫描是主要瓶颈 |
| 204 个项目列表 | p95 `1.71 s` | 项目越多，列表越慢（P3-1 前的全量扫描结果） |
| 300 个项目列表（P3-1 后） | 首屏 60 项 `0.16 s`，缓存命中 `0.003 s`，完整 300 行 `0.41 s` | 分页 + 5 秒目录/行缓存；侧栏只取当前页，任务完成后强制刷新 |
| 200 项目 + 1000 对浏览器渲染 | 首屏热缓存 `0.90 s`；网络页 `0.47–0.59 s`；干涉页 `0.27–0.45 s` | Chromium 1440×900；1000 条网络线 + 1000 行表格约 1.1 万 DOM 节点，JS 堆 10 MB |
| 3000 对项目浏览器渲染 | 网络页 `1.18 s` / 3.3 万 DOM 节点；干涉下拉 `0.78 s` | 1000 对以内无需分页；3000 对仍可用，超过后建议再考虑表格分块或虚拟滚动 |
| 31 个项目 / 3.6 万文件冷启动（P3-5 后） | 列表 `0.098 s`（优化前 `4.70 s`）；TTL 过期后 `0.060 s` | 列表行不再递归统计体积；6000 文件项目概览 `4 ms` / `4 KiB`，成果页按需返回文件清单 `255 ms` / `567 KiB` |
| 5000×5000 地理编码查找表 | `89.4 s`，峰值 RSS 增量约 `418 MB` | 分块 + 最多 4 线程；输出数组约 325 MB |
| 1.02 GB 导入预检（P3-3 后） | 轻量 `0.19 s` / 峰值 RSS +`115 MB`；深度 `2.43 s` / +`1536 MB`；正式导入 `4.57 s` / +`1536 MB` | 8×4000×4000 complex64；轻量只读头部 + 4M 像元连续块，警告与深度预检一致 |
| 48 景 × 700 × 700 大栈（P3-6 后） | SBAS 160 对 `295.7 s` / 峰值 RSS +`689 MB`；PS 93 对 `698.2 s` / +`1625 MB`；DS 160 对 `321.9 s` / +`942 MB` | 单进程完整五阶段；PS 反演旧实现约 `5.2 GB`，重写后进程峰值 `1.65 GB`；SBAS/DS 使用 `multilook=2`，PS 单视 |
| 30 轮长稳 | RSS `165.0 → 272.1 MB`，句柄 `671 → 1050` | 长时间运行需要关注资源增长 |
| 48×440×520 合成规模 | 完成 `102.9 s`，峰值 RSS `702.0 MB` | 单进程内存可控制在 1 GB 以内，但真实数据需更高余量 |

当前版本四套 canonical 演示（24 景、220 × 260）的本机全流程耗时为 SBAS 17.3 s、PS 33.6 s、DS 18.1 s、D-InSAR 4.2 s。上表是历史压力测试，机器状态、数据规模和参数与本轮回归不同，两组数字不能直接比较。

结论：当前版本适合单用户、单机、串行或最多 2 个轻量作业的使用方式。需要多用户并发时，应先改造成进程级 worker 或独立作业进程，不能直接把当前 Flask 单进程服务当多人服务使用。以上数字只用于判断量级，不是对真实数据或生产环境的性能承诺；最新一轮四路线回归耗时以技术说明第 0 节为准。

## 2. 安装与环境准备

### 2.1 系统要求

| 项目 | 最低 | 推荐 |
| --- | --- | --- |
| 操作系统 | Windows 10/11、Linux、macOS | Windows 10/11 或 Ubuntu 22.04 |
| Python | 3.9，64 位 | 3.11，64 位 |
| 内存 | 4 GB 可用 | 8 GB 以上；真实大栈 16 GB 以上 |
| CPU | 2 核 | 4 核以上 |
| 磁盘 | 2 GB 程序 + 数据空间 | 20 GB 以上，另加原始数据和成果空间 |
| 浏览器 | 现代 Chrome、Edge、Firefox | Chrome 或 Edge |
| GPU | 不需要 | 不需要 |

首次安装依赖需要联网；依赖装好后可以离线运行。软件不会自动上传数据，但 GACOS 官方申请/邮件导入、自定义在线 GACOS、Sentinel-1 下载等功能会访问外部服务。

**内存预算**：配准、干涉和反演开始前会估算峰值内存。如果预计超过当前可用物理内存的 90%，任务会提前停止并返回阶段、预计峰值和缩减建议，而不是等到系统强制终止。自动检测覆盖 Windows、Linux 和 macOS；在容器、虚拟机或共享机器上，可以显式覆盖：

```powershell
$env:INSAR_MEMORY_BUDGET_BYTES = "8G"
python -m insar_studio serve
```

值可以是纯字节数，也可以带 `K/M/G/T` 后缀。这个预算是上限而不是预留，估算也不覆盖 Python 对象、图件和内存碎片；真实大栈仍应先在目标机器上小规模试跑，观察任务管理器或 `ps` 的 RSS。

### 2.2 Windows 一键启动

1. 安装 Python 3.9–3.11 64 位（推荐 3.11），安装时勾选 “Add python.exe to PATH”。`start.bat` 会优先选择 3.11/3.10/3.9，再回退到 PATH 和更新版本；如果本机同时装了 3.12 或 3.13，建议先按 2.3 节用 3.11 建虚拟环境，避免依赖轮子不兼容。
2. 双击项目根目录的 `start.bat`；只想检查环境和依赖时运行 `start.bat --check`。
3. 脚本会通过 `scripts/bootstrap.py` 检查依赖；缺失时自动创建项目内 `.venv` 并安装 `requirements.txt`，只需一次。
4. 服务默认从 `8765` 起自动选择空闲端口，并自动打开浏览器；终端会打印实际地址。
5. 保持命令行窗口打开。关闭窗口或按 `Ctrl+C` 停止服务。

如果依赖安装失败，先看窗口里的错误，再执行：

```powershell
cd D:\path\to\insar-studio
python -m insar_studio doctor
```

**收到别人分享的发布 ZIP 时**，不要直接双击 ZIP 里的文件：

1. 确认 ZIP 和同名 `.sha256` 文件在一起，先按包内根目录的 `RELEASE.md` 校验哈希；
2. 解压到路径较短、没有特殊字符的本地目录，例如 `D:\insar-studio`；
3. 先运行 `start.bat --check` 查看环境；如果只提示缺少依赖，继续双击 `start.bat` 让脚本自动安装，如果提示 Python 版本或 32 位问题，先安装 64 位 Python 3.11；
4. 第一次启动会在包内创建 `.venv` 并安装依赖，需要联网；发布包本身不包含 `workspace/`，演示项目会在本机重新生成。

Linux / macOS 把 `start.bat` 换成 `bash start.sh` 即可。

### 2.3 手动安装

Windows PowerShell：

```powershell
cd D:\path\to\insar-studio

# 可选：创建独立环境
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
python -m pip install -r requirements.txt

# 自检
python -m insar_studio doctor

# 启动并自动打开浏览器
python -m insar_studio serve --open
```

如果 PowerShell 阻止激活脚本，可以改用：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m insar_studio serve --open
```

Linux / macOS：

```bash
cd /path/to/insar-studio
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m insar_studio doctor
python -m insar_studio serve --open
```

也可以直接运行：

```bash
bash start.sh
```

### 2.6 环境变量

| 变量 | 默认值 | 作用 | 注意 |
| --- | --- | --- | --- |
| `INSAR_STUDIO_WORKSPACE` | `<repo>/workspace` | 指定工作区根目录 | 在 `config.py` 导入时读取，必须在启动进程前设置 |
| `INSAR_STUDIO_HOST` | `127.0.0.1` | 监听地址 | 只对直接调用 `server.main()` 生效；CLI 会传 `--host`，请用 `--host 0.0.0.0` 显式指定。暴露到局域网前先加认证 |
| `INSAR_STUDIO_PORT` | `8765` | 起始端口 | 只对直接调用 `server.main()` 生效；CLI 默认传 `--port 8765`，请用 `--port` 指定。`0` 表示系统分配 |
| `INSAR_STUDIO_DEBUG` | `0` | 开启 Flask 调试 | 调试模式的 500 响应会带 traceback，不要共享开启 |
| `INSAR_STUDIO_OPEN` | `0` | 启动后打开浏览器 | 等价于 `--open` |
| `INSAR_STUDIO_STRICT_PORT` | `0` | 端口占用直接失败 | 否则从起始端口向后尝试 29 个端口 |

`INSAR_STUDIO_DEBUG`、`INSAR_STUDIO_OPEN`、`INSAR_STUDIO_STRICT_PORT` 在 `python -m insar_studio serve` 下仍会生效；`INSAR_STUDIO_HOST/PORT` 会被 CLI 的默认参数覆盖。

仓库根目录提供了 `.env.example` 作为变量清单。程序**不会自动加载** `.env`，需要先把变量导入当前 shell，或在系统环境变量中设置；真实的 `.env` 已被 `.gitignore` 忽略，不要提交。

示例：把工作区放到 D 盘独立目录，避免备份时把程序和数据混在一起。

```powershell
$env:INSAR_STUDIO_WORKSPACE = "D:\insar_workspace"
python -m insar_studio serve --open
```

### 2.7 可选组件 SNAPHU

默认解缠算法是内置质量引导，不安装 SNAPHU 也能完整跑通。需要对比 SNAPHU 时：

1. 安装 SNAPHU，确保 `snaphu` 在 `PATH` 中，或在参数里设置 `snaphu_exe` 的绝对路径。
2. 运行 `python -m insar_studio doctor`，确认 SNAPHU 检查项为可用。
3. 在干涉步骤把解缠算法切到 SNAPHU。若调用失败，程序会自动回退质量引导，并在 `unwrap_info` 中记录原因。

### 2.8 工作区与升级

- 默认工作区是项目根目录下的 `workspace/`，其中 `projects/` 保存项目，`jobs/` 保存作业，`cache/` 保存缓存，`logs/` 保存日志。
- 升级前先备份 `workspace/projects/`；项目目录可以整体复制到新机器。
- 升级后建议先跑 `python -m insar_studio doctor` 和 `python -m pytest -q`，再打开旧项目做一次项目体检。
- 删除项目会删除对应目录，且不可恢复；不要把唯一副本放在 `workspace/` 里。

## 3. 快速上手

### 3.1 五分钟跑通演示

1. 启动服务，浏览器打开终端打印的地址，例如 `http://127.0.0.1:8765`。
2. 左侧项目库选择任意演示项目；如果没有项目，点击欢迎页的“用演示数据跑一遍”。
3. 在顶部工具栏点击“一键跑完全流程”（切到“7 成果”也能看到同一个按钮）。
4. 观察右下任务控制台依次显示：配准 → 网络 → 干涉 → 大气 → 反演。
5. 完成后页面自动跳到成果页。重点看：
   - 速率中位数和（演示数据的）位移 RMSE；
   - 速率图、时序相干性图、残差图；

演示数据的真值只用于算法回归，不能当作真实场景精度。演示项目的默认大气方法是“演示 GACOS”，它使用与合成数据一致的模拟大气，用来观察校正上限。

### 3.4 导入自己的最小数据栈

准备一个目录：

```text
my_stack/
  slc.npy          # complex64, (n_dates, rows, cols)，必需
  dem.npy          # float32, (rows, cols)，可选
  mask.npy         # bool, (rows, cols)，可选
  meta.json        # 日期、平台、基线等元数据，强烈建议
```

`meta.json` 最小示例：

```json
{
  "dates": ["2023-01-03", "2023-01-15", "2023-01-27"],
  "platform": "Sentinel-1A",
  "orbit_direction": "DESCENDING",
  "relative_orbit": 42,
  "bperp_m": [-35.2, 12.8, 64.1],
  "incidence_deg": 38.5,
  "range_spacing_m": 2.33,
  "azimuth_spacing_m": 13.97
}
```

操作步骤：

1. 点击左侧“+ 新建”，选择“导入本地数据”。
2. 填写数据目录或单个 `.npz` 文件路径，可选填 DEM。
3. 如果整栈已经在 SNAP/ISCE 等工具中配准完成，勾选“导入的 SLC 已经配准”。
4. 创建后进入“数据”页，核对预检警告、日期、尺寸、掩膜和振幅预览。
5. 进入“网络”页生成网络；预配准栈会直接复用，其余数据先自动配准。
6. 依次运行干涉、大气、反演，或在成果页“一键跑完全流程”。

已有项目重新导入时，点击“预检并导入”会先做只读检查，显示景数、尺寸、地理参考、验证级别（`full`/`sampled`/`header`）和全部警告；确认后才覆盖当前栈。

预检默认是轻量的：小栈会完整抽样（`full`），大 `.npy`/原生目录只读头部和最多 4M 像元连续块（`sampled`），`.npz`/ENVI/GeoTIFF/SAFE 只读文件头（`header`）。正式导入始终完整读取并校验全部像元；需要强制完整预检时，可在 API 请求体里加 `"deep": true`。1.02 GB 的 8×4000×4000 栈实测轻量预检 0.19 秒、峰值内存增量约 115 MB，深度预检 2.43 秒、约 1536 MB。

如果缺少 `bperp_m`，垂直基线会被置零，DEM 误差估计不可用；如果缺少 `dates`，会按 12 天间隔补齐，并在 `dates_source` 中标记为 `inferred`；如果缺少 `corner_lon`/`corner_lat`，会明确警告成果使用像元坐标。导入后务必核对日期顺序、尺寸和预检警告。

如果希望反演后自动输出地图坐标 GeoTIFF，还需要在 `meta.json` 中提供 `start_times`（每景首行 UTC 时间）、`azimuth_time_interval`、`range_spacing_m`，以及 `slant_range_time_s` 或显式的 `slant_range_m`；同时把 Sentinel-1 `.EOF` 轨道文件放在数据目录、父目录或 `orbit_dir` 指定的目录。缺少任何关键项时，`products/geocode.json` 会写 `unavailable` 并说明原因，产品仍保留在雷达网格。

## 4. 主要功能与用法

### 4.1 界面结构

| 区域 | 作用 |
| --- | --- |
| 左侧项目库 | 搜索、分页加载、切换、新建、删除项目；显示路线、影像数和进度 |
| 顶部栏 | 引导/专家模式切换、帮助、环境自检、版本标识 |
| 项目标题区 | 数据源、时间范围、影像数、尺寸、项目体检、一键跑完 |
| 七步导航 | 项目 → 数据 → 网络 → 干涉 → 大气 → 反演 → 成果 |
| 中间内容区 | 当前步骤的指标、图件、参数和操作按钮 |
| 右下任务控制台 | 进度、阶段、日志；运行中自动展开 |

引导模式只显示常用参数，专家模式显示全部参数。切换模式不会改变已经保存的参数，只影响显示。

### 4.2 项目管理

支持三种创建方式：

- **演示项目**：选择 SBAS/PS/DS/D-InSAR，自动生成 24 景、220 × 260 像元的合成栈。
- **导入项目**：创建空项目后导入本地栈，适合真实数据。
- **空项目**：只创建项目骨架，稍后再导入数据。

项目库默认每页显示 60 个，底部「加载更多」继续取下一页；搜索框在服务端按名称和项目 ID 过滤，输入后约 250 ms 自动刷新。当前打开的项目即使不在第一页，也会保留在侧栏顶部，不会被刷新隐藏。

常用操作：

| 操作 | 说明 |
| --- | --- |
| 刷新 | 重新读取磁盘上的项目状态和产品 |
| 项目体检 | 只读检查数据、参数指纹、配准、网络、干涉、大气、反演、报告和磁盘空间 |
| 重置处理结果 | 清空干涉、大气、反演和导出成果，删除 `data/network.json` 和 DS 参考缓存；默认保留配准栈 |
| 重新校验 | 对演示数据重新计算真值指标 |
| 删除项目 | 删除整个项目目录，不可恢复 |

同一项目同一时间只允许一个处理任务。运行中重复提交会返回 HTTP 409；刷新页面后如果任务仍在运行，页面会自动重连。

切换技术路线时，系统会清理下游产品，并把这 5 个路由参数重置为新路线默认值：`multilook`、`max_temporal_baseline`、`max_pairs`、`ps_star_all`、`ds_patch`。其他参数保留；如果不想让某个路由参数被重置，需要在同一次请求的 `params` 里显式传值。切换路线会导致重新配准、网络、干涉、大气和反演，耗时比单阶段重跑更长。

### 4.3 数据接入

#### 4.3.1 NumPy 目录

```text
my_stack/
  slc.npy
  dem.npy
  mask.npy
  meta.json
```

要求：

- `slc.npy`：`complex64`，形状 `(n_dates, rows, cols)`。
- `dem.npy`：`float32`，形状 `(rows, cols)`，单位米。
- `mask.npy`：`bool`，形状 `(rows, cols)`，`True` 为有效。
- `meta.json`：建议至少包含 `dates`；有 `bperp_m` 才能做 DEM 误差估计；整栈已配准时可写 `"already_coregistered": true`。要输出地图坐标，还需 `start_times`、`azimuth_time_interval`、`range_spacing_m`、`slant_range_time_s` 或显式 `slant_range_m`，并让导入器找到本地 `.EOF`；有 `corner_lon`/`corner_lat`/`lon_step`/`lat_step` 且 `geo_referenced=true` 时优先复用该网格。

#### 4.3.2 `.npz` 打包

```text
stack.npz
  slc       # complex64, (n_dates, rows, cols)，必需
  dem       # float32, (rows, cols)，可选
  mask      # bool, (rows, cols)，可选
  dates     # 字符串数组，可选
  meta      # JSON 字符串，可选
```

`dates` 优先从数组读取，其次从 `meta["dates"]` 读取；导入时会按日期升序重排，并同步重映射 `bperp_m` 和 `ref_index`。

#### 4.3.3 其他格式

| 格式 | 说明 | 注意事项 |
| --- | --- | --- |
| ENVI 栈 | `.hdr` + 同名 `.dat/.img` | 复数数据类型建议 `complex64`（ENVI type 6），也支持 `complex128`（type 9）；行列、波段数要与头文件一致 |
| 复数 GeoTIFF 目录 | 每景一个文件，文件名含日期 | 所有影像必须同尺寸、同网格；不同尺寸会被裁到最小公共范围；首景的 GeoTIFF 地理标签会被读取 |
| Sentinel-1 SAFE | 实验性支持单 swath、已配准的复数 int16 TIFF | 生产级 TOPS 数据请先在 SNAP/ISCE 完成 burst 拼接、去斜和配准 |
| GACOS 本地目录 | `.ztd + .rsc`、`.tif`、`.npy` | 文件名必须包含 `YYYYMMDD` 或 `YYYY-MM-DD` |

#### 4.3.4 数据质量检查

导入后至少确认：

1. 预检警告逐条都能解释，尤其是日期推断和地理参考缺失；确认验证级别是 `full`、`sampled` 还是 `header`。
2. 振幅图有纹理，不是全黑、全白或纯噪声。
3. 日期顺序正确，没有重复或意外缺失。
4. 掩膜保留主要陆地，水体和阴影被剔除。
5. 相邻日期干涉相位连续，没有整体跳变。
6. DEM 与 SLC 同网格、同单位。
7. `bperp_m` 的数量与日期数一致，量级合理。
8. 项目体检中的“地理参考”和“预配准栈”状态符合预期。

### 4.4 网络构建

网络页负责把日期连成可解的观测图。系统会：

1. 检查 `data/processed/slc_coreg.npy`，不存在或配准参数指纹已变化时先自动配准；导入时标记为 `already_coregistered` 的栈直接复用现有配准，不再二次重采样。
2. 按路线生成干涉对。
3. 检查日期图是否连通，不连通时补一条时间桥。
4. 超过 `max_pairs` 时按短基线优先裁剪，同时保证每个日期至少出现一次；如果裁剪后连通性变差，则保留原网络，因此 `max_pairs` 是软上限。

网络页重点看四个指标：

| 指标 | 含义 | 经验判断 |
| --- | --- | --- |
| 干涉对数 | 实际保留的观测数 | 演示 SBAS 约 80 对；真实数据按需要调整 |
| 冗余度 | `n_pairs / (n_dates - 1)` | 3 以上较稳健；低于 2 要谨慎 |
| 最大时间基线 | 实际保留对的最大时间差 | 越小相干性越好，但连接越少 |
| 连通分量 | 日期图是否连通 | 必须是 1；大于 1 说明有日期无法求解 |

路线差异：

- **SBAS**：枚举所有满足时间/垂直基线阈值的日期对，补连通边，按短基线优先裁剪。
- **PS**：以参考影像为中心的星形，默认全星形，再补相邻日期对用于闭环。PS 星形边不受 `max_perpendicular_baseline` 限制；`max_pairs` 仍会限制总数。
- **DS**：与 SBAS 相同的小基线网络，相位链接在干涉/反演阶段完成。
- **D-InSAR**：只生成一对。界面选择主影像和从影像；API 中请使用长度为 2 的列表，例如 `[0, 23]`，不要依赖字符串形式。

### 4.5 干涉处理

干涉页把每一对相位变成可解的观测，并提供逐对浏览：

- 振幅；
- 缠绕相位；
- 滤波相位；
- 解缠相位；
- 相干性；
- 残差。

处理流程：

1. 复共轭相乘生成干涉相位。
2. 按 `multilook` 做复数多视。
3. 用 DEM 和垂直基线去地形相位。
4. 按 `coherence_window` 估计相干性。
5. 按 `filter` 做相位滤波。
6. 按 `min_coherence` 生成有效掩膜。
7. 按 `unwrap_method` 解缠，按 `unwrap_coherence_min` 控制解缠种子/有效像元。
8. 减去参考像元相位，按 `remove_ramp` 和 `ramp_order` 去除平面或二次趋势面。
9. 把解缠相位转换为 LOS 位移，单位毫米。

常用判断：

- 缠绕相位出现大面积条纹跳变：优先提高 `unwrap_coherence_min`、换 Goldstein，并检查配准和 burst 拼接；减小多视会增加噪声，通常不是首选。不要用强滤波掩盖解缠错误。
- 相干性整体偏低：检查配准、burst 拼接、时间去相干和植被覆盖。
- 相位全是噪声：先检查数据本身，再调参；调参无法修复未配准的 TOPS 数据。
- PS 路线应保持 `multilook = 1`，强滤波会削弱永久散射体。

### 4.6 大气校正

三种方法：

| 方法 | 数据要求 | 适用场景 | 注意事项 |
| --- | --- | --- | --- |
| GACOS | 官方邮件产品、演示、本地或自定义在线逐日天顶延迟 | 有外部大气产品，想校正分层/湍流延迟 | 真实项目推荐官方；自定义在线接口不统一，需自行确认地址和凭据 |
| 经验高程 | 不需要外部数据 | 地形起伏明显、无 GACOS | 过度校正会吃掉真实长波形变 |
| 不校正 | 无 | 先看原始结果，或反演阶段做时间高通 | 残余 APS 会进入时序，可能形成假趋势 |

官方 GACOS 的最短操作路径：

1. 大气页选择 **GACOS → 官方 GACOS**。面板会显示申请范围、成像时刻、日期/批次、覆盖率、缺失日期和最近申请/导入记录。
2. 点 **申请 GACOS 产品**，填写接收邮箱、输出格式（推荐 GeoTIFF）、W/S/E/N 和 UTC 时刻。日期列表来自项目，单次最多 20 个；超过 20 个日期时必须勾选拆批，最多 3 批（60 景）；申请范围最大 10°×10°。
3. 提交后等待官方邮件。官方服务器约保留产品 72 小时，收到邮件后尽快导入。
4. 点 **导入邮件链接**，把邮件里的 tar.gz 下载链接逐行粘贴；也可以填本机已下载的文件或目录。或者点 **上传 tar.gz / 产品文件**，直接选择邮件附件或解压后的 `.tif`、`.ztd + .rsc`、`.npy`。
5. 导入完成后确认覆盖率为 100%、缺失日期为空，再运行大气阶段。若产品是在大气结果生成之后才导入，系统会把大气阶段标记为过期，需要重跑。

详细格式、限制和排错见 5.8 节。

GACOS 本地目录：

```text
gacos/
  20230103.ztd
  20230103.rsc
  20230115.ztd
  20230115.rsc
  ...
```

文件名必须包含日期。系统会递归查找 `.ztd`、`.tif/.tiff`、`.npy`，同一日期有多个匹配时取文件名最短的。

诊断图怎么看：

- 左侧逐日 APS 屏：空间纹理是否合理，量级是否异常。
- 中间相位分布：校正后应更集中。
- 右侧逐对散点：点应更靠近 1:1 线。

校正过度时，速率图可能出现大面积负相关纹理，或把真实长波形变当成大气扣掉。此时回退到“不校正”，或只用经验高程。

> **凭据处理**：从 1.2.0 起，`atomic_write_json()` 会在所有 JSON 写盘前递归脱敏，`gacos_token`、`gacos_email`、`username`、`password` 等字段的值会变成 `***`，`project.json` 则直接删除这些键；报告和 ZIP 读取的是已脱敏的摘要。请求体、浏览器开发者工具和代理日志仍可能看到明文，真实凭据请使用一次性会话输入。

### 4.7 时序反演

四条路线的反演：

- **SBAS/DS**：对所有有效像元做加权最小二乘，加入二阶时间正则和稳健重加权，解算逐日位移和速率。
- **PS**：先按 ADI 和相干性选点，再只对 PS 点求解，并用 PS 权重加权。
- **D-InSAR**：取单对解缠相位直接转位移，不生成速率。

反演页可以调整：

- 多视因子；
- 正则化权重；
- 是否去趋势面（`remove_ramp` 实际在干涉阶段作用于解缠相位；在反演页修改后，需要重跑干涉阶段才生效）；
- 是否估计 DEM 误差；
- 稳健迭代次数；
- APS 方法、空间尺度和迭代次数；
- 参考像元模式（自动/手动）；
- PS 的 ADI 和相干性阈值；
- DS 的相干窗口 `ds_patch`（相位链接固定为 EMI，窗口重叠固定 100%，不再提供重叠率和链接方法选项）。

结果摘要会显示有效像元、时序相干性、残差、参考像元和干涉对信息。反演完成后自动进入成果页。

BASE = "http://127.0.0.1:8765"

with requests.Session() as s:
    # 1. 创建演示项目

        timeout=60,
    )
    r.raise_for_status()
    project = r.json()["project"]
    project_id = project["id"]
    print("project:", project_id)

    # 2. 提交全流程
    r = s.post(
        f"{BASE}/api/projects/{project_id}/run",
        json={"technique": "sbas", "params": {"multilook": 2, "max_pairs": 80}},
        timeout=30,
    )

    job = r.json()["job"]
    job_id = job["id"]
    print("job:", job_id)

    # 3. 轮询作业
    while True:

        r.raise_for_status()
        state = r.json()
        print(state.get("status"), state.get("progress"), state.get("message", ""))

## 5. 支持的影像类型与处理原理

这一章回答两个问题：工作台能读什么，读进来以后每一步在做什么。先给结论，再逐类说明。

> **一句话结论**：主输入只有一种，已经配准的复数 SLC 栈。DEM、掩膜和 GACOS 是辅助数据；实数振幅/强度图只能做流程演示；干涉图、解缠相位和现成形变产品不支持直接导入；Sentinel-1 SAFE 是实验性入口，不等于完整的 TOPS 处理器。

### 5.1 支持矩阵

| 数据类型 | 是否支持 | 在流程中的角色 | 能产出什么 | 关键限制 |
| --- | --- | --- | --- | --- |
| 多时相复数 SLC 栈 | 支持，主输入 | 配准、干涉和反演的唯一相位来源 | 干涉图、相干性、解缠相位、LOS 位移、速率 | 必须已配准；至少 2 景；同网格 |
| 单景复数 SLC | 不作为独立输入 | 只能作为栈中的一景 | 无 | 少于 2 景会被拒绝 |
| 实数振幅/强度图 | 有限支持 | 自动转成零相位复数 | 振幅预览、流程演示 | 没有相位，不能测形变 |
| 干涉图、解缠相位、形变产品 | 不支持 | 外部中间产品或对比材料 | 无 | 无法恢复每景相位和一致网络 |
| DEM | 支持，辅助数据 | 去地形、经验大气、DEM 误差 | 地形相位改正 | 米制；需要与 SLC 同网格或可重采样 |
| 掩膜 | 支持，辅助数据 | 限定有效像元 | 剔除水体、阴影、低相干区 | 布尔或 0/1；自动掩膜可能误删 |
| GACOS 大气产品 | 支持，辅助数据 | 逐日天顶延迟转 LOS 延迟 | 大气相位校正 | 必须覆盖项目中的每个日期；本地优先 |
| Sentinel-1 SAFE | 实验性 | 单 swath SLC 入口 | 初步查看或演示 | 不拼接 burst、不做 TOPS 配准；可读 annotation 时间和几何，并可由本地 EOF 估计基线 |
| GRD、RAW、光学影像、点云、GNSS | 不支持 | 无 | 无 | 数据类型不匹配 |

### 5.2 从 SLC 到形变：处理原理

#### 5.2.1 复数记录与干涉相位

SAR 是相干成像系统，每个像元同时记录振幅和相位：

```text
s(t) = A(t) · exp(j · φ(t))
```

其中 `A` 是回波强度，`φ` 是回波相位。两景影像共轭相乘得到干涉图：

```text
IFG = s_sec · conj(s_ref)
φ_ifg = φ_sec - φ_ref
```

干涉相位对视线向（LOS）路径差非常敏感。对于波长 `λ`，相位与路径差的关系是：

```text
φ = 4π · Δr_LOS / λ
Δr_LOS = φ_unwrapped · λ / (4π)
```

一个完整的 `2π` 条纹对应的 LOS 路径差是 `λ / 2`。这就是为什么 C 波段能测到毫米级变化，也是为什么相位缠绕必须解缠：

| 波段 | 典型波长 | 一个 `2π` 条纹对应的 LOS 变化 | 特点 |
| --- | ---: | ---: | --- |
| X 波段 | 约 3.1 cm | 约 15.5 mm | 对微小形变敏感，但植被去相干快，解缠更容易失败 |
| C 波段 | 约 5.6 cm | 约 27.7 mm | 灵敏度、相干性和覆盖的折中，Sentinel-1 常用 |
| L 波段 | 约 23.6 cm | 约 118 mm | 穿透植被能力强，但对小形变不敏感，条纹更稀疏 |

工作台的默认值是 Sentinel-1 C 波段：波长 `0.05546576 m`、入射角 `38.5°`、距离向间距 `2.329562 m`、方位向间距 `13.968 m`。换传感器时必须通过 `meta` 改成实际值，否则位移量级和地形相位都会错。

#### 5.2.2 干涉相位由什么组成

一景干涉相位不只包含形变，通常写成：

```text
φ_ifg = φ_def + φ_topo + φ_atm + φ_orbit + φ_noise
```

| 分量 | 来源 | 工作台怎么处理 |
| --- | --- | --- |
| `φ_def` | 地表在两次成像之间的 LOS 位移 | 保留，最终转成毫米 |
| `φ_topo` | 地形起伏与垂直基线共同造成的相位 | 用 DEM 和 `bperp_m` 减去 |
| `φ_atm` | 对流层延迟、电离层等 | GACOS、经验高程或反演阶段 APS |
| `φ_orbit` | 轨道误差、基线误差 | 部分被平面趋势去除，剩余进入残差 |
| `φ_noise` | 热噪声、时间去相干、配准误差 | 靠相干性掩膜、滤波和解缠质量控制 |

工作台用下面的近似计算地形相位：

```text
φ_topo = 4π · bperp_diff · h / (λ · R · sinθ)
```

其中 `bperp_diff` 是两景垂直基线之差，`h` 是 DEM 高程，`R` 是斜距，`θ` 是入射角。这个式子说明三件事：

- 没有 `bperp_m`，地形相位无法正确扣除；
- DEM 的高程基准或投影错了，地形相位就会残留；
- 垂直基线越大，对 DEM 误差越敏感，但 DEM 误差的可估性也越好。

当前实现没有单独的平地相位项。平坦且 DEM 为零时，地形相位为零，剩余的长波趋势主要交给 `remove_ramp` 的趋势面拟合处理。因此 `remove_ramp` 不是“可选美化”，它会改变宽尺度结果；`ramp_order=1` 只去平面，`ramp_order=2` 会连同二次项一起去掉。

#### 5.2.3 工作台的处理链

```text
SLC 栈
  → 配准
  → 干涉网络
  → 复共轭相乘
  → 多视
  → 去地形相位
  → 相干性估计
  → 相位滤波
  → 解缠
  → 参考像元与平面趋势
  → LOS 位移
  → 大气校正
  → 时序反演
  → 速率、残差、报告和 GeoTIFF
```

各步骤的实际行为：

1. **配准**：以 `ref_index` 指定或默认第 0 景为参考，用相位相关估计整像元偏移，再做亚像元精化。`model=affine` 时拟合仿射变换，`translation` 只估计平移；拟合失败会回退。
2. **网络**：SBAS/DS 枚举满足时间基线和垂直基线阈值的日期对，PS 以参考景为中心构造星形并补相邻对，D-InSAR 只取一对。
3. **干涉**：`IFG = sec · conj(ref)`，再按 `multilook` 做复数多视。多视会改变后续所有产品的网格。
4. **去地形**：按上面的公式减去地形相位。没有 DEM 或 `bperp_m` 全为零时，这一步实际不产生地形改正。
5. **相干性**：在 `coherence_window` 窗口内估计，值域 0–1。它既用于质量评估，也用于掩膜和解缠。
6. **滤波**：支持 boxcar、Goldstein、高斯和 NL-Means。滤波只作用于缠绕相位和解缠输入，不改变原始复数干涉图。
7. **解缠**：默认质量引导解缠，也可选 SNAPHU 或最小二乘。解缠把 `(-π, π]` 的相位恢复成连续相位，错误通常表现为整片 `2π` 跳变。
8. **参考与趋势**：减去参考像元相位，使整景有一个共同零点；`remove_ramp=true` 时按 `ramp_order` 拟合并减去平面或二次趋势面。
9. **位移**：`disp_mm = φ_unwrapped · λ / (4π) · 1000`。本工具约定 LOS 正值朝向卫星。
10. **大气**：GACOS 用逐日延迟做差分，经验高程用相位—高程回归，`off` 保留原始相位；反演阶段还可以做时空高通 APS。
11. **反演**：SBAS/DS 用加权最小二乘加二阶时间正则和稳健重加权；PS 先按 ADI 和相干性选点；D-InSAR 直接把单对解缠相位转成位移。
12. **输出**：速率/位移、相干性、残差、DEM 误差、APS、网络图、配准增益、CSV、Markdown/DOCX 报告和 GeoTIFF。

#### 5.2.4 四条路线的反演差异

| 路线 | 观测组织 | 反演核心 | 对数据的要求 |
| --- | --- | --- | --- |
| SBAS | 小基线集，多对冗余 | 逐像元时序最小二乘 + 时间正则 | 日期之间要连通，景数越多越稳 |
| PS | 单主影像星形 + 相邻对闭环 | 先选强散射点，再对点求解 | 单视、稳定散射体、较高相干性 |
| DS | 小基线集 | 局部相干矩阵特征分解做相位链接，再联合解算 | 分布式散射体，景数和冗余度更高 |
| D-InSAR | 单对 | 解缠相位直接转 LOS 位移 | 两景几何一致、相干性足够 |

### 5.3 复数 SLC 栈

#### 5.3.1 硬性要求

导入时会对 SLC 做以下检查：

| 检查 | 规则 | 不满足时 |
| --- | --- | --- |
| 维度 | 必须是 `(日期, 行, 列)` 三维 | 报错 |
| 景数 | 至少 2 景 | 报错 |
| 尺寸 | 至少 `4 × 4` | 报错 |
| 数据类型 | 推荐 `complex64` | 实数会转成零相位并警告 |
| 有限值比例 | 不低于 50% | 报错 |
| 非有限值 | 低于 99.9% 会警告 | 在相干性/掩膜阶段剔除 |
| 全零 | 不允许 | 报错 |
| 日期 | `YYYY-MM-DD`，不能重复 | 重复报错；缺失按 12 天补齐；乱序自动重排 |
| 垂直基线 | 长度应与景数一致 | 不一致时全部置零并警告 |
| 掩膜 | 至少有一个有效像元 | 报错 |

除了程序检查，真实数据还应满足：

- 同一轨道、同一成像模式、同一子条带或同一 frame；
- 已经做过 burst 拼接、去斜和 TOPS 配准；
- 所有影像在同一网格上，尺寸一致；
- 配准残差在亚像元量级，边缘没有明显相位斜坡；
- 日期、垂直基线、波长、入射角和像元间距来自同一套轨道/几何参数。

#### 5.3.2 `meta` 字段

原生目录、`.npz` 和导入接口都可以提供元数据。常用字段：

| 字段 | 作用 | 缺失时的行为 |
| --- | --- | --- |
| `dates` | 时间轴 | 按 12 天间隔从首景补齐；全缺时从 `2023-01-01` 起算 |
| `bperp_m` | 垂直基线，米 | 全部置零，地形相位和 DEM 误差估计失效 |
| `wavelength_m` | 雷达波长，米 | 使用 Sentinel-1 C 波段默认值 |
| `incidence_deg` | 入射角，度 | 使用 `38.5` |
| `range_spacing_m` | 距离向像元间距，米 | 使用 `2.329562` |
| `azimuth_spacing_m` | 方位向像元间距，米 | 使用 `13.968` |
| `slant_range_m` | 斜距，米 | 使用 `705000` |
| `ref_index` | 参考影像索引 | 使用 0；日期重排时会同步重映射 |
| `platform` | 平台名 | 使用 `Sentinel-1` |
| `orbit_direction` | 升降轨 | 使用 `UNKNOWN` |
| `relative_orbit` | 相对轨道号 | 留空 |
| `corner_lon`、`corner_lat` | 输出 GeoTIFF 左上角经纬度 | 使用 `0` |
| `lon_step`、`lat_step` | 输出像元经纬度步长 | 使用 `0.0004` 和 `-0.0004` |
| `crs` | 输出坐标系标签 | 使用 `EPSG:4326` |
| `slc_path`、`dem_path` | 原生目录内的相对路径 | 回退到 `slc.npy`、`dem.npy`/`dem.tif` |

`bperp_m` 的符号必须与所用处理链一致。工作台用 `bperp_diff = bperp[sec] - bperp[ref]` 计算地形相位；符号反了，地形相位会朝相反方向叠加。

#### 5.3.3 适用场景

- 已在 SNAP、ISCE、Gamma 等软件中完成配准的 Sentinel-1、TerraSAR-X、ALOS-1/2、RADARSAT-2、高分三号、陆探一号、ERS 等重复轨道 SLC 栈；
- 区域沉降、滑坡、城市形变、矿区形变、同震形变的算法验证；
- 教学、课程设计、算法回归和参数敏感性试验；
- 单机、小批量、数据不能离开本机的场景。

#### 5.3.4 限制

- **不做 SAR 预处理**：不做 burst 拼接、不做去斜、不做 TOPS 配准。可在导入后用本地 `.EOF` 精密轨道估计垂直基线，但不把轨道用于 TOPS 配准或轨道误差改正。未配准的 burst 直接导入，结果通常是噪声。
- **地图坐标是可选后处理**：轨道和几何元数据齐全时，反演后会自动做距离-多普勒地理编码，输出 `products/geotiff/geo/`；元数据不足时输出仍停留在处理网格。地理编码不做投影变换、严格正射校正、跨 180° 经线处理或 TOPS burst。
- **只处理一种几何**：不做升降轨联合分解，不做方位向/距离向分解。
- **内存和磁盘**：SLC 以 `complex64` 保存，`n_dates × rows × cols × 8` 字节是基本占用；原始 `slc.npy` 和配准输出 `slc_coreg.npy` 都使用内存映射，不要求完整栈常驻 RAM。干涉按行块做复共轭、多视和去 ramp，参考像元按行块流式统计；DS 的局部协方差按行块计算，单块缓存不超过 256 MiB（约 268 MB），不再保留全量 `(n_dates, n_dates, rows, cols)` 相干矩阵；PS 振幅离差也按行块流式累计。但 DS 仍保留多视后的 `slc`、`diag`、`linked`，特征分解时间随景数立方增长。处理真实大栈前先看 2.1 节的内存预算说明，必要时设置 `INSAR_MEMORY_BUDGET_BYTES`。
- **元数据质量决定结果量级**：波长、入射角、像元间距和垂直基线缺失时，程序会用 Sentinel-1 默认值继续跑，但结果可能只是“能出图”，不是可解释的形变。

### 5.4 实数振幅/强度图

**是什么**：只保留回波强度、已经丢失相位的 SAR 产品，常见于 GRD、振幅 GeoTIFF、强度 PNG/JPEG 转换结果。

**工作台怎么处理**：如果输入是三维实数数组，导入器会把它转成 `complex64`，虚部为零，并写入警告“输入不是复数 SLC，已按零相位实数数据转换，结果只能作为演示”。如果只有单景，仍会因少于 2 景被拒绝。

**原理上会发生什么**：

- 两景零相位数据共轭相乘，干涉相位恒为 0；
- 相干性可能被人为抬高，但不代表真实相位质量；
- 解缠相位为 0，LOS 位移为 0；
- 地形相位、DEM 误差、大气校正和时序反演都没有可解释的物理意义。

**适用场景**：

- 第一次熟悉界面和七步流程；
- 检查导入、网络、出图和导出链路是否正常；
- 用振幅图检查成像范围、水体、城市纹理和配准大致位置；
- 教学演示“为什么相位不可替代”。

**限制**：

- 不能用于任何形变监测、沉降评估或科研结论；
- 不能用来比较 PS/DS 点密度；
- 不能用来验证解缠、大气或反演算法；
- 如果成果页出现“位移全为 0”，先确认输入是不是振幅图。

### 5.5 干涉图、解缠相位与形变产品

**结论：不支持直接导入。**

原因不是文件读不了，而是信息不完整：

- 干涉图只保留了两景之间的相位差，丢失了每景的绝对相位和日期间的共同参考；
- 解缠相位带有任意 `2π` 整数和参考像元选择，换一个参考点整景就变；
- 形变产品通常已经做过去平地、去地形、滤波、大气校正或投影，无法再和工作台的配准、网络、DEM 和反演参数对齐；
- 时序反演要求所有干涉对共享同一套日期、同一参考和一致的相位符号，零散导入的干涉图很难满足。

如果目录里放的是三维复数干涉图栈，导入器可能把它当成 SLC 栈读进去，但语义是错的：它会继续做“配准”和“干涉”，结果没有物理意义。不要这样用。

**如果手里只有干涉图/解缠相位，怎么办**：

1. 找回原始 SLC，按第 5.3 节准备，重新走工作台流程；
2. 如果只有干涉产品，使用 StaMPS、MintPy、GMTSAR 等面向干涉图栈的工具；
3. 把外部干涉图作为视觉对比或精度参考，不导入本工具；
4. 需要交付时，把外部产品和本工具成果分开存放，避免混用参考点和符号。

### 5.6 DEM

**作用**：

- 计算并扣除地形相位；
- 为经验高程大气校正提供高程自变量；
- 在 `estimate_dem_error=true` 时参与 DEM 误差联合估计；
- 为部分诊断图提供地形背景。

**支持格式**：

| 入口 | 格式 |
| --- | --- |
| 导入项目时单独指定 `dem_path` | `.tif/.tiff`、`.npy`、ENVI `.hdr/.dat/.img` |
| 原生目录自动查找 | `dem.npy`、`dem.tif`、`dem.tiff`，或 `meta` 里的 `dem_path` |
| `.npz` | `dem` 数组 |

**要求**：

- 单位是米，浮点数组；
- 形状应与 SLC 的 `(rows, cols)` 一致；不一致会重采样并警告；
- 非有限值会被替换为 0 并警告；
- 常数 DEM 会警告“地形相位将为零”；
- 没有 DEM 时使用全零数组，地形相位和 DEM 误差估计不可用。

**限制**：

- 工作台不按地理坐标重投影 DEM，只按数组形状重采样。DEM 必须已经与 SLC 同区域、同网格或近似同网格；拿一张范围不对的 DEM 进来，重采样只会把错误范围拉伸到整景。
- 垂直基准（大地高/正高）、geoid 和 DEM 空洞会影响地形相位。大范围、高落差区域应使用同一基准的 DEM，并检查空洞填补。
- 植被覆盖区的 DSM 会把树冠高度当成地形，导致地形相位残差。
- DEM 分辨率不是越高越好。远高于 SLC 分辨率时不会自动提升形变精度，反而可能引入配准和噪声问题。
- 导入 DEM 不会自动给输出 GeoTIFF 建立正确地理参考；输出范围仍由 `meta` 的角点和步长决定。缺少角点时会明确警告，成果按像元坐标输出。

### 5.7 掩膜

**作用**：限定参与相干性统计、解缠和反演的像元，剔除水体、阴影、叠掩、低相干区和无效边界。

**支持格式**：

- 原生目录：`mask.npy`、`mask.tif`、`mask.tiff`；
- `.npz`：`mask` 数组；
- 单独的 `dem_path` 没有 mask 参数，掩膜需要在原生目录或 `.npz` 中提供。

**自动掩膜**：没有提供掩膜时，导入器用首景振幅生成：

```text
lo, hi = 振幅的 3% 和 99% 分位数
mask = 振幅 > max(lo, hi × 0.08)
mask 的最外 2 像元全部置 False
```

这个规则适合快速起步，不适合精细业务。首景如果有云、阴影、条带或定标异常，自动掩膜会继承这些问题。

**限制**：

- 掩膜会被重采样到 SLC 尺寸，阈值是 `> 0.5`；
- 掩膜内没有有效像元会直接报错；
- 自动掩膜不识别叠掩和阴影，只按振幅阈值处理；
- 掩膜过严会减少有效像元，过松会把噪声带进反演；
- 当前界面不提供交互式掩膜编辑，精细掩膜应在导入前用外部工具生成。

### 5.8 GACOS 大气产品

**作用**：GACOS 提供逐日天顶总延迟（ZTD）。工作台把 ZTD 转成 LOS 延迟，再对每个干涉对做差分，减去 `screen[sec] - screen[ref]` 对应的相位。

**四种来源**：

| `gacos_source` | 适用场景 | 说明 |
| --- | --- | --- |
| `demo` | 演示项目 | 默认；用合成真值生成模拟延迟，不能用于真实项目 |
| `official` | 真实项目默认 | 官网表单申请，邮件交付 tar.gz，导入项目缓存 |
| `local` | 已有本地产品 | 目录递归查找，文件名必须包含日期 |
| `online` | 自建或第三方服务 | 非 GACOS 官方接口，需要自行配置 URL、邮箱和令牌 |

**官方申请与导入（推荐）**：

1. 在大气页选择 **GACOS → 官方 GACOS**。面板显示申请范围、成像时刻、日期/批次、覆盖率、缺失日期、最近申请与最近导入。
2. 点 **申请 GACOS 产品**，填写接收邮箱、输出格式（推荐 GeoTIFF）、W/S/E/N 和 UTC 时/分。日期列表来自项目，不能手改。
3. 官方限制：单次最多 20 个日期，范围最大 10°×10°，不支持跨 180° 经线。超过 20 个日期时，界面会显示“允许拆分为 N 批申请”；勾选后最多 3 批（60 景）。超过 60 景需要减少日期或分多次处理。
4. 提交成功只代表申请已受理，产品通过邮件异步发送，可能需要数分钟到数小时。官方服务器约保留产品 72 小时，收到邮件后尽快导入。
5. 收到邮件后有两种导入方式：
   - **导入邮件链接**：把邮件里的 tar.gz 下载链接逐行粘贴；也可以填本机已下载的文件或目录路径。系统会逐跳校验重定向，只允许公网 http/https 地址。
   - **上传 tar.gz / 产品文件**：直接选择邮件附件或解压后的 `.tif/.tiff`、`.ztd + .rsc`、`.npy`，可多选。单次上传上限 512 MiB。
6. 导入完成后确认覆盖率为 100%、缺失日期为空，再运行大气阶段。若新产品是在大气结果生成之后导入，阶段会被标记为过期，需要重跑。重复导入字节相同的文件不会触发过期。

**支持格式**：

| 格式 | 读取方式 | 单位处理 |
| --- | --- | --- |
| `.ztd` + `.rsc` | `.rsc` 提供行列、角点和步长；二进制 float32 先按小端读取，数值不合理时回退大端 | 中位数大于 50 时按毫米输入处理，否则按米输入处理 |
| `.tif/.tiff` | GeoTIFF 单波段，可带地理标签 | 中位数小于 10 时按米，否则按毫米 |
| `.npy` | 二维数组 | 直接按毫米使用 |

`.ztd` 的 `.rsc` 至少要有 `file_length`（或 `lines`）和 `width`（或 `samples`）；有 `x_first`、`y_first`、`x_step`、`y_step` 时会用于重采样。

**日期匹配**：

- 文件名必须包含 `YYYYMMDD` 或 `YYYY-MM-DD`；
- 目录会递归查找；
- 同一日期有多个匹配时，取文件名最短的；
- **项目中的每个日期都必须有对应屏幕，缺一个就会在大气阶段报错**，不会静默跳过。

**重采样**：

- 形状已经一致时直接使用；
- 有地理范围时按经纬度双线性插值；
- 没有地理范围时按数组尺寸缩放，再裁剪或边缘填充；
- 产品范围与项目范围完全不重叠时直接报错。

**安全边界**：

- tar/zip 拒绝路径穿越、绝对路径、符号链接、设备/非普通条目和加密 zip；
- 限制压缩包条目数（4000）、展开体积（2 GiB）、上传体积（512 MiB）和下载体积（1 GiB）；
- 下载只允许公网 http/https，拒绝私网、回环、链路本地、组播和保留地址；
- 解压和下载临时文件位于 `data/gacos/.tmp/`，导入结束后清理；
- 申请邮箱只在本次请求内存和响应中使用，`last_request.json` 只保存脱敏后的 `email_masked`。

**限制**：

- GACOS 是外部气象模型产品，不是真值；残余分层延迟和短波湍流仍可能存在；
- 日期不匹配、成像时刻与模型时刻不一致会削弱校正效果；
- 官方服务只支持网页申请和邮件交付，没有同步下载 API；官方服务改版可能导致表单提交失败；
- 自定义在线 GACOS 接口因部署而异，软件不保证第三方端点可用；
- `gacos_token`、`gacos_email` 等凭据字段会在所有 JSON 落盘前脱敏为 `***`，但请求体、浏览器开发者工具和代理日志仍可能看到明文；真实凭据请用一次性会话输入；
- 业务使用优先走官方 `official` 或本地 `local`。

### 5.9 传感器、波段与元数据

工作台不绑定 Sentinel-1，但默认参数是按 Sentinel-1 写的。其他传感器可以导入复数 SLC，前提是元数据齐全。

| 波段 | 典型传感器 | 波长量级 | 优势 | 主要难点 |
| --- | --- | ---: | --- | --- |
| L | ALOS-1/2 PALSAR、部分陆探系列 | 约 23.6 cm | 植被穿透好，低相干区更容易保持相干 | 对小形变不敏感，条纹稀疏，天线大、数据量大 |
| C | Sentinel-1、RADARSAT-2、高分三号、ERS | 约 5.6 cm | 灵敏度与覆盖平衡，数据源多 | 植被区时间去相干快，C 波段大气影响明显 |
| X | TerraSAR-X、COSMO-SkyMed | 约 3.1 cm | 分辨率高，对微小形变敏感 | 相干性下降快，解缠更难，覆盖范围小 |

换传感器时至少要设置：

```json
{
  "platform": "TerraSAR-X",
  "wavelength_m": 0.031,
  "incidence_deg": 35.0,
  "range_spacing_m": 1.2,
  "azimuth_spacing_m": 2.0,
  "slant_range_m": 600000,
  "bperp_m": [0.0, 12.3, 25.1]
}
```

注意：

- 波长错了，位移会按比例错；L 波段数据套用 C 波段默认波长，位移会被低估约 4 倍。
- 入射角错了，地形相位和部分几何换算会错；Sentinel-1 不同子条带和不同景的入射角并不都等于 `38.5°`。
- 像元间距错了，影响多视后的空间尺度、报告和外部工具对接。
- 垂直基线错了，地形相位会残留，DEM 误差估计也不可信。
- 工作台没有对非 Sentinel-1 传感器做系统验证；首次使用应先用小区域、已知形变或公开样例做符号和量级检查。

### 5.10 格式矩阵与导入判定

| 输入形式 | 识别条件 | 日期来源 | DEM/掩膜 | 备注 |
| --- | --- | --- | --- | --- |
| 原生目录 | 存在 `stack.json`、`meta.json` 或 `slc.npy` | `meta["dates"]` | 自动查找 `dem.npy`、`dem.tif`、`mask.npy`、`mask.tif` | 最推荐；`meta` 可指定 `slc_path`、`dem_path` |
| 单个 `.npy` | 三维复数数组 | 文件名中的日期，取不到则补齐 | 无 | 三维数组可含多景；只有一景时被拒绝 |
| 单个 `.npz` | 含 `slc` 或 `stack` 键 | `dates` 数组或 `meta["dates"]` | `dem`、`mask` 可选 | 还可带 `bperp_m` 和 `meta` JSON 字符串 |
| ENVI | `.hdr` 及同名 `.dat/.img` | 文件名中的日期 | 无 | `bands` 作为日期数，数据类型需为复数 |
| GeoTIFF 目录 | 目录中有 `.tif/.tiff` | 文件名中的日期 | 无 | 每景单波段复数，或 `(rows, cols, 2)` 的 I/Q |
| SAFE | 目录含 `measurement`，或含 `.SAFE` 子目录 | measurement TIFF 文件名 | 无 | 实验性，单 swath；读取 annotation 时间和几何，可由本地 EOF 估计基线，不拼接 burst |
| 单景 GeoTIFF/ENVI | 单个文件 | 文件名 | 无 | 只能算一景，因少于 2 景被拒绝 |

导入器按以下顺序判断目录：

1. 有 `measurement` 或 `.SAFE` 子目录，按 SAFE 读取；
2. 有 `stack.json`、`meta.json` 或 `slc.npy`，按原生目录读取；
3. 有 `.tif/.tiff`，按 GeoTIFF 场景目录读取；
4. 都不满足，报“无法识别数据目录”。

GeoTIFF 目录还有两个容易忽略的行为：

- 所有场景尺寸不一致时，会裁到最小公共范围并警告，不建议依赖这个行为；
- 双波段 I/Q 只识别最后一维为 2 的排列，即 `(rows, cols, 2)`。如果你的导出是 `(2, rows, cols)`，先转置或导出为单波段复数。

ENVI 栈：

- `data type` 必须是复数类型，常用 `6`（complex64）或 `9`（complex128）；
- `bands` 被当作日期数；
- 支持 `bsq`、`bil`、`bip`；
- 日期从文件名提取，提取不到就按 12 天补齐。

SAFE：

- 读取 `measurement/*.tiff`，两波段 I/Q 会合成复数；
- 日期从文件名提取；
- 读取 `annotation` 中的首行时间、入射角、距离/方位像元间距和轨道号；
- 如果目录或其父目录有 Sentinel-1 `.EOF`，且每景都有成像时间，会估计 `bperp_m`；
- 不解析 burst、子条带或去斜参数，也不做 TOPS 配准；
- 只适合初步查看，生产级处理请先在 SNAP/ISCE 完成 TOPS 流程。

### 5.11 路线选择与数据条件

| 路线 | 程序下限 | 建议景数 | 数据条件 | 常见失败信号 |
| --- | ---: | ---: | --- | --- |
| D-InSAR | 2 | 2 | 两景几何一致、相干性足够、形变梯度不过大 | 解缠整片跳变、条纹过密 |
| SBAS | 8 | 8–12 | 小基线网络连通，日期覆盖均匀 | 连通分量大于 1、冗余度低 |
| PS | 8 | 8–12 | 单视、强散射点、较高相干性、轨道稳定 | PS 点极少或全是噪声 |
| DS | 10 | 10 以上 | 分布式散射体、短时间基线、足够冗余 | 相干性低、块内样本不足 |

程序下限由 `config.py` 的 `TECHNIQUES` 统一声明，并在导入、路线切换、API 运行入口和 `run_pipeline()` 入口强制校验；不足时会直接报错，不会带着无意义数据进入反演。`ds_patch` 另有内部约束，相位链接要求至少 6 个历元，但 DS 路线的整体下限是 10 景。

### 5.12 误差来源与导入前检查

| 误差来源 | 典型表现 | 先检查什么 |
| --- | --- | --- |
| 配准误差 | 边缘相位斜坡、相干性整体下降 | 配准残差、burst 拼接、`ref_index` |
| 轨道/基线误差 | 与地形相关的长波相位、速率图倾斜 | `bperp_m` 符号和数值、轨道来源 |
| DEM 误差 | 相位与高程相关，重复出现 | DEM 基准、范围、空洞、分辨率 |
| 解缠错误 | 整片 `2π` 跳变、位移台阶 | 相干性、滤波、`unwrap_coherence_min` |
| 大气延迟 | 空间相关、随时间变化的屏 | GACOS 覆盖、经验高程阶数、APS 参数 |
| 时间去相干 | 植被区相干性低、PS 点少 | 时间基线、季节、波段 |
| 形变梯度过大 | 条纹过密、解缠失败 | 多视、SNAPHU、外部先验 |
| 参考像元不稳定 | 整条时间序列整体漂移 | 参考点位置、`reference_mode` |
| 波长/入射角错误 | 位移量级成比例偏差 | `wavelength_m`、`incidence_deg` |
| 地理参考缺失 | 成果无法直接叠加到 GIS，范围显示为 0,0 | `corner_lon`、`corner_lat`、`lon_step`、`lat_step` |

导入前按下面顺序判断：

1. 是不是复数 SLC？不是的话，只能做演示，不要进入形变解释。
2. 是不是至少 2 景、同一网格、已经配准？不是的话，先回 SAR 预处理；已经配准的栈要勾选“导入的 SLC 已经配准”，否则会被二次重采样。
3. 日期是否完整、唯一、升序？缺失可以补，但补出来的日期不是观测日期，`dates_source` 会标记为 `inferred`，交付时要说明。
4. `bperp_m` 是否非零、长度是否等于景数？全零可以做 SBAS，但不能做地形改正和 DEM 误差估计。
5. DEM 是否同区域、同基准、米制？不确定就先做零 DEM 对照。
6. 掩膜是否覆盖主要陆地、剔除了水体和阴影？自动掩膜只能作为起点。
7. 传感器元数据是否是当前数据的真实值？不是的话，先改 `meta` 再导入。
8. 地理参考是否完整？缺少角点时成果只能按像元坐标使用，项目体检会给出警告。
9. 选哪条路线？先看景数、相干性和目标，不要默认所有数据都跑 SBAS。

## 6. 完整操作教程

这一章按场景给出可以直接照做的步骤。每个教程都包含目标、数据准备、操作顺序、参数起点、结果检查和失败处理。参数不是固定答案，第一次跑建议先用表中的起点，不要一次改很多项。

### 6.1 教程一：跑通 SBAS 演示

**目标**：确认安装、熟悉七步流程、得到第一份可检查的成果。

**准备**：

- Python 3.9–3.11 64 位；
- 项目根目录的 `start.bat` 或 `python -m insar_studio serve --open`；
- `python -m insar_studio doctor` 通过，SNAPHU 可选。

**步骤**：

1. 双击 `start.bat`，等待终端打印地址，例如 `http://127.0.0.1:8765`。浏览器打开这个地址，不要用旧标签页。
2. 左侧项目库点击“新建”，选择“演示项目”，名称填“SBAS 演示”，路线选 `SBAS`。
3. 进入“数据”页，核对：
   - 影像数 `24`；
   - 尺寸 `220 × 260`；
   - 日期从 `2023-01-03` 到 `2023-10-06`，间隔 12 天；
   - 振幅预览有城市、山地、水体纹理；
   - DEM、掩膜、真值信息都存在。
4. 进入“网络”页，点击“生成网络”。默认参数如下：

| 参数 | 值 | 作用 |
| --- | ---: | --- |
| `max_temporal_baseline` | 72 天 | 允许的最大时间基线 |
| `max_perpendicular_baseline` | 180 m | 允许的最大垂直基线 |
| `max_pairs` | 80 | 干涉对软上限 |
| `ref_index` | 0 | 参考影像索引 |

5. 检查网络指标：干涉对数应在几十对量级，冗余度大于 3，连通分量必须为 1。如果连通分量大于 1，先不要继续，回到网络页检查日期和基线阈值。
6. 进入“干涉”页，点击“运行干涉”。默认参数如下：

| 参数 | 值 |
| --- | ---: |
| `multilook` | 2 |
| `coherence_window` | 5 |
| `filter` | boxcar |
| `boxcar_size` | 3 |
| `unwrap_method` | quality |
| `unwrap_coherence_min` | 0.18 |
| `min_coherence` | 0.25 |
| `remove_ramp` | true |

7. 逐对检查：振幅图是否有纹理、缠绕相位是否有连续条纹、相干性是否成片、解缠相位是否有大块跳变。演示数据的平均相干性通常较高；如果某一对明显异常，先记录对号，不要急着改全局参数。
8. 进入“大气”页，演示项目默认使用“演示 GACOS”。运行后看三张诊断图：逐日 APS 屏、校正前后相位分布、逐对散点。演示数据的校正后分布应更集中。
9. 进入“反演”页，保持默认：`regularization=0.30`、`robust_iterations=3`、`estimate_dem_error=false`、`reference_mode=auto`、`aps_sigma_px=10`、`aps_iterations=1`。点击“运行反演”。
10. 完成后自动进入“成果”页。依次检查速率图、时序相干性、残差、DEM 误差、APS、网络图和配准增益图。
11. 在像元时间序列里输入一个行列号，或点击“跳到形变峰值”，确认时间序列没有整体跳变。
12. 点击“真值校验”。演示数据的位移 RMSE 应达到“优秀”或“良好”；如果达到“需检查”，先看解缠和参考点。
13. 点击“生成报告”，再点击“下载成果包 ZIP”，选择“成果包”（精简）或“完整包”。打开报告，确认路线、参数、参考像元、统计指标和图表都在。
14. 回到项目标题区点击“项目体检”，确认 0 错误；警告项要能解释。

**演示项目的合理预期**：

- 全流程在本机通常是几十秒量级，取决于 CPU 和磁盘；
- 速率图应能看出合成形变的主要空间形态；
- 残差不应出现明显的时间趋势或与地形强相关；
- 真值 RMSE 只用于回归，不代表真实数据精度。

**如果失败**：

| 现象 | 先做什么 |
| --- | --- |
| 页面打不开 | 看终端地址和端口，`Ctrl+F5`，确认没有连到旧端口 |
| 网络连通分量大于 1 | 提高 `max_temporal_baseline` 或 `max_perpendicular_baseline` 后重建 |
| 干涉平均相干性很低 | 确认没有误导入振幅数据；检查 `ref_index` 和配准 |
| 解缠大片跳变 | 提高 `unwrap_coherence_min`，换 Goldstein，检查配准 |
| 反演后速率全为 0 | 检查输入是否实数振幅、掩膜是否为空、是否只跑了一半流程 |
| 报告没有生成 | 在成果页重新点击“生成报告”，再看项目体检提示 |

### 6.2 教程二：导入真实 SLC 栈跑 SBAS

**目标**：把外部预处理好的 SLC 栈导入工作台，完成一次可解释的 SBAS 时序处理。

**第一步：在外部完成 SAR 预处理**

真实 Sentinel-1 TOPS 数据不要直接导入。先在 SNAP、ISCE 或 Gamma 中完成：

1. 应用精密轨道；
2. burst 拼接、去斜；
3. TOPS 配准；
4. 生成同一网格上的复数 SLC 栈；
5. 准备同区域 DEM 和有效掩膜；
6. 从轨道导出每景垂直基线。

**第二步：准备目录**

推荐使用原生目录：

```text
my_stack/
  slc.npy          # complex64, (n_dates, rows, cols)
  dem.npy          # float32, (rows, cols)，可选但强烈建议
  mask.npy         # bool, (rows, cols)，可选
  meta.json        # 日期、基线、传感器参数
```

`meta.json` 示例：

```json
{
  "dates": ["2023-01-03", "2023-01-15", "2023-01-27", "2023-02-08"],
  "platform": "Sentinel-1A",
  "orbit_direction": "DESCENDING",
  "relative_orbit": 42,
  "bperp_m": [-35.2, 12.8, 64.1, -8.4],
  "wavelength_m": 0.05546576,
  "incidence_deg": 38.5,
  "range_spacing_m": 2.329562,
  "azimuth_spacing_m": 13.968,
  "slant_range_time_s": 0.0055,
  "azimuth_time_interval": 0.002055556,
  "start_times": ["2023-01-03T05:23:45.123456", "2023-01-15T05:23:45.123456", "2023-01-27T05:23:45.123456", "2023-02-08T05:23:45.123456"],
  "ref_index": 0,
  "corner_lon": 116.2,
  "corner_lat": 40.1,
  "lon_step": 0.0004,
  "lat_step": -0.0004,
  "crs": "EPSG:4326"
}
```

地理编码还需要参考影像的轨道状态向量。把 Sentinel-1 `POEORB`/`RESORB` 的 `.EOF` 文件放在数据目录、父目录，或在 `meta.json` 中写 `"orbit_dir": "D:/orbits/S1A"`。导入器会匹配每景 `start_times`，写出 `data/stack/orbits.json`；没有轨道或时间不匹配时，反演仍可完成，但 `products/geocode.json` 会标记为 `unavailable`。

**第三步：导入前自检**

在项目根目录运行下面的脚本，路径换成自己的：

```python
import json
from pathlib import Path

import numpy as np

root = Path(r"D:\data\my_stack")
slc = np.load(root / "slc.npy", mmap_mode="r")
meta = json.loads((root / "meta.json").read_text(encoding="utf-8"))

print("shape:", slc.shape)
print("dtype:", slc.dtype)
print("finite:", float(np.isfinite(slc).mean()))
print("dates:", len(meta.get("dates", [])))
print("bperp:", len(meta.get("bperp_m", [])))

assert slc.ndim == 3, "SLC 必须是 (日期, 行, 列)"
assert slc.shape[0] == len(meta["dates"]), "日期数与景数不一致"
assert slc.shape[0] >= 2, "D-InSAR 至少需要 2 景；PS/SBAS 需要 8 景，DS 需要 10 景"
```

再检查：

- `slc.dtype` 应为 `complex64`；
- `finite` 应接近 1，低于 0.999 会有警告，低于 0.5 会被拒绝；
- `bperp` 长度应与日期数一致，且不是全零；
- `dem.npy` 和 `mask.npy` 的形状应为 `(rows, cols)`；
- 日期没有重复，格式为 `YYYY-MM-DD`；
- 如果整栈已经配准，确认 `meta.json` 的 `already_coregistered` 与事实一致。

界面里的“预检并导入”会先做轻量检查（大栈只读头部和抽样像元），不写任何文件；预检通过后才询问是否覆盖当前栈。正式导入会对全部像元重新校验，抽样阶段漏掉的局部坏值仍会被拦下。

**第四步：创建工作台项目**

1. 左侧点击“新建”，选择“导入本地数据”。
2. 名称填站点名，路线选 `SBAS`。
3. 数据路径填 `D:\data\my_stack`，DEM 路径可留空（目录内已有 `dem.npy`），也可以单独指定 `dem.tif`。
4. 创建后进入“数据”页，重点看：
   - 日期数量和顺序；
   - 尺寸是否与预期一致；
   - `bperp_m` 是否非零；
   - 导入警告（`import_warnings`）是否只有可解释的提示；
   - 振幅、DEM、掩膜预览是否正常。

**第五步：网络**

第一次跑真实数据，用保守起点：

| 参数 | 起点 | 调整方向 |
| --- | ---: | --- |
| `max_temporal_baseline` | 72 天 | 对数太少就加到 96；相干性差就降到 48–60 |
| `max_perpendicular_baseline` | 180 m | 地形起伏大或 DEM 不稳就降到 100–150 |
| `max_pairs` | 80 | 先控制计算量，确认链路后再加 |
| `ref_index` | 0 | 选时间居中、质量好的影像；改动会触发重配准 |

检查连通分量为 1。如果对数明显少于日期数减一，先放宽时间基线；如果平均相干性很低，先查数据和配准，不要盲目加对数。

**第六步：干涉**

第一遍用默认值：

| 参数 | 起点 |
| --- | ---: |
| `multilook` | 2 |
| `coherence_window` | 5 |
| `filter` | boxcar |
| `boxcar_size` | 3 |
| `unwrap_method` | quality |
| `unwrap_coherence_min` | 0.18 |
| `min_coherence` | 0.25 |
| `remove_ramp` | true |

如果整体相干性偏低，按这个顺序小步调整：

1. `multilook` 2 → 4；
2. `coherence_window` 5 → 7；
3. `filter` 改 `goldstein`，`goldstein_alpha` 0.6–0.8；
4. `unwrap_coherence_min` 0.18 → 0.25；
5. `min_coherence` 0.25 → 0.30。

一次只改一类，重跑后比较平均相干性、有效像元比例和解缠连续性。

**第七步：大气**

- 有本地 GACOS：`atmosphere_method=gacos`，`gacos_source=local`，`gacos_dir` 指向目录；确认每个日期都有屏幕。
- 没有 GACOS：先用 `atmosphere_method=off` 跑一遍，保存速率图作为对照；再用 `empirical`，`empirical_order=1`，比较两次结果的差异。
- 演示项目才用 `gacos_source=demo`。

**第八步：反演**

第一遍保持：

| 参数 | 起点 |
| --- | ---: |
| `regularization` | 0.30 |
| `robust_iterations` | 3 |
| `estimate_dem_error` | false |
| `reference_mode` | auto |
| `aps_method` | spatiotemporal |
| `aps_sigma_px` | 10 |
| `aps_iterations` | 1 |

如果结果噪声大，先把 `regularization` 调到 0.35–0.45；如果明显过度平滑，降到 0.15–0.25。`estimate_dem_error` 只在垂直基线跨度足够、时序较长时再开。

**第九步：结果检查**

| 指标 | 经验判断 | 不理想时 |
| --- | --- | --- |
| 连通分量 | 必须为 1 | 放宽网络阈值 |
| 冗余度 | 2 以上可解，3 以上更稳 | 增加对数 |
| 平均相干性 | 城区/裸地常见 0.4–0.8，植被 0.2–0.4 | 低于 0.2 先查数据 |
| 有效像元比例 | 与场景和阈值有关，不应接近 0 | 降低 `min_coherence` 或检查掩膜 |
| 残差 | 不应有系统性时间趋势或地形相关 | 检查解缠、DEM、APS |
| 速率图 | 空间形态应与地质/人类活动背景相符 | 检查参考点、符号、轨道 ramp |

这些是经验值，不是验收标准。真实数据的精度最终要靠 GNSS、水准、角反射器或独立干涉结果交叉验证。

### 6.3 教程三：城市 PS

**目标**：在城市建筑、桥梁、裸岩等强散射区提取 PS 点，得到点目标时序位移和速率。

**数据条件**：

- 至少 8–12 景，建议同一轨道、同一入射角；
- 使用单视 SLC，不要用已经多视的 SLC；
- 场景中有稳定强散射体，如建筑屋顶、桥梁、岩石、角反射器；
- 轨道和基线质量较好，配准残差小；
- 植被覆盖高的区域不要期待高 PS 密度。

**步骤**：

1. 新建或导入项目，路线选 `PS`。
2. 数据页确认 SLC 是单视复数数据；如果已经是多视产品，PS 点会被平均掉。
3. 网络页设置：

| 参数 | 起点 | 说明 |
| --- | ---: | --- |
| `ps_star_all` | true | 所有影像连到参考景；数据大时可关掉以控制对数 |
| `max_temporal_baseline` | 96 天 | 关闭全星形时才主要用于限制星形边 |
| `max_pairs` | 140 | PS 对数通常比 SBAS 多 |
| `ref_index` | 0 或时间居中景 | 参考景质量影响整组结果 |

4. 检查网络：星形边应以参考景为中心，相邻对用于闭环，连通分量为 1。
5. 干涉页设置：

| 参数 | 起点 |
| --- | ---: |
| `multilook` | 1 |
| `coherence_window` | 3–5 |
| `filter` | boxcar |
| `boxcar_size` | 3 |
| `unwrap_method` | quality |
| `unwrap_coherence_min` | 0.20–0.25 |
| `min_coherence` | 0.25–0.30 |

6. 不要对 PS 使用强高斯或大窗口 Goldstein。强滤波会把点目标抹掉，看起来图更“干净”，但 PS 点会减少。
7. 大气阶段优先用本地 GACOS；没有 GACOS 时用经验高程或 `off`，并在反演阶段保留 APS。
8. 反演页设置：

| 参数 | 起点 | 调整 |
| --- | ---: | --- |
| `ps_adi_max` | 0.28 | 点太少放宽到 0.32–0.38；噪声多收紧到 0.22–0.25 |
| `ps_coherence_min` | 0.62 | 点太少降到 0.55；噪声多升到 0.68–0.72 |
| `regularization` | 0.25–0.30 | 噪声大略增 |
| `reference_mode` | auto | 有已知稳定点用 manual |
| `aps_iterations` | 1 | 不建议超过 2 |

9. 结果页检查 PS 点分布是否落在建筑、桥梁、岩石等强散射体上，而不是均匀铺满植被区。
10. 选几个 PS 点看时间序列，确认没有整体跳变和季节性异常。

**示例配置**：某城区 12 景 Sentinel-1 SLC，单视，`ps_adi_max=0.26`、`ps_coherence_min=0.62`、`max_temporal_baseline=96`、`max_pairs=140`、`multilook=1`。先看 PS 点密度和分布，再决定是否放宽阈值；不要用固定点数作为成功标准。

**限制**：

- PS 不是“任何地方都能测”。植被、农田、水面和施工区不适合；
- 叠掩、阴影和透视收缩区没有有效点；
- 桥梁、大坝等大型结构可能有热膨胀信号，不能直接当成地质形变；
- 输出仍在处理网格上，不能直接叠加到地图；
- PS 点稀疏时，速率图的插值外观可能误导，交付时应同时给点分布图。

### 6.4 教程四：植被/农田 DS

**目标**：在低相干区利用分布式散射体做相位链接，提升覆盖。

**数据条件**：

- 至少 10 景，少于 6 景不要跑 DS；
- 同一轨道、同一几何，SLC 已配准；
- 时间基线尽量短，避免跨季节太多；
- 场景中有农田、裸土、草地、低矮植被等分布式散射体；
- 计算资源比 SBAS 更充足，DS 的局部矩阵分解更耗时。

**步骤**：

1. 新建或导入项目，路线选 `DS`。
2. 数据页确认景数、日期和掩膜；DS 对日期连通性更敏感。
3. 网络页设置：

| 参数 | 起点 | 说明 |
| --- | ---: | --- |
| `max_temporal_baseline` | 48–60 天 | 短基线保相干 |
| `max_perpendicular_baseline` | 100–150 m | 降低 DEM 误差敏感度 |
| `max_pairs` | 60–80 | 控制计算量 |
| `ref_index` | 0 或时间居中景 | 参考景应质量好 |

4. 干涉页设置：

| 参数 | 起点 |
| --- | ---: |
| `multilook` | 2 |
| `coherence_window` | 5–7 |
| `filter` | goldstein 或 boxcar |
| `goldstein_alpha` | 0.6–0.75 |
| `boxcar_size` | 5 |
| `unwrap_method` | quality |
| `unwrap_coherence_min` | 0.25–0.30 |
| `min_coherence` | 0.20–0.25 |

5. 大气阶段优先 GACOS；没有 GACOS 时用 `empirical`，但要注意它可能吃掉真实长波形变。
6. 反演页设置：

| 参数 | 起点 | 说明 |
| --- | ---: | --- |
| `ds_patch` | 9–13，必须是奇数 | 块越大样本越多，分辨率越低 |
| `regularization` | 0.35–0.45 | 低相干区适当增强 |
| `aps_sigma_px` | 10 | 大尺度大气可到 15 |
| `aps_iterations` | 1 | 不建议超过 2 |
| `reference_mode` | auto | 稳定点难找时可 manual |

7. 结果页重点看 DS 相干性、有效像元覆盖和时间序列连续性。DS 的覆盖率提升应伴随相干性下降，这是正常的折中。
8. 如果块内样本不足或结果破碎，先把 `ds_patch` 从 9 调到 11 或 13，再考虑放宽相干性阈值。

**示例配置**：某农业区 14 景 Sentinel-1 SLC，`multilook=2`、`ds_patch=11`、`max_temporal_baseline=48`、`max_pairs=72`、`min_coherence=0.22`、`regularization=0.40`。先用小范围验证，再扩大到整景。

**限制**：

- 少于 6 景无法做相位链接，DS 路线整体要求至少 10 景；
- 相位链接固定使用特征值分解（EMI），局部协方差按逐像元滑窗估计、重叠率固定为 100%，因此没有重叠率和链接方法开关；协方差按行块计算，单块缓存不超过 256 MiB（约 268 MB），成对相干性在重建干涉图时按对重算；
- `ds_patch` 必须为奇数，偶数会提交失败；
- 低相干区的结果空间分辨率低于 PS，且更容易受大气和 DEM 误差影响；
- 特征分解时间随景数立方增长，景数很多时即使内存够用也会明显变慢；大栈建议先降采样或减少对数验证流程。

### 6.5 教程五：D-InSAR 应急

**目标**：用两景影像快速得到一次事件或短时间内的 LOS 位移场。

**数据条件**：

- 至少 2 景，最好是事件前、事件后各一景；
- 同一轨道、同一 frame、同一成像模式；
- 时间间隔尽量短，减少去相干；
- 有同区域 DEM 和基线；
- 形变梯度不能大到条纹完全混叠。

**步骤**：

1. 新建或导入项目，路线选 `D-InSAR`。
2. 如果导入的栈多于 2 景，在网络页选择主影像和从影像；默认是第 `n//3` 景和最后一景，应急时应手动指定事件前后。
3. 检查选中的对：`dt_days` 是否符合事件时间，`bperp_diff` 是否合理，两景是否同几何。
4. 干涉页设置：

| 参数 | 起点 | 说明 |
| --- | ---: | --- |
| `multilook` | 2–4 | 形变梯度大时适当增大 |
| `coherence_window` | 5 | 低相干时 7 |
| `filter` | goldstein | `goldstein_alpha=0.6–0.8` |
| `unwrap_method` | quality 或 snaphu | 条纹密集时优先 SNAPHU |
| `unwrap_coherence_min` | 0.20–0.30 | 低相干区可降到 0.15 |
| `min_coherence` | 0.20–0.30 | 先保证覆盖 |
| `remove_ramp` | true | 应急时先去低阶轨道趋势 |

5. 大气阶段：有 GACOS 用 GACOS；没有则用 `off` 或 `empirical`，并在解释时明确说明单对无法分离大气。
6. 反演页直接生成单帧位移，不生成速率。检查位移图的符号、单位和参考点。
7. 结果页看缠绕相位、解缠相位和位移三张图。解缠相位出现整片 `2π` 跳变时，先提高相干性阈值或换 SNAPHU，不要用强滤波掩盖。
8. 与外部资料对比：USGS/GFZ 同震模型、GNSS 同震位移、光学影像或现场调查。单对 D-InSAR 不能独立确定形变机制。

**示例配置**：同震应急，事件前后两景 Sentinel-1，`multilook=4`、`filter=goldstein`、`goldstein_alpha=0.7`、`unwrap_method=snaphu`、`unwrap_coherence_min=0.22`、`min_coherence=0.25`、`remove_ramp=true`。

**限制**：

- 只有一帧，不能区分长期趋势、季节变化和同震形变；
- 大气、轨道、DEM 误差都会进入单帧位移；
- 大形变梯度会导致解缠失败，需要外部先验或分块处理；
- 升降轨几何不同，LOS 位移不能直接比较；
- 地理编码依赖参考轨道与完整几何元数据；缺少时成果仍为雷达坐标，叠加到地图前需要补齐元数据或外部处理。

### 6.6 教程六：无 GACOS 的山区

**目标**：在没有外部大气产品时，用 DEM 和经验高程校正尽量压低分层大气，同时不把真实形变一起扣掉。

**数据条件**：

- 至少 8 景，时间跨度覆盖完整季节；
- 有同区域、同基准、米制 DEM；
- `bperp_m` 非零，垂直基线有一定跨度；
- 场景地形起伏明显，SAR 几何有叠掩/阴影时要先掩膜。

**步骤**：

1. 导入时提供 DEM，确认数据页没有“未提供 DEM”或“DEM 为常数”的警告。
2. 网络页设置：

| 参数 | 起点 | 说明 |
| --- | ---: | --- |
| `max_temporal_baseline` | 48–72 天 | 山区植被去相干快，不宜太长 |
| `max_perpendicular_baseline` | 80–120 m | 降低 DEM 误差敏感度 |
| `max_pairs` | 60–80 | 先控制计算量 |

3. 干涉页设置：

| 参数 | 起点 |
| --- | ---: |
| `multilook` | 2–4 |
| `coherence_window` | 5–7 |
| `filter` | goldstein |
| `goldstein_alpha` | 0.65–0.80 |
| `unwrap_coherence_min` | 0.25–0.35 |
| `min_coherence` | 0.30–0.40 |
| `remove_ramp` | true |

4. 先用 `atmosphere_method=off` 跑一遍，保存速率图和残差图作为对照。
5. 再用 `atmosphere_method=empirical`，`empirical_order=1` 或 `2`，`empirical_iterations=3`，重跑大气和反演。
6. 对比两次结果：
   - 校正后相位—高程相关性应下降；
   - 速率图不应出现大面积与地形强相关的假形变；
   - 已知稳定区的时间序列应更平。
7. 只有在垂直基线跨度足够、时序较长时，才尝试 `estimate_dem_error=true`。打开后如果速率图出现新的长波纹理，或与高程相关，先关掉。
8. 反演参数用 `regularization=0.20–0.30`、`aps_sigma_px=8–15`、`aps_iterations=1`，不要同时开强正则、强 APS 和 DEM 误差。

**示例配置**：某山区 16 景 Sentinel-1，DEM 为 30 m，`multilook=2`、`max_temporal_baseline=60`、`max_perpendicular_baseline=100`、`filter=goldstein`、`goldstein_alpha=0.7`、`unwrap_coherence_min=0.30`、`min_coherence=0.35`、`empirical_order=2`、`regularization=0.25`。

**限制与警告**：

- 经验高程校正假设大气与高程相关，真实大气不总满足这个假设；
- 阶数越高越容易过拟合，`empirical_order=3` 要慎用；
- 经验校正会把真实的长波形变当成大气扣掉，宽尺度研究要保留 `off` 对照；
- DEM 误差和形变在短时序、低冗余时共线，`estimate_dem_error` 可能给出错误符号；
- 没有 GNSS/水准时，山区结果的绝对精度很难独立验证。

### 6.7 教程七：命令行与 API 批处理

**目标**：不打开网页，批量创建项目、跑流程、导出成果。

**命令行**：

```powershell
# 环境自检
python -m insar_studio doctor

# 创建并运行演示
python -m insar_studio demo --name "SBAS 批处理演示" --technique sbas

# 重跑已有项目，参数用项目 ID 或名称
python -m insar_studio run prj_xxxxxxxx_xxxxxx
python -m insar_studio run "SBAS 批处理演示"

# 列出项目
python -m insar_studio projects
python -m insar_studio projects --json

# 启动服务
python -m insar_studio serve --port 8765
```

**API 批处理**：先启动服务，再运行下面的脚本。每个站点一个目录，脚本创建导入项目、提交全流程、轮询作业、下载 ZIP。

```python
import time
from pathlib import Path

import requests

BASE = "http://127.0.0.1:8765"
SITES = [
    {"name": "site-a", "path": r"D:\data\site-a", "dem": r"D:\data\site-a\dem.tif"},
    {"name": "site-b", "path": r"D:\data\site-b", "dem": None},
]
OUT = Path(r"D:\data\insar-results")
OUT.mkdir(parents=True, exist_ok=True)

with requests.Session() as s:
    for site in SITES:
        payload = {
            "name": site["name"],
            "technique": "sbas",
            "source": "import",
            "path": site["path"],
            "dem_path": site["dem"],
        }
        r = s.post(f"{BASE}/api/projects", json=payload, timeout=300)
        r.raise_for_status()
        project_id = r.json()["project"]["id"]
        print(site["name"], "project:", project_id)

        r = s.post(
            f"{BASE}/api/projects/{project_id}/run",
            json={
                "technique": "sbas",
                "params": {
                    "multilook": 2,
                    "max_temporal_baseline": 72,
                    "max_perpendicular_baseline": 180,
                    "max_pairs": 80,
                },
            },
            timeout=30,
        )
        if r.status_code == 409:
            raise SystemExit(f"{site['name']} 已有作业在运行")
        r.raise_for_status()
        job_id = r.json()["job"]["id"]

        while True:
            r = s.get(f"{BASE}/api/jobs/{job_id}", timeout=30)
            r.raise_for_status()
            state = r.json()
            print(site["name"], state.get("status"), state.get("progress"))
            if state.get("status") in {"done", "failed", "cancelled", "interrupted"}:
                break
            time.sleep(2)

        if state.get("status") != "done":
            print(site["name"], "FAILED:", state.get("error"))
            continue

        r = s.get(f"{BASE}/api/projects/{project_id}/export", timeout=600)
        r.raise_for_status()
        out = OUT / f"{site['name']}-{project_id}.zip"
        out.write_bytes(r.content)
        print(site["name"], "zip:", out, len(r.content), "bytes")
```

**只跑单个阶段**：

```python
s.post(f"{BASE}/api/projects/{project_id}/network", json={"params": {...}})
s.post(f"{BASE}/api/projects/{project_id}/interferometry", json={"params": {...}})
s.post(f"{BASE}/api/projects/{project_id}/atmosphere", json={"params": {...}})
s.post(f"{BASE}/api/projects/{project_id}/inversion", json={"params": {...}})
```

这些接口都返回 202 和作业 ID，仍然需要轮询 `/api/jobs/<job_id>`。

**注意事项**：

- 作业提交成功不等于完成，必须轮询状态；
- 同一项目同时只允许一个作业，重复提交返回 409；全局最多同时执行 2 个作业，其余排队；
- 取消是协作式的，单个长 NumPy/SciPy 调用不会立即中断；
- API 没有认证，只应监听 `127.0.0.1`；
- JSON 请求体默认上限 4 MiB，超过返回 413；GACOS multipart 上传另限 512 MiB；
- 批处理前先确认磁盘空间，完整包可能包含大量干涉产品和图件；
- 失败站点要记录错误信息，不要用同一个项目反复重试到状态混乱。

### 6.8 教程八：成果检查与交付

**目标**：把一次处理整理成别人能看懂、能复查、能复现的交付物。

**第一步：项目体检**

点击“项目体检”，检查：

- 数据、参数指纹、配准、网络、干涉、大气、反演、报告和磁盘空间；
- 错误必须为 0；
- 警告要能解释，例如“部分日期缺失，已按 12 天补齐”“没有提供 DEM”。

**第二步：看四类图**

| 图 | 看什么 | 异常信号 |
| --- | --- | --- |
| 速率/位移主图 | 空间形态、符号、量级、边界 | 大面积条纹、与地形强相关、边界突变 |
| 时序相干性 | 哪些区域可信 | 整体偏低、城市以外也异常高 |
| 残差 | 还有没有未解释信号 | 时间趋势、季节项、空间条带 |
| APS/DEM 误差 | 校正是否过度 | 把真实形变当成大气或地形扣掉 |

**第三步：看时间序列**

- 选参考点、形变峰值点和稳定区点各一条；
- 检查是否有整体跳变、`2π` 台阶、季节性异常；
- 检查参考点附近是否稳定；
- 把时间序列和降雨、地下水、施工、地震等外部信息对照。

**第四步：生成报告**

点击“生成报告”，得到：

```text
products/report/report.md
products/report/report.docx
```

报告只读项目文件，不重新计算。检查报告中的路线、参数、参考像元、统计指标和图件是否与当前成果一致。

**第五步：导出 ZIP**

点击“下载成果包 ZIP”，弹窗会显示两种模式的未压缩体积和文件数，并推荐“成果包”（精简）：

- **成果包（精简）**：`project.json` + `products/`。包含数组、GeoTIFF、CSV、图件和报告，不含原始 SLC、配准栈、干涉图和大气产品。适合发给同事看图、写报告。
- **完整包**：在精简包基础上加入 `data/stack/`、`data/network.json`、`data/processed/coreg.json`、`data/atmosphere/` 和 `interferograms/`。适合归档或在另一台机器复现。

两种包都跳过 `products/exports/` 自身，避免递归打包。若只需要图件和报告，也可以直接从项目目录取 `products/figures/` 和 `products/report/`。

**第六步：整理交付包**

建议命名：

```text
site-a_SBAS_YYYYMMDD_v1.zip
site-a_SBAS_YYYYMMDD_v1_notes.md
```

`notes.md` 至少写：

- 数据来源、轨道号、升降轨、时间范围；
- 景数、尺寸、波长、入射角、像元间距；
- 使用的路线和关键参数；
- 参考像元位置和符号约定；
- 是否使用 GACOS，GACOS 来源和覆盖日期；
- 已知问题和未验证项；
- 软件版本和运行日期。

**交付前检查清单**：

- [ ] 项目体检 0 错误，警告有解释；
- [ ] 速率/位移、相干性、残差、APS 图都检查过；
- [ ] 参考像元合理，符号和单位确认；
- [ ] 关键参数已记录，成果与参数一致；
- [ ] 报告和 ZIP 能打开；
- [ ] ZIP 内没有 `gacos_token`、`gacos_email`、密码、私钥和本机绝对路径；
- [ ] `interferograms/summary.json` 已检查敏感字段；
- [ ] 真实数据已确认地理编码/投影状态；
- [ ] 原始数据和成果已备份。

## 7. 参数详解与调参建议

### 7.1 参数如何生效

- 运行时参数 = 引擎默认值 + 项目已保存参数 + 本次请求参数。项目参数会递归过滤敏感字段；引擎摘要和作业记录在落盘前统一脱敏（见 4.6 的安全提示）。
- 每个阶段有参数指纹。修改了某阶段相关参数但没有重跑，项目体检会提示“参数待重跑”。
- 切换技术路线会重置 5 个路由参数（`multilook`、`max_temporal_baseline`、`max_pairs`、`ps_star_all`、`ds_patch`）为新路线默认值；其他参数保留。要在切换时保留某个路由参数，必须在同一次请求里显式传值。
- 参数校验在 `insar_studio/params.py` 中完成。未知参数会保留，`params.py` 中登记的已知参数会做类型和范围检查。
- 界面只暴露一部分参数；API、配置文件或导入项目可以包含更多自由参数。

### 7.3 网络参数

| 参数 | 默认 | 引擎允许范围 | 作用与影响 | 推荐起点 |
| --- | ---: | --- | --- | --- |
| `max_temporal_baseline` | 72 天 | 6–730 | 调大：对数多、覆盖好，但时间去相干增加；调小：相干性好，但对数少、可能不连通 | 一般 48–96；植被/快速形变 24–60；稳定城区 72–120 |
| `max_perpendicular_baseline` | 180 m | 5–3000 | 调大：对数多，但 DEM 误差和相位模糊更敏感；调小：对 DEM 误差不敏感，但对数少 | 一般 120–200；地形起伏大 80–120；平坦且 DEM 可靠 200–300 |
| `max_pairs` | 80 | 1–1000 | 控制计算量和冗余度；是软上限，为保证连通性可能被突破 | SBAS/DS 60–100；PS 120–160；资源有限 40–60 |
| `ref_index` | 0 | 0–1000000 | 参考影像索引；影响配准和网络参考。应选时间居中、质量好的影像 | 默认 0 可用；长时序选中间日期或超级主影像 |
| `ps_star_all` | PS 为 true | 布尔 | PS 全星形：所有影像连到参考影像；关闭后只保留时间基线内的星形边，再补相邻对 | 小数据保留 true；大数据可 false 以控制对数 |
| `dinsar_pair` | null | 两个日期索引或 `"00_05"` | D-InSAR 指定主/从影像；字符串和列表等价 | 应急时明确指定 `[ref, sec]` 或 `"ref_sec"` |

补充：

- PS 的全星形边不检查 `max_perpendicular_baseline`；该参数主要影响 SBAS/DS。
- `max_pairs` 裁剪会优先保留短时间基线、短垂直基线的对；如果裁剪后日期图连通分量变多，代码会放弃裁剪，因此实际对数可能大于设定值。
- 修改 `ref_index` 会触发配准和网络重跑，成本较高。

### 7.4 干涉与解缠参数

| 参数 | 默认 | 引擎允许范围 | 作用与影响 | 推荐起点 |
| --- | ---: | --- | --- | --- |
| `multilook` | 2 | 1–8 | 调大：噪声低、分辨率低、计算快；调小：保留细节，但噪声大 | PS 1；一般 2；低相干/大区域 4；8 仅踏勘 |
| `coherence_window` | 5 | 3–31，奇数 | 相干性估计窗口；调大更平滑但空间分辨率下降 | 3–5 城区；5–7 一般；7–9 低相干 |
| `filter` | boxcar | boxcar / goldstein / gaussian（gauss）/ nlmeans（nl-means、nlm）/ none | Boxcar 稳健；Goldstein 保频谱峰；高斯更平滑；NL-Means 保边但慢 | 默认 boxcar；噪声大 goldstein；保边 nlmeans；对比时 none |
| `boxcar_size` | 3 | 1–31，奇数 | Boxcar 窗口；调大更平滑，过大糊掉细节 | 3–5；低相干 5–7；PS 保持 3 或更小 |
| `goldstein_alpha` | 0.65 | 0–1.5 | Goldstein 强度；越大抑制越强 | 0.5–0.8；弱噪声 0.4–0.6；强噪声 0.7–0.9 |
| `goldstein_patch` | 32 | 8–128 | Goldstein 分块大小；越大越全局，越小越局部 | 24–64；小图 16–32；大图 64–96 |
| `gaussian_sigma` | 2.0 | 0.3–12 | 高斯低通尺度；越大越平滑 | 1–3；强噪声 3–5；不建议超过 6 |
| `unwrap_method` | quality | quality / snaphu / skimage（least-squares） | 质量引导稳健；SNAPHU 需安装；最小二乘适合连续低噪声相位 | 默认 quality；有 SNAPHU 可对比；连续低噪声用 skimage |
| `unwrap_coherence_min` | 0.18 | 0–0.99 | 解缠时使用的相干性下限；调高减少错误但增加空洞 | 0.15–0.25 一般；0.25–0.35 噪声大；0.10–0.18 高相干 |
| `min_coherence` | 0.25 | 0–0.99 | 有效像元掩膜阈值；调高结果干净但覆盖少 | 0.20–0.30 一般；0.30–0.45 噪声大；0.15–0.20 高相干 |
| `remove_ramp` | true | 布尔 | 解缠后去除低阶趋势面；会同时移除同尺度的真实长波形变 | 首次处理 true；研究宽尺度形变时 false |
| `ramp_order` | 1 | 1 或 2 | 趋势面阶数；1=平面，2=二次曲面，二次项更强地吸收长波信号 | 默认 1；确认存在二次轨道误差时用 2 |
| `snaphu_exe` | `snaphu` | 字符串，最长 260 | 指定 SNAPHU 可执行文件；找不到时自动回退质量引导 | 一般不用填；多版本环境填绝对路径 |

注意：

- `remove_ramp` 支持 `ramp_order=1`（平面）和 `ramp_order=2`（二次曲面），默认 1。二次项会更强地吸收真实长波信号，研究宽尺度形变或没有明确二次轨道误差时应谨慎。
- `min_coherence` 和 `unwrap_coherence_min` 不是同一个阈值。前者控制最终有效像元，后者控制解缠阶段。
- 滤波只影响缠绕相位和解缠输入，不会改变原始复数干涉图。
- 多视因子会影响后续所有阶段的网格；修改后必须重跑干涉及下游。

### 7.5 大气参数

| --- | --- | --- | --- | --- |
| `atmosphere_method` | 演示 gacos；导入 empirical | gacos / empirical / off | GACOS 用外部延迟；经验高程用相位—高程回归；off 保留原始相位 | 有 GACOS 用 gacos；无外部数据用 empirical；先看原始结果用 off |
| `gacos_source` | demo 或 official | demo / official / local / online | 演示合成、官方邮件产品、本地文件、自定义在线服务 | 演示项目 demo；真实项目 official；已有本地产品用 local |
| `gacos_dir` | 空 | 本地路径 | 本地 GACOS 目录；文件名需含日期 | `gacos_source=local` 时指向按日期命名的目录 |

| `gacos_timeout` | 60 s | 整数；建议 30–120（未校验） | 自定义在线请求超时 | 30–120；慢网络可更长 |
| `gacos_dem` | `SRTM` | 字符串；建议按服务文档填写（未校验） | 自定义在线服务使用的 DEM 模型 | 按服务文档填写 |

| `aps_method` | spatiotemporal | spatiotemporal / off | 反演阶段是否做时间高通 APS 分离 | 默认开；长波形变明显时关 |

- 所有 JSON 落盘前会递归脱敏，`gacos_token` 等字段的值变为 `***`；仍不要把真实凭据写进项目备注或明文配置文件。

### 7.7 PS / DS 专用参数

| 参数 | 默认 | 引擎允许范围 | 作用与影响 | 推荐起点 |
| --- | ---: | --- | --- | --- |
| `ps_adi_max` | 0.28 | 0.01–0.8 | PS 振幅离差上限；越小点越少越稳，越大点越多噪声越多 | 城市 0.20–0.28；稀疏区 0.30–0.40；严格 0.15–0.22 |
| `ps_coherence_min` | 0.62 | 0.01–0.99 | PS 平均相干性下限；越高点越少 | 城市 0.55–0.65；稀疏区 0.45–0.55；严格 0.65–0.75 |
| `ps_star_all` | true | 布尔 | PS 是否使用全星形网络 | 小数据 true；大数据 false |
| `ds_patch` | 9 | 3–41；DS 路线要求奇数 | DS 局部相干矩阵的滑窗大小；越大样本越多、越平滑、分辨率越低 | 7–11 一般；5–7 异质区；13–21 低相干 homogeneous 区 |
| `ds_coherence_min` | 0.18 | 浮点；建议 0.15–0.25（未校验） | DS 有效像元相干性下限，引擎读取，界面未暴露 | 0.15–0.25 |
| `ds_filter_size` | 3 | 整数；建议 3–5（未校验） | DS 重建干涉图后的 Boxcar 大小，引擎读取，界面未暴露 | 3–5 |

注意：

- `ds_patch` 只在 DS 路线（或未指定路线）下校验奇偶性，DS 必须用奇数；界面允许输入偶数，但提交会失败。其他路线不使用该参数，建议仍填 9、11、13。
- 相位链接固定使用特征值分解（EMI）；局部协方差按逐像元滑窗估计，窗口重叠率固定为 100%。`ds_overlap` 和 `ds_phase_linking` 已从默认参数和界面中移除，不再作为调参项。
- DS 协方差按行块计算，单块缓存受 256 MiB（约 268 MB）预算约束；成对相干性在重建阶段按对重算，不再保存全量相干矩阵。PS 振幅离差按行块流式累计。
- `ds_patch`、`ds_coherence_min`、`ds_filter_size` 已纳入干涉阶段指纹；修改后需要重跑干涉及下游阶段。
- PS 路线应保持 `multilook = 1`，否则会破坏点目标采样。
- PS 选点少于阈值时会自动放宽并标记 `relaxed=true`；如果点密度异常高，检查 ADI 和相干性阈值是否过松。若相干性全部无效导致候选点为 0，反演会明确报错并提示降低 `ps_adi_max`、`ps_coherence_min` 或检查振幅和有效掩膜，不会伪造 PS 点。

### 7.8 配准高级参数

这些参数主要供 API、配置文件和高级排障使用，界面通常不暴露：

| 参数 | 默认 | 允许范围 | 作用 | 建议 |
| --- | ---: | --- | --- | --- |
| `ref_index` | 0 | 0–1000000 | 配准参考影像 | 选时间居中、质量好的影像 |
| `model` | affine | affine / translation / similarity | 配准变换模型；affine 允许旋转、剪切和尺度，similarity 只允许旋转 + 统一尺度 + 平移，translation 只估计整体偏移 | 常规用 affine；几何稳定、只需偏移时用 translation；轨道/入射角差异明显但不应有剪切时用 similarity |
| `tile` | 64 | 16–256 | 分块相位相关窗口 | 小图 32–64；大图 64–128；纹理弱时适当增大 |

### 7.9 常见场景的参数组合

下面的组合是“起点”，不是固定答案。每次只改一类参数，重跑后比较相干性、残差、有效像元和速率图。

| 场景 | 关键设置 | 说明 |
| --- | --- | --- |
| 第一次跑通 / 区域沉降 | 全部默认；SBAS；`multilook=2`；`remove_ramp=true` | 先用默认值建立基线，再决定是否调参 |
| 植被、农田、低相干 | `multilook=4`；`max_temporal_baseline=48–60`；`max_perpendicular_baseline=100–150`；`filter=goldstein`；`goldstein_alpha=0.6–0.8`；`unwrap_coherence_min=0.25–0.35`；`min_coherence=0.30–0.40`；`regularization=0.35–0.50` | 用多视和短基线换相干性，接受分辨率下降 |
| 城市 PS | `multilook=1`；`max_temporal_baseline=96`；`max_pairs=140`；`ps_adi_max=0.20–0.28`；`ps_coherence_min=0.60–0.70`；`filter=boxcar`；`boxcar_size=3` | 保持单视和点目标，不要用强滤波 |
| 植被 DS | `multilook=2`；`ds_patch=9–13`；`max_temporal_baseline=48–72`；`min_coherence=0.20–0.25`；`regularization=0.30–0.40` | DS 计算量大，先小范围验证 |
| 地形起伏大、无 GACOS | `atmosphere_method=empirical`；`empirical_order=1–2`；`max_perpendicular_baseline=80–120`；`estimate_dem_error=true`（仅时序足够长时） | 经验校正可能吃掉长波形变，务必对比校正前后 |
| 快速滑坡/强形变 | `max_temporal_baseline=24–48`；`multilook=2`；`unwrap_coherence_min=0.22–0.30`；`regularization=0.15–0.25` | 短基线保相干，低正则保留快速变化 |
| 大区域/算力有限 | `multilook=4`；`max_pairs=40–60`；`filter=boxcar`；`boxcar_size=5`；`unwrap_method=quality`；关闭不必要的 GACOS | 先降采样和减对数，再考虑分块处理 |
| 同震/应急 D-InSAR | 单对；`multilook=2–4`；`filter=goldstein`；`unwrap_coherence_min=0.20–0.30`；`remove_ramp=true` | 单对没有时间约束，必须结合外部信息解释 |
| 宽尺度长波形变 | `remove_ramp=false`；`regularization=0.05–0.15`；`aps_iterations=0–1`；谨慎使用经验高程 | 去趋势和强 APS 会移除真实长波信号 |

### 7.10 调参流程

建议按下面的顺序做，避免“一次改十个参数，不知道哪个起作用”：

1. **建立基线**：用默认参数跑一遍，保存 `summary`、速率图、残差图和项目体检结果。
2. **定位问题**：先判断是数据问题（未配准、低相干、DEM 不匹配）还是参数问题。数据问题不要靠调参解决。
3. **只改一类参数**：例如只调网络基线，或只调解缠阈值，不要同时改滤波、正则化和 APS。
4. **重跑受影响阶段**：网络变了要重跑干涉、大气、反演；只改反演参数可以只重跑反演。
5. **看四个指标**：有效像元比例、时序相干性、残差中位数、速率图空间形态。不要只看一张图。
6. **做对照**：保留上一版结果或截图，比较差异是否在预期方向。
7. **记录参数**：项目体检会提示参数指纹；交付时把关键参数写进报告或备注。
8. **不要过拟合演示数据**：演示数据的真值用于回归，不是真实场景的调参目标。

### 7.11 参数交互与常见误区

| 误区 | 后果 | 正确做法 |
| --- | --- | --- |
| 同时开强正则化和 DEM 误差估计 | 两者都吸收长波，速率被系统性低估 | 先关 DEM 误差，确认残差后再逐项开 |
| `aps_iterations` 调得很大 | 把真实形变当成 APS 扣掉 | 1–2 次；对比关闭前后的速率图 |
| `remove_ramp=true` 处理宽尺度形变 | 真实长波被低阶趋势面移除 | 研究宽尺度时关掉，或只在确认有轨道 ramp 时开，并优先用 `ramp_order=1` |
| `min_coherence` 和 `unwrap_coherence_min` 一起调得很高 | 有效像元大幅减少，反演覆盖不足 | 先调解缠阈值，再看有效像元 |
| PS 用 `multilook>1` | 点目标被多视平均掉 | PS 保持 1 |
| `filter` 用很强的高斯/Goldstein | 细节被抹平，PS 点减少 | 先轻滤波；PS 用 boxcar 3 |
| DS 路线下 `ds_patch` 填偶数 | 参数校验失败 | 只用奇数 |
| 在 DS 中寻找重叠率或链接方法开关 | 这两个参数已移除，避免无效调参 | 只调 `ds_patch`；相位链接固定为 EMI，窗口重叠固定 100% |
| D-InSAR 用字符串 `"00_05"` 指定对 | 已支持，字符串与列表等价 | 用字符串或列表均可 |
| 改完参数不重跑 | 成果仍对应旧参数 | 看项目体检的“参数待重跑”，重跑对应阶段 |

### 7.12 参数改动与重跑范围

参数不是保存后立即生效。每个阶段有参数指纹；修改后如果没有重跑，成果仍然对应旧参数。下表给出常见改动的最小重跑范围。

| 改动 | 例子 | 至少重跑 | 说明 |
| --- | --- | --- | --- |
| 导入新数据 | 新 SLC 栈、DEM、掩膜、日期、基线 | 全部 | 导入会清理派生成果 |
| 切换技术路线 | SBAS → PS | 全部 | 5 个路由参数会重置为新路线默认值 |
| 配准参数 | `ref_index`、`model`、`tile`、`upsample` | 配准 → 网络 → 干涉 → 大气 → 反演 | `ref_index` 还会改变网络参考 |
| 网络参数 | `max_temporal_baseline`、`max_perpendicular_baseline`、`max_pairs` | 网络 → 干涉 → 大气 → 反演 | 只改网络也必须重跑下游 |
| 干涉参数 | `multilook`、`coherence_window`、`filter`、`boxcar_size`、`goldstein_alpha`、`gaussian_sigma`、`unwrap_method`、`unwrap_coherence_min`、`min_coherence`、`remove_ramp`、`ramp_order`、`snaphu_exe` | 干涉 → 大气 → 反演 | `multilook` 改变网格；`remove_ramp`/`ramp_order` 也影响反演指纹 |
| 大气参数 | `atmosphere_method`、`gacos_source`、`aps_method`、`aps_sigma_px`、`aps_iterations` | 大气 → 反演 | `aps_*` 同时属于大气和反演阶段 |
| 经验大气细节 | `empirical_order`、`empirical_iterations` | 大气 → 反演 | 当前版本不在大气指纹里，体检可能不提示，必须手动重跑 |
| GACOS 细节 | `gacos_dir`、`gacos_url`、`gacos_token`、`gacos_timeout`、`gacos_dem` | 大气 → 反演 | 同样可能不在指纹里，换目录/凭据后手动重跑 |
| 反演参数 | `regularization`、`robust_iterations`、`estimate_dem_error`、`reference_mode`、`reference_row`、`reference_col` | 反演 | 只改这些通常不必重跑干涉 |
| PS 参数 | `ps_adi_max`、`ps_coherence_min`、`ps_star_all` | 反演；`ps_star_all` 还要重跑网络 → 干涉 → 大气 → 反演 | `ps_star_all` 改变网络，但当前网络指纹未包含它 |
| DS 参数 | `ds_patch`、`ds_coherence_min`、`ds_filter_size` | 干涉 → 大气 → 反演 | 三者已纳入干涉阶段指纹 |
| D-InSAR 对 | `dinsar_pair` | 网络 → 干涉 → 大气 → 反演 | 字符串和列表等价；已纳入网络与反演指纹 |

执行原则：

1. 先看项目体检的“参数待重跑”，但不要完全依赖它；上表中标了“指纹未包含”的参数，必须手动重跑。
2. 改一类参数，重跑一次，比较结果；不要一次改网络、滤波、正则化和 APS。
3. 重跑会清理下游产品。需要保留旧结果时，先导出 ZIP 或复制整个项目目录。
4. 参数指纹只说明“参数变过”，不说明新参数更好。每次重跑都要用相干性、有效像元、残差和速率图共同判断。

## 8. 常见问题与注意事项

### 8.1 安装与启动

**端口被占用怎么办？**

默认会从 8765 起自动向后找空闲端口，终端会打印实际地址。想固定端口并在被占用时明确失败：

```powershell
python -m insar_studio serve --port 8765 --strict-port
```

`--port 0` 表示交给操作系统分配。

**依赖安装失败怎么办？**

优先使用 Python 3.9–3.11 64 位。SciPy、scikit-image 需要和 NumPy 版本匹配；本项目在 NumPy 1.24 / SciPy 1.10 / scikit-image 0.20 / Matplotlib 3.7 上验证。若使用 conda，按 2.4 节单独建环境。

**没有 SNAPHU 能跑吗？**

能。默认质量引导解缠，不依赖 SNAPHU。只有显式选择 SNAPHU 且调用失败时才会回退，并在 `unwrap_info` 中记录原因。

**页面空白或按钮无反应怎么办？**

1. `Ctrl+F5` 强制刷新；
2. 看浏览器控制台是否有 JS 报错；
3. 看启动服务的终端有没有异常；
4. 确认浏览器访问的是终端打印的地址，而不是旧端口。

### 8.2 项目与数据

**为什么项目体检提示“参数待重跑”？**

说明上次处理后参数被修改过，当前成果仍对应旧参数。按体检建议重跑对应阶段；重跑会清理下游产品。体检本身是只读的。

**为什么任务运行时不能改参数或重复提交？**

同一项目同时只允许一个处理任务，避免两个任务同时写 `products/`。重复提交返回 409；等待完成或取消后再提交。

**任务提示“预计峰值内存”超过可用内存怎么办？**

这是阶段开始前的保护，不是已经 OOM。按提示优先增大 `multilook`、减少日期或干涉对数、关闭 APS/DEM 误差估计；也可以改用内存更大的机器。共享机器或容器里自动检测不准时，用 `INSAR_MEMORY_BUDGET_BYTES` 显式设置可用上限（见 2.1 节）。如果估算通过但任务仍被系统终止，说明实际峰值高于估算，应记录失败阶段和 RSS 后进一步降低规模。

**导入后全是噪声怎么办？**

先检查：SLC 是否已配准、轨道/基线元数据是否正确、DEM 是否同网格、掩膜是否覆盖有效区域、相干性阈值是否过低。真实 TOPS 数据不要直接拿未拼接的 burst 导入。

**我的 SLC 已经配准，导入后会再配一次吗？**

不会，前提是导入时明确标记。界面上勾选“导入的 SLC 已经配准”，或在 `meta.json` 中设置 `"already_coregistered": true`。导入器会把原始栈直接作为 `data/processed/slc_coreg.npy`，并写入 `model: "pre-coregistered"` 的 `coreg.json`；网络、干涉和显式配准阶段都会跳过二次重采样。只有确认整栈已配准到同一参考时才应勾选，否则配准误差会原样进入干涉链。

**没有地理坐标能跑吗？**

可以跑，但成果只能按像元坐标使用，导出的雷达网格 GeoTIFF 会使用占位范围，不能直接叠加到 QGIS/ArcGIS 的底图上。导入预检和项目体检都会明确警告。需要地图坐标时，在 `meta.json` 中提供 `start_times`、`azimuth_time_interval`、`range_spacing_m`、`slant_range_time_s`（或显式 `slant_range_m`），并把 Sentinel-1 `.EOF` 放在数据目录、父目录或 `orbit_dir`。反演后会输出 `products/geotiff/geo/` 和 `products/geocode.json`；如果只想复用已有经纬度网格，可同时提供 `corner_lon`、`corner_lat`、`lon_step`、`lat_step` 并设置 `"geo_referenced": true`。

**地理编码成功了吗？产物在哪里？**

查看 `products/geocode.json` 的 `status`：`done` 表示覆盖率 ≥ 50%，`partial` 表示只覆盖部分地图网格，`failed` 表示几何求解失败，`unavailable` 表示轨道或几何元数据不足。`files` 列出已写出的地图坐标 GeoTIFF，通常包括 `velocity_mm_yr.tif`、`temporal_coherence.tif`、`dem_error_m.tif` 和逐日 `disp_YYYYMMDD.tif`；D-InSAR 还包括 `disp_pair_mm.tif` 和 `coherence.tif`。`lookup_blocks`、`lookup_block_rows`、`lookup_workers` 和 `lookup_seconds` 记录本次查找表的分块、线程和耗时；5000×5000 网格约需 90 秒和 418 MB 峰值增量，输出数组本身约 325 MB。项目体检的“地理编码”项和报告中的处理链表也会显示同一状态。

**最少需要几景？**

技术路线的最少影像数由 `config.py` 的 `TECHNIQUES` 声明并强制校验：D-InSAR 2 景、SBAS 8 景、PS 8 景、DS 10 景。导入、切换路线、启动全流程都会在开始处理前检查，不足时直接报错并保留原路线状态。实际使用建议 SBAS/PS 准备 8–12 景，DS 准备 10 景以上；DS 的相位链接内部还要求至少 6 个历元，但路线整体下限是 10 景。

**D-InSAR 的日期对怎么指定？**

界面直接选主/从影像。API 用 `"dinsar_pair": [ref_index, sec_index]` 或 `"dinsar_pair": "00_05"`，两者等价，索引从 0 开始；网络阶段会生成指定的一对。

**可以把项目复制到另一台机器吗？**

可以。复制整个 `workspace/projects/<id>/` 到新机器的对应目录，重启服务即可。只迁移成果时，至少复制 `products/` 和 `project.json`；要继续处理，还必须复制 `data/` 和 `interferograms/`。删除项目会删除整个目录，不可恢复。

**GRD 能直接导入吗？**

不能。GRD 是已经检波的强度产品，相位在聚焦和检波过程中已经丢失；它的网格、几何和 SLC 也不同。工作台需要复数 SLC 才能形成干涉。请从原始 SLC 开始，先在 SNAP/ISCE 中完成配准，再导入配准后的 SLC 栈。

**干涉图、解缠相位或现成的形变产品能导入吗？**

不支持。工作台需要每景 SLC 的相位，才能自己构造网络、去地形、解缠和反演。干涉图缺少每景绝对相位，解缠相位带有任意 `2π` 整数和参考点，形变产品已经经过外部校正，无法再和工作台的参数对齐。只有干涉产品时，请使用 StaMPS、MintPy、GMTSAR 等工具；本工具只从 SLC 栈生成这些产品。

**为什么单景 GeoTIFF 或 ENVI 导入失败？**

工作台至少要 2 景才能建立干涉网络，这是所有路线的绝对下限。单景 `.tif`、`.tiff` 或 ENVI 文件会被读成 1 景并被拒绝。此外，PS-InSAR 和 SBAS-InSAR 至少需要 8 景，DS-InSAR 至少需要 10 景；影像数不足时，导入、切换路线和启动全流程都会在开始处理前报错。请把多景复数影像放在同一目录，文件名包含日期，再导入目录；或者打包成 `.npz`/原生目录。影像数不够时先补数据，或改用影像数要求更低的 D-InSAR。

**为什么导入 5 景后切到 PS/SBAS/DS 会被拒绝？**

技术路线的最少影像数由 `config.py` 的 `TECHNIQUES` 统一声明并强制校验：D-InSAR 2 景、PS 8 景、SBAS 8 景、DS 10 景。5 景足够做 D-InSAR 的快速差分，但不足以支撑稳定时序反演，因此工作台会在导入、路线切换和运行入口直接拒绝，而不是跑到反演阶段才失败。补充影像后重新导入，或先保持 D-InSAR 路线。

**Sentinel-1 SAFE 导入后为什么基线全是 0？**

SAFE 入口是实验性的，只读取 `measurement` 下的 TIFF，不拼接 burst，也不做 TOPS 配准。它会读取 `annotation` 中的首行时间和几何；如果目录或其父目录有 Sentinel-1 `.EOF`，且每景都能匹配到成像时间，就会估计 `bperp_m`。没有轨道文件时基线仍为 0，地形相位和 DEM 误差估计不可用。生产级 TOPS 数据请先在 SNAP/ISCE 完成 burst 拼接、去斜和配准，再导出 SLC 栈；也可以把本地 EOF 放在数据目录旁，让导入器估计基线。

**其他传感器怎么设置波长和入射角？**

在 `meta.json` 或 `.npz` 的 `meta` 中提供 `wavelength_m`、`incidence_deg`、`range_spacing_m`、`azimuth_spacing_m`、`slant_range_m` 和 `bperp_m`。不提供时程序会使用 Sentinel-1 默认值继续跑，结果可能只是“能出图”，量级不可解释。换波段时尤其要改波长，否则位移会成比例错误。

**`bperp_m` 全为 0 会怎样？**

地形相位按零基线计算，相当于不去地形；DEM 误差估计不可用；`max_perpendicular_baseline` 对所有日期对都满足，网络可能变得过多。此时应手动控制 `max_pairs`，并在结果解释中明确说明没有地形改正。SBAS 仍可跑，但不能把它当成完整差分干涉。

**日期缺失、重复或乱序怎么处理？**

缺失日期会按 12 天间隔补齐并警告；补齐的日期不是真实观测日期，交付时要说明。重复日期会直接报错。乱序会自动按日期升序重排，并同步重映射 `bperp_m` 和 `ref_index`。如果日期完全无法从 `meta` 或文件名提取，会从 `2023-01-01` 起按 12 天补齐，这通常不是你想要的时间轴。

**DEM 尺寸或投影不一致怎么办？**

尺寸不一致会按数组形状重采样并警告；但工作台不按地理坐标重投影 DEM。如果 DEM 的范围、投影或垂直基准与 SLC 不一致，重采样不能修复，必须先在地理信息软件中对齐到 SLC 网格。常数 DEM 会警告“地形相位将为零”；没有 DEM 时地形相位为零，DEM 误差估计关闭。

**导入振幅图后位移为什么全是 0？**

实数振幅/强度图没有相位，导入器会把它转成零相位复数。两景零相位相减，干涉相位恒为 0，解缠和位移也为 0。这种数据只能做界面和流程演示，不能用于形变分析。

**GACOS 少一天为什么会直接报错？**

GACOS 校正要求项目中的每个日期都有对应延迟屏幕，缺一个就无法对涉及该日期的干涉对做一致改正。先在官方 GACOS 面板查看“缺失日期”，再补导对应日期产品；补齐后确认覆盖率为 100%，然后重跑大气。也可以改用 `atmosphere_method=off` / `empirical`。不要用相邻日期强行代替，除非你明确接受时间错配。

**申请提交成功但一直没收到邮件怎么办？**

官方是异步处理，通常数分钟到数小时，服务器约保留产品 72 小时。先检查垃圾邮件和邮箱拦截规则，确认申请时填写的邮箱拼写正确；超过一天仍未收到时可以重新申请。若页面返回官方服务错误文本，可能是表单或服务改版，先点面板里的「打开官网」手动提交，再把邮件链接或附件导入项目。

**导入邮件链接或上传失败怎么办？**

先确认下载链接是完整的公网 `http/https` 地址，签名链接过期后需要重新申请或从邮件重新复制。系统会拒绝私网、回环地址、路径穿越、符号链接和异常压缩包；单个上传上限 512 MiB，超过时请分次上传。若链接被拦截，可以先用浏览器下载 tar.gz，再用「上传 tar.gz / 产品文件」导入。

**掩膜不合适怎么替换？**

在导入前准备 `mask.npy` 或 `mask.tif`，布尔值或 0/1，形状与 SLC 一致；也可以放在原生目录或 `.npz` 的 `mask` 键里。当前界面不提供交互式掩膜编辑。替换后重新导入会清理干涉、大气和反演成果，需要重跑下游。

**双波段 I/Q GeoTIFF 为什么读不进来？**

当前读取器只识别最后一维为 2 的排列，即 `(rows, cols, 2)`。如果导出是 `(2, rows, cols)`，请先转置，或直接导出单波段复数 GeoTIFF。多波段、多页 TIFF 也不会自动按日期展开。

### 8.3 处理与结果

**速率图方向为什么和别的软件相反？**

本工具约定 LOS 正值朝向卫星（抬升/靠近卫星为正）。不同软件的符号约定可能相反，比较前先确认参考像元和符号。

**速率图出现大面积条纹怎么办？**

检查配准、去斜、DEM 和轨道 ramp。可以先尝试 `remove_ramp=true`，但注意它会移除真实长波形变。若条纹与地形相关，检查 DEM 和 `bperp_m`。

**形变被“抹平”怎么办？**

降低 `regularization`，把 `aps_iterations` 设为 `0` 或 `aps_method=off`，谨慎使用 `remove_ramp`，检查 `estimate_dem_error` 是否吸收了长波信号。

**相位跳变/解缠错误怎么办？**

提高 `unwrap_coherence_min`，换 Goldstein 或 NL-Means，检查配准和 burst 拼接；减小多视会增加噪声，通常不是首选。不要用强滤波掩盖解缠错误。

**为什么成果页没有真值校验？**

真值校验只对合成演示项目有效。真实数据没有真值，页面会提示不可用。

**GeoTIFF 为什么不能直接叠加到地图？**

先检查项目是否满足地理编码条件。雷达网格产品只表示处理网格；只有在导入时找到参考轨道，并且 `start_times`、`azimuth_time_interval`、`range_spacing_m`、`slant_range_time_s` 或显式 `slant_range_m` 齐全时，反演后才会在 `products/geotiff/geo/` 下生成地图坐标版本。若 `products/geocode.json` 的 `status` 是 `unavailable` 或 `failed`，按 `reasons` 补齐元数据后重跑反演；本工具不做严格正射校正和投影变换，需要更高精度时仍应在 SNAP/ISCE/GDAL 等工具中处理。

**ZIP 太大怎么办？**

优先选择“成果包（精简）”，它只打包 `project.json` 和 `products/`，通常比完整包小一个数量级。只需要图件时，直接取 `products/figures/` 和 `products/report/`；需要让别人复现时再选“完整包”，或单独提供 `data/stack/`、`data/network.json`、`data/processed/coreg.json`、`data/atmosphere/` 和 `interferograms/`。导出弹窗会先显示两种模式的未压缩体积和文件数，便于判断。

### 8.4 性能、并发与安全

**可以多人同时用吗？**

当前版本不建议。服务是单进程 threaded WSGI，作业在线程中执行；压力测试显示 4 个作业并行效率只有 `0.334`，8 个作业没有吞吐收益；16 线程 API 压测总 p95 为 `11.31 s`，其中 `/api/projects` 端点 p95 达到 `11.96 s`。全局同时执行的作业数默认限制为 2，超出的作业保持 `queued` 排队，可用 `INSAR_MAX_CONCURRENT_JOBS` 在 1–32 之间调整。多人使用仍应改为进程级 worker 或独立作业进程，并加项目锁。

**可以长时间挂着跑吗？**

30 轮长稳测试显示 RSS 从 `165.0 MB` 涨到 `272.1 MB`，句柄从 `671` 涨到 `1050`。当前版本没有证明 8 小时连续运行无漂移；长时间运行时应监控内存和句柄，定期重启，并先修复资源释放问题。作业记录会在内存和磁盘上各保留最近 300 条，活跃作业不会被裁剪。

**请求体有大小限制吗？**

有。JSON 请求体默认上限 4 MiB，超过返回 413；可用 `INSAR_MAX_JSON_BYTES` 调整（支持 `K/M/G/T` 后缀）。错误 `Content-Type` 返回 415，坏 JSON 或非对象 JSON 返回 400。GACOS 官方产品的 multipart 上传另有 512 MiB 上限。页面和 API 已启用 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy` 和 CSP，API 响应不缓存；但这些响应头不能替代认证。

**可以把服务暴露到局域网或公网吗？**

不要。默认只监听 `127.0.0.1`，没有登录、权限、CSRF、TLS 和速率限制。虽然已启用 CSP 和基础安全响应头，但任何能访问端口的人仍然可以创建、修改、删除项目，读取项目内任意文件。远程访问请用 SSH 隧道或带认证的反向代理，并自行加访问控制。

**GACOS 令牌会保存吗？**

`project.json`、引擎摘要、作业记录、报告和 ZIP 都会过滤或脱敏敏感字段：`project.json` 直接删除凭据键，其余 JSON 将凭据值替换为 `***`。因此处理真实凭据后不需要手工清理 `interferograms/summary.json`；但请求体、浏览器开发者工具和代理日志仍可能看到明文，建议使用本地 GACOS 或一次性会话输入令牌。

**项目目录里不要放什么？**

不要放私钥、口令文件、与处理无关的敏感资料。`/api/projects/<id>/asset/<path>` 和 `/api/projects/<id>/download/<path>` 可以读取项目目录内的任意文件；这是本地单用户工具的设计取舍，不是多租户隔离。

**删除项目能恢复吗？**

不能。删除会移除整个项目目录。请先备份 `workspace/projects/<id>/`，或导出 ZIP。

### 9.8 如果已经误传了敏感信息

1. **先轮换凭据**：删除或重置 token、密码、密钥。只要推送过，就应视为已泄露。
2. 从当前提交删除文件：

```powershell
git rm --cached path\to\secret.json
git commit -m "Remove sensitive file"
git push
```

3. 历史仍然保留旧内容，需要重写历史：

```powershell
# 安装 git-filter-repo 后
git filter-repo --path path/to/secret.json --invert-paths
git push --force --all
git push --force --tags
```

4. 通知协作者重新克隆；强制推送会改变历史。
5. 如果仓库已经公开，联系 GitHub Support 请求清理缓存，并检查 fork。
6. 之后加 secret scanning、pre-commit hook 和 CI 检查，避免再次发生。

`git rm --cached` 只影响下一次提交，不会清除历史；不要以为删掉文件就安全了。

- **先私有后公开**：先推私有仓库，检查文件列表、体积、secret scanning，再切换 Public。

- **大文件**：不要用 Git LFS 存运行数据；演示数据用代码生成，真实数据让用户自行下载。
