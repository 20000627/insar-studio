## 0. 文档约定

- 文中的 `python` 指当前使用的 Python 3.9–3.11 解释器。Windows 上如果同时装了多个版本，建议显式写成 `py -3.11` 或解释器绝对路径。
- 文中的 `D:\path\to\insar-studio` 是示例项目目录，实际使用时替换成自己的路径。
- “演示数据”指软件内置的确定性合成数据；“真实数据”指用户导入的 SLS、SLC 栈、DEM 或 GACOS 产品。
- 参数名使用代码中的下划线形式，例如 `max_temporal_baseline`；界面上的中文标签放在括号里。
- 文中所有耗时、内存和精度数字都来自本机合成数据测试，只用于判断量级，不是对真实数据的精度承诺。

## 1. 项目简介与适用场景

### 1.1 这是什么

InSAR Studio 是一个完全本地运行的 InSAR 时序形变处理工作台。它把数据接入、五个处理阶段（配准、网络、干涉、大气、反演）和成果输出串成一条可复现的处理链：

```text
数据接入 → 配准 → 干涉网络 → 差分干涉 → 大气校正 → 时序反演 → 成果输出
```

软件提供中文分步向导，默认参数可以直接跑完演示项目；专家模式可以调整基线、滤波、解缠、反演和 PS/DS 的关键参数。所有项目、数组、图件、报告和导出包都保存在本地 `workspace/` 下，不依赖数据库、消息队列或云服务。

### 1.2 四条技术路线

| 路线 | 处理方式 | 适用场景 | 默认网络 | 主要输出 |
| --- | --- | --- | --- | --- |
| **SBAS-InSAR** | 小基线集 + 加权最小二乘 + 时间正则 | 区域沉降、滑坡、城市形变，默认推荐 | 最大时间基线 72 天 | 时序位移、速率、相干性、残差 |
| **PS-InSAR** | 单主影像星形 + 相邻对闭环，按 ADI 和相干性选点 | 城市建筑、桥梁、裸岩、强散射点 | 全星形 + 相邻对；关闭全星形后受 96 天时间基线限制 | PS 候选点、时序位移、速率 |
| **DS-InSAR** | 局部相干矩阵 + 特征分解相位链接，再联合解算 | 植被、农田、裸土等低相干区 | 小基线集，最大时间基线 72 天 | DS 相干性、时序位移、速率 |
| **D-InSAR** | 单干涉对差分，解缠相位直接转 LOS 位移 | 同震、突发滑坡、应急踏勘 | 单对，默认第 `n//3` 景与最后一景 | 单帧位移、相干性、缠绕相位 |

四条路线共用同一套配准、干涉、滤波、解缠和成果输出代码。路线差异主要在网络构造、PS 选点、DS 相位链接和反演输入。

### 1.3 适合什么场景

| 场景 | 推荐路线 | 说明 |
| --- | --- | --- |
| 第一次接触 InSAR，想理解完整链路 | SBAS | 演示项目默认路线，网络稳健，结果容易解读 |
| 城市建筑、桥梁、岩石裸露区的点目标监测 | PS | 强散射点保留，适合做毫米级变化趋势的算法验证 |
| 植被、农田、裸土等低相干区 | DS | 相位链接可以提升低相干区的覆盖，但计算量更大 |
| 同震、滑坡、单次事件的快速差分 | D-InSAR | 单对最快，适合快速查看空间形态 |
| 教学、课程设计、算法回归 | 任意路线 | 合成数据有真值，可量化检查链路 |
| 离线环境、数据不能出本机 | 任意路线 | 软件默认只监听 `127.0.0.1`，可完全离线运行 |

### 1.4 不适合什么场景

- 不作为生产级、计量认证的形变监测系统。
- 不执行 Sentinel-1 burst 级 TOPS 配准、去斜、拼接和精密轨道处理；真实 TOPS 数据应先在 SNAP、ISCE 或 Gamma 中预处理。
- 不做地理编码、正射校正、地图投影重采样；输出的 GeoTIFF 仍是处理网格，不是自动配准到地图坐标的产品。
- 不做升轨/降轨联合分解、方位向/距离向分解、GNSS 或水准融合。
- 不做断层滑动反演、震源参数反演、角反射器识别。
- 不提供用户认证、权限隔离、审计日志和多租户能力；不要直接暴露到公网。
- 不保证在线 GACOS、Copernicus Data Space、ASF 等外部服务的长期可用性。

### 1.5 实测性能与容量边界

以下数字来自本机 `Intel 16 逻辑核 / 15.7 GB RAM / Windows` 的合成数据压力测试，使用的是独立 `stress/workspace`，不是真实 SLC：

| 项目 | 实测结果 | 使用含义 |
| --- | --- | --- |
| 演示 SBAS 全流程 B0 | `18.96 s` | 单用户交互式处理可以接受 |
| 基准四路线 | SBAS `23.11 s`、PS `47.18 s`、DS `24.38 s`、D-InSAR `4.15 s` | 路线耗时差异主要来自网络对数和 PS/DS 计算 |
| 4 个作业并发 | 单作业中位 `56.61 s`，并行效率 `0.334` | 进程内线程并发几乎没有吞吐收益 |
| 8 个作业并发 | 小数据单作业中位 `100.56 s`，为小数据单实例 `12.13 s` 的 `8.29×` | 不建议把 8 个作业同时提交 |
| 16 线程 API 压测 | 总 p95 `11.31 s`；`/api/projects` 端点 p95 `11.96 s` | 项目列表全量扫描是主要瓶颈 |
| 204 个项目列表 | p95 `1.71 s` | 项目越多，列表越慢 |
| 30 轮长稳 | RSS `165.0 → 272.1 MB`，句柄 `671 → 1050` | 长时间运行需要关注资源增长 |
| 48×440×520 合成规模 | 完成 `102.9 s`，峰值 RSS `702.0 MB` | 单进程内存可控制在 1 GB 以内，但真实数据需更高余量 |

结论：当前版本适合单用户、单机、串行或最多 2 个轻量作业的使用方式。需要多用户并发时，应先改造成进程级 worker 或独立作业进程，不能直接把当前 Flask 单进程服务当多人服务使用。完整测试方法和数据见 `stress/results/report.md`。

## 2. 安装与环境准备

### 2.1 系统要求

| 项目 | 最低 | 推荐 |
| --- | --- | --- |
| 操作系统 | Windows 10/11、Linux、macOS | Windows 10/11 或 Ubuntu 22.04 |
| Python | 3.9，64 位 | 3.11，64 位 |
| 内存 | 4 GB 可用 | 8 GB 以上；真实大栈 16 GB 以上 |
| CPU | 2 核 | 4 核以上 |
| 磁盘 | 2 GB 程序 + 数据空间 | 20 GB 以上，另加原始数据和成果空间 |
| 浏览器 | 现代 Chrome、Edge、Firefox | Chrome 或 Edge |
| GPU | 不需要 | 不需要 |

首次安装依赖需要联网；依赖装好后可以离线运行。软件不会自动上传数据，但在线 GACOS、Sentinel-1 下载等功能会访问外部服务。

### 2.2 Windows 一键启动

1. 安装 Python 3.9–3.11 64 位（推荐 3.11），安装时勾选 “Add python.exe to PATH”。`start.bat` 会优先使用 `py`/PATH 里的最新解释器；如果本机同时装了 3.12 或 3.13，建议先按 2.3 节用 3.11 建虚拟环境，避免依赖轮子不兼容。
2. 双击项目根目录的 `start.bat`。
3. 脚本会通过 `scripts/bootstrap.py` 检查依赖；缺失时自动创建项目内 `.venv` 并安装 `requirements.txt`，只需一次。
4. 服务默认从 `8765` 起自动选择空闲端口，并自动打开浏览器；终端会打印实际地址。
5. 保持命令行窗口打开。关闭窗口或按 `Ctrl+C` 停止服务。

如果依赖安装失败，先看窗口里的错误，再执行：

```powershell
cd D:\path\to\insar-studio
python -m insar_studio doctor
```

### 2.3 手动安装

Windows PowerShell：

```powershell
cd D:\path\to\insar-studio

# 可选：创建独立环境
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
python -m pip install -r requirements.txt

# 自检
python -m insar_studio doctor

# 启动并自动打开浏览器
python -m insar_studio serve --open
```

如果 PowerShell 阻止激活脚本，可以改用：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m insar_studio serve --open
```

Linux / macOS：

```bash
cd /path/to/insar-studio
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m insar_studio doctor
python -m insar_studio serve --open
```

也可以直接运行：

```bash
bash start.sh
```

### 2.4 使用 conda

如果本机已经有 conda，建议单独建环境，避免和系统 Python 的 NumPy/SciPy 冲突：

conda activate insar

### 2.6 环境变量

| 变量 | 默认值 | 作用 | 注意 |
| --- | --- | --- | --- |
| `INSAR_STUDIO_WORKSPACE` | `<repo>/workspace` | 指定工作区根目录 | 在 `config.py` 导入时读取，必须在启动进程前设置 |
| `INSAR_STUDIO_HOST` | `127.0.0.1` | 监听地址 | 只对直接调用 `server.main()` 生效；CLI 会传 `--host`，请用 `--host 0.0.0.0` 显式指定。暴露到局域网前先加认证 |
| `INSAR_STUDIO_PORT` | `8765` | 起始端口 | 只对直接调用 `server.main()` 生效；CLI 默认传 `--port 8765`，请用 `--port` 指定。`0` 表示系统分配 |
| `INSAR_STUDIO_DEBUG` | `0` | 开启 Flask 调试 | 调试模式的 500 响应会带 traceback，不要共享开启 |
| `INSAR_STUDIO_OPEN` | `0` | 启动后打开浏览器 | 等价于 `--open` |
| `INSAR_STUDIO_STRICT_PORT` | `0` | 端口占用直接失败 | 否则从起始端口向后尝试 29 个端口 |

`INSAR_STUDIO_DEBUG`、`INSAR_STUDIO_OPEN`、`INSAR_STUDIO_STRICT_PORT` 在 `python -m insar_studio serve` 下仍会生效；`INSAR_STUDIO_HOST/PORT` 会被 CLI 的默认参数覆盖。

仓库根目录提供了 `.env.example` 作为变量清单。程序**不会自动加载** `.env`，需要先把变量导入当前 shell，或在系统环境变量中设置；真实的 `.env` 已被 `.gitignore` 忽略，不要提交。

示例：把工作区放到 D 盘独立目录，避免备份时把程序和数据混在一起。

```powershell
$env:INSAR_STUDIO_WORKSPACE = "D:\insar_workspace"
python -m insar_studio serve --open
```

### 2.7 可选组件 SNAPHU

默认解缠算法是内置质量引导，不安装 SNAPHU 也能完整跑通。需要对比 SNAPHU 时：

1. 安装 SNAPHU，确保 `snaphu` 在 `PATH` 中，或在参数里设置 `snaphu_exe` 的绝对路径。
2. 运行 `python -m insar_studio doctor`，确认 SNAPHU 检查项为可用。
3. 在干涉步骤把解缠算法切到 SNAPHU。若调用失败，程序会自动回退质量引导，并在 `unwrap_info` 中记录原因。

### 2.8 工作区与升级

- 默认工作区是项目根目录下的 `workspace/`，其中 `projects/` 保存项目，`jobs/` 保存作业，`cache/` 保存缓存，`logs/` 保存日志。
- 升级前先备份 `workspace/projects/`；项目目录可以整体复制到新机器。
- 升级后建议先跑 `python -m insar_studio doctor` 和 `python -m pytest -q`，再打开旧项目做一次项目体检。
- 删除项目会删除对应目录，且不可恢复；不要把唯一副本放在 `workspace/` 里。

## 3. 快速上手

### 3.1 五分钟跑通演示

1. 启动服务，浏览器打开终端打印的地址，例如 `http://127.0.0.1:8765`。
2. 左侧项目库选择任意演示项目；如果没有项目，点击欢迎页的“用演示数据跑一遍”。
3. 在顶部工具栏点击“一键跑完全流程”（切到“7 成果”也能看到同一个按钮）。
4. 观察右下任务控制台依次显示：配准 → 网络 → 干涉 → 大气 → 反演。
5. 完成后页面自动跳到成果页。重点看：
   - 速率中位数和（演示数据的）位移 RMSE；
   - 速率图、时序相干性图、残差图；
   - 任意像元的时间序列；
   - 报告和 ZIP 成果包。

演示数据的真值只用于算法回归，不能当作真实场景精度。演示项目的默认大气方法是“演示 GACOS”，它使用与合成数据一致的模拟大气，用来观察校正上限。

### 3.2 用命令行创建并运行演示

```powershell
cd D:\path\to\insar-studio

# 创建并运行 SBAS 演示
python -m insar_studio demo --name "我的 SBAS 演示" --technique sbas

# 只生成数据，不处理
python -m insar_studio demo --name "空演示" --technique ps --no-run

# 查看项目
python -m insar_studio projects

# 重跑已有项目（项目 ID 或名称）
python -m insar_studio run prj_xxxxxxxx_xxxxxx
python -m insar_studio run "我的 SBAS 演示"
```

`demo` 会创建项目并立即跑完整流程；`run` 会覆盖已有产品，但保留原始演示数据。

### 3.3 导入自己的最小数据栈

准备一个目录：

```text
my_stack/
  slc.npy          # complex64, (n_dates, rows, cols)，必需
  dem.npy          # float32, (rows, cols)，可选
  mask.npy         # bool, (rows, cols)，可选
  meta.json        # 日期、平台、基线等元数据，强烈建议
```

`meta.json` 最小示例：

```json
{
  "dates": ["2023-01-03", "2023-01-15", "2023-01-27"],
  "platform": "Sentinel-1A",
  "orbit_direction": "DESCENDING",
  "relative_orbit": 42,
  "bperp_m": [-35.2, 12.8, 64.1],
  "incidence_deg": 38.5,
  "range_spacing_m": 2.33,
  "azimuth_spacing_m": 13.97
}
```

操作步骤：

1. 点击左侧“+ 新建”，选择“导入本地数据”。
2. 填写数据目录或单个 `.npz` 文件路径，可选填 DEM。
3. 创建后进入“数据”页，核对日期、尺寸、掩膜和振幅预览。
4. 进入“网络”页生成网络；如果还没有配准，系统会先自动配准。
5. 依次运行干涉、大气、反演，或在成果页“一键跑完全流程”。

如果缺少 `bperp_m`，垂直基线会被置零，DEM 误差估计不可用；如果缺少 `dates`，会按 12 天间隔补齐。导入后务必核对日期顺序和尺寸。

### 3.4 第一次运行检查清单

- [ ] `python -m insar_studio doctor` 全部通过，或只有 SNAPHU 不可用。
- [ ] 浏览器能打开本地地址，左侧能看到演示项目。
- [ ] 演示 SBAS 全流程能完成，成果页有速率图。
- [ ] 任务控制台没有红色错误。
- [ ] 项目体检为 0 错误；警告项能解释。
- [ ] `workspace/projects/<id>/products/` 下有数组、图件和报告。
- [ ] 知道项目目录在哪里，已做一次备份。

## 4. 主要功能与用法

### 4.1 界面结构

| 区域 | 作用 |
| --- | --- |
| 左侧项目库 | 搜索、切换、新建、删除项目；显示路线、影像数和进度 |
| 顶部栏 | 引导/专家模式切换、帮助、环境自检、版本标识 |
| 项目标题区 | 数据源、时间范围、影像数、尺寸、项目体检、一键跑完 |
| 七步导航 | 项目 → 数据 → 网络 → 干涉 → 大气 → 反演 → 成果 |
| 中间内容区 | 当前步骤的指标、图件、参数和操作按钮 |
| 右下任务控制台 | 进度、阶段、日志；运行中自动展开 |

引导模式只显示常用参数，专家模式显示全部参数。切换模式不会改变已经保存的参数，只影响显示。

### 4.2 项目管理

支持三种创建方式：

- **演示项目**：选择 SBAS/PS/DS/D-InSAR，自动生成 24 景、220 × 260 像元的合成栈。
- **导入项目**：创建空项目后导入本地栈，适合真实数据。
- **空项目**：只创建项目骨架，稍后再导入数据。

常用操作：

| 操作 | 说明 |
| --- | --- |
| 刷新 | 重新读取磁盘上的项目状态和产品 |
| 项目体检 | 只读检查数据、参数指纹、配准、网络、干涉、大气、反演、报告和磁盘空间 |
| 重置处理结果 | 清空干涉、大气、反演和导出成果，删除 `data/network.json` 和 DS 参考缓存；默认保留配准栈 |
| 重新校验 | 对演示数据重新计算真值指标 |
| 删除项目 | 删除整个项目目录，不可恢复 |

同一项目同一时间只允许一个处理任务。运行中重复提交会返回 HTTP 409；刷新页面后如果任务仍在运行，页面会自动重连。

切换技术路线时，系统会清理下游产品，并把这 6 个路由参数重置为新路线默认值：`multilook`、`max_temporal_baseline`、`max_pairs`、`ps_star_all`、`ds_patch`、`ds_overlap`。其他参数保留；如果不想让某个路由参数被重置，需要在同一次请求的 `params` 里显式传值。切换路线会导致重新配准、网络、干涉、大气和反演，耗时比单阶段重跑更长。

### 4.3 数据接入

#### 4.3.1 NumPy 目录

```text
my_stack/
  slc.npy
  dem.npy
  mask.npy
  meta.json
```

要求：

- `slc.npy`：`complex64`，形状 `(n_dates, rows, cols)`。
- `dem.npy`：`float32`，形状 `(rows, cols)`，单位米。
- `mask.npy`：`bool`，形状 `(rows, cols)`，`True` 为有效。
- `meta.json`：建议至少包含 `dates`；有 `bperp_m` 才能做 DEM 误差估计。

#### 4.3.2 `.npz` 打包

```text
stack.npz
  slc       # complex64, (n_dates, rows, cols)，必需
  dem       # float32, (rows, cols)，可选
  mask      # bool, (rows, cols)，可选
  dates     # 字符串数组，可选
  meta      # JSON 字符串，可选
```

`dates` 优先从数组读取，其次从 `meta["dates"]` 读取；导入时会按日期升序重排，并同步重映射 `bperp_m` 和 `ref_index`。

#### 4.3.3 其他格式

| 格式 | 说明 | 注意事项 |
| --- | --- | --- |
| ENVI 栈 | `.hdr` + 同名 `.dat/.img` | 复数数据必须是 `complex64`；行列、波段数要与头文件一致 |
| 复数 GeoTIFF 目录 | 每景一个文件，文件名含日期 | 所有影像必须同尺寸、同网格；不同尺寸会被裁到最小公共范围 |
| Sentinel-1 SAFE | 实验性支持单 swath、已配准的复数 int16 TIFF | 生产级 TOPS 数据请先在 SNAP/ISCE 完成 burst 拼接、去斜和配准 |
| GACOS 本地目录 | `.ztd + .rsc`、`.tif`、`.npy` | 文件名必须包含 `YYYYMMDD` 或 `YYYY-MM-DD` |

#### 4.3.4 数据质量检查

导入后至少确认：

1. 振幅图有纹理，不是全黑、全白或纯噪声。
2. 日期顺序正确，没有重复或意外缺失。
3. 掩膜保留主要陆地，水体和阴影被剔除。
4. 相邻日期干涉相位连续，没有整体跳变。
5. DEM 与 SLC 同网格、同单位。
6. `bperp_m` 的数量与日期数一致，量级合理。

### 4.4 网络构建

网络页负责把日期连成可解的观测图。系统会：

1. 检查 `data/processed/slc_coreg.npy`，不存在或配准参数指纹已变化时先自动配准。
2. 按路线生成干涉对。
3. 检查日期图是否连通，不连通时补一条时间桥。
4. 超过 `max_pairs` 时按短基线优先裁剪，同时保证每个日期至少出现一次；如果裁剪后连通性变差，则保留原网络，因此 `max_pairs` 是软上限。

网络页重点看四个指标：

| 指标 | 含义 | 经验判断 |
| --- | --- | --- |
| 干涉对数 | 实际保留的观测数 | 演示 SBAS 约 80 对；真实数据按需要调整 |
| 冗余度 | `n_pairs / (n_dates - 1)` | 3 以上较稳健；低于 2 要谨慎 |
| 最大时间基线 | 实际保留对的最大时间差 | 越小相干性越好，但连接越少 |
| 连通分量 | 日期图是否连通 | 必须是 1；大于 1 说明有日期无法求解 |

路线差异：

- **SBAS**：枚举所有满足时间/垂直基线阈值的日期对，补连通边，按短基线优先裁剪。
- **PS**：以参考影像为中心的星形，默认全星形，再补相邻日期对用于闭环。PS 星形边不受 `max_perpendicular_baseline` 限制；`max_pairs` 仍会限制总数。
- **DS**：与 SBAS 相同的小基线网络，相位链接在干涉/反演阶段完成。
- **D-InSAR**：只生成一对。界面选择主影像和从影像；API 中请使用长度为 2 的列表，例如 `[0, 23]`，不要依赖字符串形式。

### 4.5 干涉处理

干涉页把每一对相位变成可解的观测，并提供逐对浏览：

- 振幅；
- 缠绕相位；
- 滤波相位；
- 解缠相位；
- 相干性；
- 残差。

处理流程：

1. 复共轭相乘生成干涉相位。
2. 按 `multilook` 做复数多视。
3. 用 DEM 和垂直基线去地形相位。
4. 按 `coherence_window` 估计相干性。
5. 按 `filter` 做相位滤波。
6. 按 `min_coherence` 生成有效掩膜。
7. 按 `unwrap_method` 解缠，按 `unwrap_coherence_min` 控制解缠种子/有效像元。
8. 减去参考像元相位，按 `remove_ramp` 去除一个平面趋势。
9. 把解缠相位转换为 LOS 位移，单位毫米。

常用判断：

- 缠绕相位出现大面积条纹跳变：优先提高 `unwrap_coherence_min`、换 Goldstein，并检查配准和 burst 拼接；减小多视会增加噪声，通常不是首选。不要用强滤波掩盖解缠错误。
- 相干性整体偏低：检查配准、burst 拼接、时间去相干和植被覆盖。
- 相位全是噪声：先检查数据本身，再调参；调参无法修复未配准的 TOPS 数据。
- PS 路线应保持 `multilook = 1`，强滤波会削弱永久散射体。

### 4.6 大气校正

三种方法：

| 方法 | 数据要求 | 适用场景 | 注意事项 |
| --- | --- | --- | --- |
| GACOS | 演示、本地或在线逐日天顶延迟 | 有外部大气产品，想校正分层/湍流延迟 | 在线服务接口不统一，需自行确认地址和凭据 |
| 经验高程 | 不需要外部数据 | 地形起伏明显、无 GACOS | 过度校正会吃掉真实长波形变 |
| 不校正 | 无 | 先看原始结果，或反演阶段做时间高通 | 残余 APS 会进入时序，可能形成假趋势 |

GACOS 本地目录：

```text
gacos/
  20230103.ztd
  20230103.rsc
  20230115.ztd
  20230115.rsc
  ...
```

文件名必须包含日期。系统会递归查找 `.ztd`、`.tif/.tiff`、`.npy`，同一日期有多个匹配时取文件名最短的。

诊断图怎么看：

- 左侧逐日 APS 屏：空间纹理是否合理，量级是否异常。
- 中间相位分布：校正后应更集中。
- 右侧逐对散点：点应更靠近 1:1 线。

校正过度时，速率图可能出现大面积负相关纹理，或把真实长波形变当成大气扣掉。此时回退到“不校正”，或只用经验高程。

> **1.2.0 的已知安全薄弱点**：通过在线 GACOS 或单阶段接口传入的 `gacos_token`、`gacos_email` 等参数，可能被写入 `interferograms/summary.json`，并随 ZIP 导出。界面和 `project.json` 的过滤不能覆盖引擎摘要。处理真实凭据后，请检查并清理该文件，或优先使用本地 GACOS。详见第 6.4 节。

### 4.7 时序反演

四条路线的反演：

- **SBAS/DS**：对所有有效像元做加权最小二乘，加入二阶时间正则和稳健重加权，解算逐日位移和速率。
- **PS**：先按 ADI 和相干性选点，再只对 PS 点求解，并用 PS 权重加权。
- **D-InSAR**：取单对解缠相位直接转位移，不生成速率。

反演页可以调整：

- 多视因子；
- 正则化权重；
- 是否去趋势面（`remove_ramp` 实际在干涉阶段作用于解缠相位；在反演页修改后，需要重跑干涉阶段才生效）；
- 是否估计 DEM 误差；
- 稳健迭代次数；
- APS 方法、空间尺度和迭代次数；
- 参考像元模式（自动/手动）；
- PS 的 ADI 和相干性阈值；
- DS 的块大小、重叠率和相位链接方法（后两者在当前版本不改变结果）。

结果摘要会显示有效像元、时序相干性、残差、参考像元和干涉对信息。反演完成后自动进入成果页。

### 4.8 成果与交付

成果页包括：

| 内容 | 说明 |
| --- | --- |
| 评价卡 | 路线、参考像元、速率/位移中位数、演示数据 RMSE、空间相关 |
| 统计卡 | 有效像元比例、时序相干性、残差、成果文件数 |
| 主图 | 速率/位移、相干性、残差、DEM 误差、大气、网络、配准增益 |
| 像元时间序列 | 输入行列查询，或跳到形变峰值/参考点 |

报告只读项目文件，不重新计算。若反演后没有生成报告，成果页会提示“尚未生成报告”，项目体检给 info 而不是错误。

演示数据的真值分级：

| --- | --- |

这些阈值只用于合成数据回归，不代表真实数据精度。

### 4.10 HTTP API 自动化

服务启动后，所有接口都在 `/api/` 下。常用接口：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/health` | 进程存活、版本、工作区 |
| `GET` | `/api/capabilities` | 路线、格式、默认参数、SNAPHU 可用性 |
| `POST` | `/api/projects` | 创建演示/导入/空项目 |
| `GET` | `/api/projects/<id>` | 项目概览 |
| `POST` | `/api/projects/<id>/run` | 提交全流程作业，返回 202 |
| `POST` | `/api/projects/<id>/network` | 只跑网络阶段 |
| `POST` | `/api/projects/<id>/interferometry` | 只跑干涉阶段 |
| `POST` | `/api/projects/<id>/atmosphere` | 只跑大气阶段 |
| `POST` | `/api/projects/<id>/inversion` | 只跑反演阶段 |
| `GET` | `/api/jobs/<job_id>` | 查询作业状态和进度 |
| `GET` | `/api/projects/<id>/results` | 成果总览 |
| `GET` | `/api/projects/<id>/series?row=&col=` | 单像元时间序列 |
| `POST` | `/api/projects/<id>/report` | 生成 Markdown + DOCX |
| `GET` | `/api/projects/<id>/export` | 下载 ZIP 成果包 |

Python 示例：创建演示项目、提交全流程、轮询作业、下载 ZIP。

```python
import time
from pathlib import Path

import requests

BASE = "http://127.0.0.1:8765"

with requests.Session() as s:
    # 1. 创建演示项目
    r = s.post(
        f"{BASE}/api/projects",
        json={"name": "API 演示", "technique": "sbas", "source": "demo"},
        timeout=60,
    )
    r.raise_for_status()
    project = r.json()["project"]
    project_id = project["id"]
    print("project:", project_id)

    # 2. 提交全流程
    r = s.post(
        f"{BASE}/api/projects/{project_id}/run",
        json={"technique": "sbas", "params": {"multilook": 2, "max_pairs": 80}},
        timeout=30,
    )
    r.raise_for_status()
    job = r.json()["job"]
    job_id = job["id"]
    print("job:", job_id)

    # 3. 轮询作业
    while True:
        r = s.get(f"{BASE}/api/jobs/{job_id}", timeout=30)
        r.raise_for_status()
        state = r.json()
        print(state.get("status"), state.get("progress"), state.get("message", ""))
        if state.get("status") in {"done", "failed", "cancelled", "interrupted"}:
            break
        time.sleep(1)

    if state.get("status") != "done":
        raise SystemExit(f"job ended with {state.get('status')}: {state.get('error')}")

    # 4. 下载 ZIP
    r = s.get(f"{BASE}/api/projects/{project_id}/export", timeout=300)
    r.raise_for_status()
    out = Path(f"{project_id}.zip")
    out.write_bytes(r.content)
    print("zip:", out.resolve(), len(r.content), "bytes")
```

创建导入项目时，把 `source` 改成 `"import"`，并增加 `path` 和可选的 `dem_path`：

```python
r = s.post(
    f"{BASE}/api/projects",
    json={
        "name": "我的数据",
        "technique": "sbas",
        "source": "import",
        "path": r"D:\data\my_stack",
        "dem_path": r"D:\data\dem.tif",
    },
    timeout=300,
)
```

注意：

- 作业提交成功返回 202，不是同步完成；必须轮询 `/api/jobs/<job_id>`。
- 同一项目已有活跃作业时，提交返回 409；不要重复提交。
- 取消是协作式的，能在下一次进度检查时停止；单个长时间 NumPy/SciPy 调用或外部进程不会立即被打断。
- API 没有版本前缀，升级后先看 `/api/capabilities` 的版本和参数。

## 5. 参数详解与调参建议

### 5.1 参数如何生效

- 运行时参数 = 引擎默认值 + 项目已保存参数 + 本次请求参数。项目参数会过滤敏感字段，但引擎摘要可能保留原始参数（见 4.6 的安全提示）。
- 每个阶段有参数指纹。修改了某阶段相关参数但没有重跑，项目体检会提示“参数待重跑”。
- 切换技术路线会重置 6 个路由参数（`multilook`、`max_temporal_baseline`、`max_pairs`、`ps_star_all`、`ds_patch`、`ds_overlap`）为新路线默认值；其他参数保留。要在切换时保留某个路由参数，必须在同一次请求里显式传值。
- 参数校验在 `insar_studio/params.py` 中完成。未知参数会保留，`params.py` 中登记的已知参数会做类型和范围检查。
- 界面只暴露一部分参数；API、配置文件或导入项目可以包含更多自由参数。

### 5.2 四条路线的默认值

| 参数 | SBAS | PS | DS | D-InSAR |
| --- | ---: | ---: | ---: | ---: |
| `multilook` | 2 | 1 | 2 | 2 |
| `max_temporal_baseline` | 72 | 96 | 72 | 不适用 |
| `max_pairs` | 80 | 140 | 80 | 80（D-InSAR 固定 1 对，不使用该上限） |
| `ps_star_all` | false | true | false | false |
| `ds_patch` | 9 | 9 | 9 | 9 |
| `remove_ramp` | true | true | true | true |

未列出的参数使用下文的共享默认值。默认值针对演示数据调过，真实数据应从默认值开始，一次只改一类参数。

### 5.3 网络参数

| 参数 | 默认 | 引擎允许范围 | 作用与影响 | 推荐起点 |
| --- | ---: | --- | --- | --- |
| `max_temporal_baseline` | 72 天 | 6–730 | 调大：对数多、覆盖好，但时间去相干增加；调小：相干性好，但对数少、可能不连通 | 一般 48–96；植被/快速形变 24–60；稳定城区 72–120 |
| `max_perpendicular_baseline` | 180 m | 5–3000 | 调大：对数多，但 DEM 误差和相位模糊更敏感；调小：对 DEM 误差不敏感，但对数少 | 一般 120–200；地形起伏大 80–120；平坦且 DEM 可靠 200–300 |
| `max_pairs` | 80 | 1–1000 | 控制计算量和冗余度；是软上限，为保证连通性可能被突破 | SBAS/DS 60–100；PS 120–160；资源有限 40–60 |
| `ref_index` | 0 | 0–1000000 | 参考影像索引；影响配准和网络参考。应选时间居中、质量好的影像 | 默认 0 可用；长时序选中间日期或超级主影像 |
| `ps_star_all` | PS 为 true | 布尔 | PS 全星形：所有影像连到参考影像；关闭后只保留时间基线内的星形边，再补相邻对 | 小数据保留 true；大数据可 false 以控制对数 |
| `dinsar_pair` | null | 两个日期索引 | D-InSAR 指定主/从影像；API 用 `[ref, sec]`，字符串 `"00_05"` 通常不会改变网络 | 应急时明确指定 `[ref, sec]` |

补充：

- PS 的全星形边不检查 `max_perpendicular_baseline`；该参数主要影响 SBAS/DS。
- `max_pairs` 裁剪会优先保留短时间基线、短垂直基线的对；如果裁剪后日期图连通分量变多，代码会放弃裁剪，因此实际对数可能大于设定值。
- 修改 `ref_index` 会触发配准和网络重跑，成本较高。

### 5.4 干涉与解缠参数

| 参数 | 默认 | 引擎允许范围 | 作用与影响 | 推荐起点 |
| --- | ---: | --- | --- | --- |
| `multilook` | 2 | 1–8 | 调大：噪声低、分辨率低、计算快；调小：保留细节，但噪声大 | PS 1；一般 2；低相干/大区域 4；8 仅踏勘 |
| `coherence_window` | 5 | 3–31，奇数 | 相干性估计窗口；调大更平滑但空间分辨率下降 | 3–5 城区；5–7 一般；7–9 低相干 |
| `filter` | boxcar | boxcar / goldstein / gaussian（gauss）/ nlmeans（nl-means、nlm）/ none | Boxcar 稳健；Goldstein 保频谱峰；高斯更平滑；NL-Means 保边但慢 | 默认 boxcar；噪声大 goldstein；保边 nlmeans；对比时 none |
| `boxcar_size` | 3 | 1–31，奇数 | Boxcar 窗口；调大更平滑，过大糊掉细节 | 3–5；低相干 5–7；PS 保持 3 或更小 |
| `goldstein_alpha` | 0.65 | 0–1.5 | Goldstein 强度；越大抑制越强 | 0.5–0.8；弱噪声 0.4–0.6；强噪声 0.7–0.9 |
| `goldstein_patch` | 32 | 8–128 | Goldstein 分块大小；越大越全局，越小越局部 | 24–64；小图 16–32；大图 64–96 |
| `gaussian_sigma` | 2.0 | 0.3–12 | 高斯低通尺度；越大越平滑 | 1–3；强噪声 3–5；不建议超过 6 |
| `unwrap_method` | quality | quality / snaphu / skimage（least-squares） | 质量引导稳健；SNAPHU 需安装；最小二乘适合连续低噪声相位 | 默认 quality；有 SNAPHU 可对比；连续低噪声用 skimage |
| `unwrap_coherence_min` | 0.18 | 0–0.99 | 解缠时使用的相干性下限；调高减少错误但增加空洞 | 0.15–0.25 一般；0.25–0.35 噪声大；0.10–0.18 高相干 |
| `min_coherence` | 0.25 | 0–0.99 | 有效像元掩膜阈值；调高结果干净但覆盖少 | 0.20–0.30 一般；0.30–0.45 噪声大；0.15–0.20 高相干 |
| `remove_ramp` | true | 布尔 | 解缠后减去一个平面趋势；会同时移除同尺度的真实长波形变 | 首次处理 true；研究宽尺度形变时 false |
| `snaphu_exe` | `snaphu` | 字符串，最长 260 | 指定 SNAPHU 可执行文件；找不到时自动回退质量引导 | 一般不用填；多版本环境填绝对路径 |

注意：

- `remove_ramp` 在当前实现中只拟合一个平面，不是二次趋势。“线性/二次趋势面”的界面文案应按“平面趋势”理解。
- `min_coherence` 和 `unwrap_coherence_min` 不是同一个阈值。前者控制最终有效像元，后者控制解缠阶段。
- 滤波只影响缠绕相位和解缠输入，不会改变原始复数干涉图。
- 多视因子会影响后续所有阶段的网格；修改后必须重跑干涉及下游。

### 5.9 常见场景的参数组合

下面的组合是“起点”，不是固定答案。每次只改一类参数，重跑后比较相干性、残差、有效像元和速率图。

| 场景 | 关键设置 | 说明 |
| --- | --- | --- |
| 第一次跑通 / 区域沉降 | 全部默认；SBAS；`multilook=2`；`remove_ramp=true` | 先用默认值建立基线，再决定是否调参 |
| 植被、农田、低相干 | `multilook=4`；`max_temporal_baseline=48–60`；`max_perpendicular_baseline=100–150`；`filter=goldstein`；`goldstein_alpha=0.6–0.8`；`unwrap_coherence_min=0.25–0.35`；`min_coherence=0.30–0.40`；`regularization=0.35–0.50` | 用多视和短基线换相干性，接受分辨率下降 |
| 城市 PS | `multilook=1`；`max_temporal_baseline=96`；`max_pairs=140`；`ps_adi_max=0.20–0.28`；`ps_coherence_min=0.60–0.70`；`filter=boxcar`；`boxcar_size=3` | 保持单视和点目标，不要用强滤波 |
| 植被 DS | `multilook=2`；`ds_patch=9–13`；`max_temporal_baseline=48–72`；`min_coherence=0.20–0.25`；`regularization=0.30–0.40` | DS 计算量大，先小范围验证 |
| 地形起伏大、无 GACOS | `atmosphere_method=empirical`；`empirical_order=1–2`；`max_perpendicular_baseline=80–120`；`estimate_dem_error=true`（仅时序足够长时） | 经验校正可能吃掉长波形变，务必对比校正前后 |
| 快速滑坡/强形变 | `max_temporal_baseline=24–48`；`multilook=2`；`unwrap_coherence_min=0.22–0.30`；`regularization=0.15–0.25` | 短基线保相干，低正则保留快速变化 |
| 大区域/算力有限 | `multilook=4`；`max_pairs=40–60`；`filter=boxcar`；`boxcar_size=5`；`unwrap_method=quality`；关闭不必要的 GACOS | 先降采样和减对数，再考虑分块处理 |
| 同震/应急 D-InSAR | 单对；`multilook=2–4`；`filter=goldstein`；`unwrap_coherence_min=0.20–0.30`；`remove_ramp=true` | 单对没有时间约束，必须结合外部信息解释 |
| 宽尺度长波形变 | `remove_ramp=false`；`regularization=0.05–0.15`；`aps_iterations=0–1`；谨慎使用经验高程 | 去趋势和强 APS 会移除真实长波信号 |

### 5.10 调参流程

建议按下面的顺序做，避免“一次改十个参数，不知道哪个起作用”：

1. **建立基线**：用默认参数跑一遍，保存 `summary`、速率图、残差图和项目体检结果。
2. **定位问题**：先判断是数据问题（未配准、低相干、DEM 不匹配）还是参数问题。数据问题不要靠调参解决。
3. **只改一类参数**：例如只调网络基线，或只调解缠阈值，不要同时改滤波、正则化和 APS。
4. **重跑受影响阶段**：网络变了要重跑干涉、大气、反演；只改反演参数可以只重跑反演。
5. **看四个指标**：有效像元比例、时序相干性、残差中位数、速率图空间形态。不要只看一张图。
6. **做对照**：保留上一版结果或截图，比较差异是否在预期方向。
7. **记录参数**：项目体检会提示参数指纹；交付时把关键参数写进报告或备注。
8. **不要过拟合演示数据**：演示数据的真值用于回归，不是真实场景的调参目标。

### 5.11 参数交互与常见误区

| 误区 | 后果 | 正确做法 |
| --- | --- | --- |
| 同时开强正则化和 DEM 误差估计 | 两者都吸收长波，速率被系统性低估 | 先关 DEM 误差，确认残差后再逐项开 |
| `aps_iterations` 调得很大 | 把真实形变当成 APS 扣掉 | 1–2 次；对比关闭前后的速率图 |
| `remove_ramp=true` 处理宽尺度形变 | 真实长波被平面趋势移除 | 研究宽尺度时关掉，或只在确认有轨道 ramp 时开 |
| `min_coherence` 和 `unwrap_coherence_min` 一起调得很高 | 有效像元大幅减少，反演覆盖不足 | 先调解缠阈值，再看有效像元 |
| PS 用 `multilook>1` | 点目标被多视平均掉 | PS 保持 1 |
| `filter` 用很强的高斯/Goldstein | 细节被抹平，PS 点减少 | 先轻滤波；PS 用 boxcar 3 |
| DS 路线下 `ds_patch` 填偶数 | 参数校验失败 | 只用奇数 |
| 改 `ds_overlap` 或 `ds_phase_linking` 期待结果变化 | 当前版本不生效 | 不要在这两个参数上浪费时间 |
| D-InSAR 用字符串 `"00_05"` 指定对 | 网络阶段仍用默认对 | 用列表 `[0, 5]` 或界面选择 |
| 改完参数不重跑 | 成果仍对应旧参数 | 看项目体检的“参数待重跑”，重跑对应阶段 |

## 6. 常见问题与注意事项

### 6.1 安装与启动

**端口被占用怎么办？**

默认会从 8765 起自动向后找空闲端口，终端会打印实际地址。想固定端口并在被占用时明确失败：

```powershell
python -m insar_studio serve --port 8765 --strict-port
```

`--port 0` 表示交给操作系统分配。

**依赖安装失败怎么办？**

优先使用 Python 3.9–3.11 64 位。SciPy、scikit-image 需要和 NumPy 版本匹配；本项目在 NumPy 1.24 / SciPy 1.10 / scikit-image 0.20 / Matplotlib 3.7 上验证。若使用 conda，按 2.4 节单独建环境。

**没有 SNAPHU 能跑吗？**

能。默认质量引导解缠，不依赖 SNAPHU。只有显式选择 SNAPHU 且调用失败时才会回退，并在 `unwrap_info` 中记录原因。

**页面空白或按钮无反应怎么办？**

1. `Ctrl+F5` 强制刷新；
2. 看浏览器控制台是否有 JS 报错；
3. 看启动服务的终端有没有异常；
4. 确认浏览器访问的是终端打印的地址，而不是旧端口。

### 6.2 项目与数据

**为什么项目体检提示“参数待重跑”？**

说明上次处理后参数被修改过，当前成果仍对应旧参数。按体检建议重跑对应阶段；重跑会清理下游产品。体检本身是只读的。

**为什么任务运行时不能改参数或重复提交？**

同一项目同时只允许一个处理任务，避免两个任务同时写 `products/`。重复提交返回 409；等待完成或取消后再提交。

**导入后全是噪声怎么办？**

先检查：SLC 是否已配准、轨道/基线元数据是否正确、DEM 是否同网格、掩膜是否覆盖有效区域、相干性阈值是否过低。真实 TOPS 数据不要直接拿未拼接的 burst 导入。

**最少需要几景？**

配置表声明 SBAS/PS 至少 8 景、DS 至少 10 景、D-InSAR 至少 2 景，但当前代码没有在导入或创建项目时统一强制这些下限；DS 相位链接本身有 6 景的硬性下限。实际建议：SBAS/PS 至少 8–12 景，DS 至少 10 景；少于 6 景不要跑 DS。

**D-InSAR 的日期对怎么指定？**

界面直接选主/从影像。API 用 `"dinsar_pair": [ref_index, sec_index]`，索引从 0 开始。字符串 `"00_05"` 虽然能通过参数校验，但网络阶段通常不会使用它。

**可以把项目复制到另一台机器吗？**

可以。复制整个 `workspace/projects/<id>/` 到新机器的对应目录，重启服务即可。只迁移成果时，至少复制 `products/` 和 `project.json`；要继续处理，还必须复制 `data/` 和 `interferograms/`。删除项目会删除整个目录，不可恢复。

### 6.3 处理与结果

**速率图方向为什么和别的软件相反？**

本工具约定 LOS 正值朝向卫星（抬升/靠近卫星为正）。不同软件的符号约定可能相反，比较前先确认参考像元和符号。

**速率图出现大面积条纹怎么办？**

检查配准、去斜、DEM 和轨道 ramp。可以先尝试 `remove_ramp=true`，但注意它会移除真实长波形变。若条纹与地形相关，检查 DEM 和 `bperp_m`。

**形变被“抹平”怎么办？**

降低 `regularization`，把 `aps_iterations` 设为 `0` 或 `aps_method=off`，谨慎使用 `remove_ramp`，检查 `estimate_dem_error` 是否吸收了长波信号。

**相位跳变/解缠错误怎么办？**

提高 `unwrap_coherence_min`，换 Goldstein 或 NL-Means，检查配准和 burst 拼接；减小多视会增加噪声，通常不是首选。不要用强滤波掩盖解缠错误。

**为什么成果页没有真值校验？**

真值校验只对合成演示项目有效。真实数据没有真值，页面会提示不可用。

**GeoTIFF 为什么不能直接叠加到地图？**

本工具不做地理编码和正射校正，输出的 GeoTIFF 仍在处理网格上。需要地图坐标时，先在 SNAP/ISCE/GDAL 等工具中完成地理编码。

**ZIP 太大怎么办？**

ZIP 包含干涉图、数组、图件和报告，可能很大。只需要交付图件时，直接取 `products/figures/` 和 `products/report/`；也可以先清理不需要的干涉对产品再导出。

### 6.4 性能、并发与安全

**可以多人同时用吗？**

当前版本不建议。服务是单进程 threaded WSGI，作业在线程中执行；压力测试显示 4 个作业并行效率只有 `0.334`，8 个作业没有吞吐收益；16 线程 API 压测总 p95 为 `11.31 s`，其中 `/api/projects` 端点 p95 达到 `11.96 s`。多人使用应改为进程级 worker 或独立作业进程，并加项目锁。

**可以长时间挂着跑吗？**

30 轮长稳测试显示 RSS 从 `165.0 MB` 涨到 `272.1 MB`，句柄从 `671` 涨到 `1050`。当前版本没有证明 8 小时连续运行无漂移；长时间运行时应监控内存和句柄，定期重启，并先修复资源释放问题。

**可以把服务暴露到局域网或公网吗？**

不要。默认只监听 `127.0.0.1`，没有登录、权限、CSRF、TLS 和速率限制。任何能访问端口的人都可以创建、修改、删除项目，读取项目内任意文件。远程访问请用 SSH 隧道或带认证的反向代理，并自行加访问控制。

**GACOS 令牌会保存吗？**

`project.json` 和报告会过滤敏感字段，但 1.2.0 的 `interferograms/summary.json` 可能保留 `gacos_token`、`gacos_email` 等参数，并随 ZIP 导出。处理真实凭据后，检查并删除该文件中的敏感字段；更稳妥的做法是使用本地 GACOS，或在一次性会话中输入令牌。

**项目目录里不要放什么？**

不要放私钥、口令文件、与处理无关的敏感资料。`/api/projects/<id>/asset/<path>` 和 `/api/projects/<id>/download/<path>` 可以读取项目目录内的任意文件；这是本地单用户工具的设计取舍，不是多租户隔离。

**删除项目能恢复吗？**

不能。删除会移除整个项目目录。请先备份 `workspace/projects/<id>/`，或导出 ZIP。

### 7.8 如果已经误传了敏感信息

1. **先轮换凭据**：删除或重置 token、密码、密钥。只要推送过，就应视为已泄露。
2. 从当前提交删除文件：

```powershell
git rm --cached path\to\secret.json
git commit -m "Remove sensitive file"
git push
```

3. 历史仍然保留旧内容，需要重写历史：

```powershell
# 安装 git-filter-repo 后
git filter-repo --path path/to/secret.json --invert-paths
git push --force --all
git push --force --tags
```

4. 通知协作者重新克隆；强制推送会改变历史。
5. 如果仓库已经公开，联系 GitHub Support 请求清理缓存，并检查 fork。
6. 之后加 secret scanning、pre-commit hook 和 CI 检查，避免再次发生。

`git rm --cached` 只影响下一次提交，不会清除历史；不要以为删掉文件就安全了。

- **先私有后公开**：先推私有仓库，检查文件列表、体积、secret scanning，再切换 Public。
- **许可证**：保留 MIT，补版权人和免责声明；第三方依赖和数据单独合规。
