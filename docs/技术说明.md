## 1. 业务目标与项目定位

### 1.1 产品定位

InSAR Studio 是一个本地优先、单用户的时序 InSAR 形变处理工作台。它把“已配准的复数 SLC 栈”加工成可检查的视线向（LOS）位移、速率、相干性、残差、DEM 误差、大气诊断、报告和成果包，并提供一条从演示数据到真实数据导入的完整路径。

它覆盖的是时序处理与反演这一段，不覆盖 Sentinel-1 原始产品的完整工程化预处理链。真实 TOPS 数据仍应在 SNAP、ISCE、Gamma 等软件中完成轨道校正、burst 拼接、去斜和 TOPS 配准，再导入本工具；导入后，若参考轨道与几何元数据齐全，本工具可用距离-多普勒模型把产品重采样到 EPSG:4326 地图网格。

### 1.2 可验证的业务目标

| 编号 | 业务目标 | 具体表现 | 验收方式 |
| --- | --- | --- | --- |
| G1 | 降低从 SLC 栈到形变产品的操作成本 | 七步向导、一键全流程、单阶段重跑、自动补齐前置阶段 | 新建演示项目后只点一次“一键跑完全流程”即可得到速率图、报告和 ZIP |
| G2 | 结果可复现 | 演示数据固定种子；项目保存参数；阶段保存参数指纹 | 同一版本、同一参数重跑四个演示，指标应落在本文基线附近 |
| G3 | 过程可检查 | 每个阶段输出 JSON 摘要、数组和图件；体检给出分级和下一步 | 体检能指出缺数据、参数过期、缺配准、缺干涉、缺反演、磁盘不足 |
| G4 | 数据尽量留在本机 | 默认只监听 `127.0.0.1`；数据和产品写入 `workspace/` | 断网后除在线下载/GACOS 外，演示与本地处理仍可运行 |
| G5 | 精度表述克制 | 真值校验只对合成演示启用；报告中明确使用限制 | 真实项目不生成真值评分；报告含“合成数据不能外推”声明 |
| G6 | 失败可恢复 | 作业取消、服务重启标记中断、阶段下游清理、原子写入 | 运行中重启服务后任务变为 `interrupted`，项目文件不出现半写 JSON |

| 地质灾害研究人员 | 滑坡、沉降的快速踏勘 | 小基线网络、速率图、时间序列、点位 CSV |

### 1.4 明确不做的事情

- **不做 TOPS burst 级配准、去斜、burst 拼接，也不做轨道误差改正**。配准模块只处理已经近似配准的整景 SLC；支持读取本地 Sentinel-1 EOF 精密轨道文件估计逐景垂直基线。
- **地理编码只覆盖具备完整轨道几何元数据的栈**。实现距离-多普勒正反解和 DEM 迭代，输出 WGS-84（EPSG:4326）北向上网格；不做投影变换、跨 180° 经线处理、TOPS burst、去斜或轨道误差改正。元数据不足时明确写入 `unavailable`，不伪造经纬度。
- **不做升/降轨联合分解、GNSS 基准校正、断层反演、角反射器识别**。
- **不做生产级多用户、权限、审计、任务队列和分布式计算**。服务是本机单进程，任务在进程内线程执行。
- **不保证 GACOS 官方服务改版后的兼容性，也不保证自定义在线 GACOS 和 Sentinel-1 下载适配器兼容所有部署**。它们是薄适配器，接口可能随服务方变化。
- **不把合成演示精度当作真实数据精度**。

### 2.2 进程、线程与状态归属

| 状态 | 存放位置 | 生命周期 | 说明 |
| --- | --- | --- | --- |
| 项目元数据 | `project.json` | 持久 | 参数、路线、步骤记录、时间戳 |
| 栈元数据 | `data/stack/meta.json` | 持久 | 日期、尺寸、波长、入射角、基线、地理角点 |
| 阶段产物 | 各阶段目录 | 持久，可被清理 | 网络、干涉图、大气、反演数组、图件 |
| 作业状态 | `workspace/jobs/job_*.json` | 持久，最多 300 个 | 运行中也在内存；重启后恢复历史记录 |
| 前端状态 | 浏览器内存 + localStorage | 会话/持久 | `insar.mode`、`insar.lastProject` |
| 图件缓存 | `workspace/cache/figures/` | 持久 | 干涉对预览 PNG，按项目 ID、对编号、字段、mtime 命名 |

进程模型：

- `server.py` 使用 `werkzeug.serving.make_server(..., threaded=True)` 启动单进程多线程 WSGI 服务。
- 每次提交处理任务时，`JobManager` 创建一个守护线程执行该任务。
- 同一项目同时只允许一个 `exclusive=True` 的作业；不同项目可以并行，但共享同一个进程、GIL、磁盘和内存。
- 没有跨进程锁。**不要让两个服务进程指向同一个 `workspace`**，否则阶段清理和写入可能互相破坏。

### 2.3 分层职责

| 层 | 模块 | 职责 | 不应做的事 |
| --- | --- | --- | --- |
| 表现层 | `templates/index.html`、`static/js/app.js`、`static/css/app.css` | 七步导航、表单、任务轮询、图件查看、报告触发 | 不直接读写文件，不实现算法 |
| 接口层 | `api.py` | 路由、参数合并、状态码、资源安全、作业提交 | 不实现数值算法 |
| 编排层 | `pipeline.py` | 阶段顺序、前置展开、进度映射、步骤记录 | 不直接做数值计算 |
| 领域层 | `project.py`、`params.py`、`jobs.py`、`health.py` | 项目持久化、参数校验/指纹、作业状态机、体检 | 不依赖 Flask 请求上下文 |
| 算法层 | `core/*.py` | 配准、网络、干涉、滤波、解缠、大气、反演、PS/DS、I/O、绘图 | 不感知 HTTP 和作业 |
| 交付层 | `validation.py`、`report.py`、`download.py`、`importer.py` | 真值校验、报告/ZIP/CSV、外部下载、数据导入 | 不改变处理算法 |

### 2.4 设计原则与取舍

1. **文件即数据库**：项目目录自包含，便于拷贝、审查和归档；代价是没有事务、没有索引，项目很多时列表需要目录扫描。列表接口用分页、5 秒目录/行缓存和显式失效把这笔开销限制在可控范围。
2. **阶段可重跑**：每个阶段先清理自己及下游，再写入新结果；代价是重跑上游会删除大量下游产物，耗时与磁盘 I/O 较高。
3. **参数指纹**：用稳定短哈希判断“结果是否由当前参数产生”；代价是指纹只覆盖已登记的阶段参数，未知参数不参与。
4. **本地优先**：默认只监听回环地址，凭据不落盘；代价是没有认证、没有 CSRF 防护，不能直接暴露到公网。
5. **演示可复现**：固定种子和固定合成模型；代价是演示指标只证明链路，不证明真实数据能力。
6. **回退优先**：SNAPHU 缺失回退内置解缠，仿射估计失败回退平移，PS 选点过严时自动放宽；代价是回退会改变结果口径，必须看元数据。

### 2.5 请求路径与任务路径

一次“跑全流程”的调用链：

```text
浏览器 POST /api/projects/<id>/run
  → api.run_all：读取项目、合并参数、校验路线和参数
  → jobs.submit：检查同项目是否有活跃作业；创建 job JSON；启动线程
  → 立即返回 202 {"job": {...}}
  → 后台线程 run_pipeline
      → coregistration → network → interferometry → atmosphere → inversion
      → 每个阶段写 JSON/数组/图件，并在 project.json 的 steps_run 记录时间和参数哈希
  → 浏览器每 1000 ms GET /api/jobs/<job_id>
  → 状态 done/failed/cancelled/interrupted 后停止轮询并刷新成果
```

请求线程只做校验和提交，不在请求内跑长任务（报告生成、ZIP 导出、CSV 生成除外）。因此大项目提交后应立即返回 202，处理进度通过作业接口读取。

## 5. 技术路线与能力边界

### 5.1 四条路线总表

| 路线 | 网络构造 | 相位处理 | 反演 | 适用场景 | 主要限制 |
| --- | --- | --- | --- | --- | --- |
| SBAS | 所有满足时间/垂直基线阈值的日期对，补连通边，按短基线优先裁剪到 `max_pairs` | 逐对干涉、滤波、解缠、去平面 ramp | 共用加权最小二乘 + 时间正则 + 稳健迭代 | 沉降、滑坡、区域形变，默认推荐 | 依赖网络连通性和解缠质量 |
| PS | 参考影像星形连接 + 相邻日期对 | 与 SBAS 相同的逐对干涉；反演前按 ADI 和相干性选点 | 共用时序解算，只在 PS 点上求解并加权 | 城市建筑、裸岩、强散射点 | 不是完整 PS 相位模型；低相干区点少 |
| DS | SBAS 小基线网络 | 先按行块估计局部相干矩阵并做特征分解相位链接，再重建干涉图 | 共用时序解算，DS 相干性加权 | 植被、裸土等分布式目标 | 特征分解随历元数立方增长；相位链接是局部近似 |
| D-InSAR | 单对；默认 `n//3` 与最后一景 | 单对干涉、滤波、解缠、去平面 ramp | 解缠相位直接转 LOS 位移 | 同震、滑坡、快速踏勘 | 无时序约束；受大气和 DEM 误差影响大 |

### 5.2 SBAS

实现要点：

1. 枚举所有 `i < j` 的日期对。
2. 保留 `dt <= max_temporal_baseline` 且 `|bperp_j - bperp_i| <= max_perpendicular_baseline` 的对。
3. 去重并按 `(ref, sec)` 排序。
4. 若日期图不连通，在相邻连通分量之间补一条时间最近、垂直基线差最小的边。
5. 若对数超过 `max_pairs`，先按 `(dt, |bperp_diff|)` 排序，为每个日期保留至少一条边，再按排序补足；只有裁剪后仍保持原连通分量数时才接受裁剪。

默认参数下，演示 24 景生成 80 对，冗余度 80/23 ≈ 3.48。

### 5.3 PS

实现要点：

1. 网络：以参考影像为中心的星形连接；当 `ps_star_all=false` 时只保留时间基线内的星形边；再补充所有相邻日期对用于闭环检查。
2. 选点：计算振幅离差指数 `ADI = std(amp)/mean(amp)` 和平均干涉相干性；振幅离差按行块流式累计一阶/二阶矩，平均相干性逐对累加有限值；同时满足 `ADI <= ps_adi_max` 且 `mean_coherence >= ps_coherence_min` 的像元为候选。
3. 自动放宽：候选少于 `max(30, 0.2% 有效像元)` 且存在有限相干性时，按 `(1/(ADI+0.03)) * coherence` 取前 `max(30, 1.5% 有效像元)`，并标记 `relaxed=true`；若相干性全部无效，候选点为 0，反演会明确报错而不是伪造点。
4. 形态学开运算：若开运算后仍保留至少 `max(20, 35% 候选)`，用开运算结果去除孤立点。
5. 权重：`clip((1 - min(ADI/adi_max, 1)) * mean_coherence, 0.04, 1.0)`，非候选点权重为 0。
6. 反演：与 SBAS 共用求解器，但只对 PS 掩膜内的点求解，并把 PS 权重作为像元权重。

边界：这不是“逐点永久散射体相位模型 + 逐点大气估计”的完整 PS-InSAR。它做的是 PS 候选选点，再复用逐对解缠相位和共用时序解算。对真实城市数据，点密度和相位质量取决于配准、解缠和相干性估计，不能把演示中的 42,326 个点当作典型值。

### 5.4 DS

实现要点：

1. 要求至少 6 个历元，否则 `phase_link` 抛错；DS 路线整体下限由 `TECHNIQUES` 强制为 10 景。
2. 对每景按垂直基线去除地形相位，再做 `multilook` 多视。
3. 用 `ds_patch × ds_patch` 局部窗口估计复数相干矩阵；窗口逐像元滑动，重叠率固定为 100%。协方差按行块计算，单块受 `COVARIANCE_BUDGET_BYTES` 约束，不再保留全量 `(n, n, rows, cols)` 矩阵。
4. 对每个像元的相干矩阵做特征分解，取主特征向量，得到链接相位（EMI）；DS 相干性为主特征值/迹。
5. 用链接相位重建每对干涉图，成对相干性由 `pair_coherence()` 按对重算，再做轻量 Boxcar 平滑和解缠。
6. 以 DS 相干性作为反演像元权重。

参数说明：

- `ds_patch` 必须是奇数，范围 3–41。
- 相位链接固定为 EMI 特征分解；协方差固定为逐像元滑窗、100% 重叠。`ds_overlap` 和 `ds_phase_linking` 已从默认参数、参数校验、路由参数和界面中移除，旧项目里的残留值会被忽略。
- `ds_patch`、`ds_coherence_min`、`ds_filter_size` 是引擎读取的 DS 参数，已纳入干涉阶段指纹；其中后两者未出现在主 UI 中。

### 5.5 D-InSAR

实现要点：

1. 网络阶段只生成一对：`dinsar_pair` 支持 `"00_05"`、`"0_5"`、`[0, 5]` 和 `(0, 5)`；未指定时默认 `(max(0, n//3), n-1)`。
2. 干涉阶段对该对做地形相位去除、滤波、解缠、去平面 ramp。
3. 反演阶段直接取该对解缠相位，按 `d = φ * λ / (4π) * 1000` 转成毫米。
4. 输出 `disp_pair_mm.npy`、`disp_ts_mm.npy`（单帧）、`velocity_mm_yr.npy`（全 NaN）、相干性、残差、有效掩膜。

边界：

- `dinsar_pair` 的字符串形式（如 `"00_05"`）和列表/元组形式等价，都会在**网络阶段**生成指定的一对；反演阶段也会再次校验该对是否存在于网络中。字符串格式必须是两个非负整数，中间用下划线连接。
- 单对结果没有时间约束，无法区分形变、大气、DEM 误差和轨道 ramp；报告中的限制说明必须保留。

### 5.6 路线选择建议

| 目标 | 建议 | 原因 |
| --- | --- | --- |
| 第一次跑通、区域沉降 | SBAS | 网络稳健，覆盖和冗余度平衡 |
| 城市建筑、桥梁、裸岩 | PS | 强散射点保留，点目标精度潜力高 |
| 植被、农田、裸土 | DS | 分布式目标相位链接，提升低相干区覆盖 |
| 同震、突发滑坡、应急 | D-InSAR | 单对最快，几分钟出图 |
| 需要严格对比升降轨 | 不支持 | 没有几何分解和 GNSS 基准 |

### 5.7 明确不具备的能力

- 不执行 burst 级 TOPS 配准、去斜、拼接。
- 不改正卫星轨道误差；可由本地 EOF 精密轨道文件估计垂直基线。
- 不做地图投影重采样和正射校正。
- 不做升/降轨联合分解、方位向/距离向分解。
- 不做 GNSS、水准、气象再分析数据融合。
- 不做断层滑动反演、震源参数反演。
- 不做角反射器识别、永久散射体相位闭环全局优化。
- 不做云原生对象存储、分布式计算、数据库、用户体系。
- 不保证在线数据源长期可用。

## 6. 七步工作流与五阶段管线

### 6.1 界面七步

| 步骤 | key | 主要内容 | 对应引擎阶段 |
| --- | --- | --- | --- |
| 项目 | `project` | 新建/选择/删除项目、技术路线、名称、备注 | 无 |
| 数据 | `data` | 振幅/DEM/掩膜预览、导入、Sentinel-1 搜索下载 | 无（导入是独立动作） |
| 网络 | `network` | 基线散点、连通性、冗余度、干涉对列表、重建网络 | `network`（内部可能先跑 `coregistration`） |
| 干涉 | `interferometry` | 逐对相位/相干性/解缠浏览 | `interferometry` |
| 大气 | `atmosphere` | GACOS/经验/关闭、诊断图 | `atmosphere` |
| 反演 | `inversion` | 时序位移/速率、DEM 误差、PS/DS 参数 | `inversion` |
| 成果 | `results` | 图件、时间序列、CSV、报告、ZIP、真值校验 | 读取 `products/` |

`step` 导航只是 UI 分区；真正的处理阶段由 `pipeline.py` 的 `run_*` 函数执行。界面允许在“网络”页直接触发网络构建，此时如果 SLC 尚未配准，`run_network` 会先执行配准。

### 6.2 引擎五阶段

| 顺序 | 阶段 key | 入口函数 | 主要产物 | 前置条件 |
| --- | --- | --- | --- | --- |
| 1 | `coregistration` | `run_coregistration` / `coregister_stack` | `data/processed/slc_coreg.npy`、`coreg.json` | `data/stack/slc.npy` 等 |
| 2 | `network` | `run_network` / `build_network` | `data/network.json`、`network.png` | 栈元数据；必要时自动配准 |
| 3 | `interferometry` | `run_interferometry` / `process_interferograms` 或 `run_ds_interferometry` | `interferograms/`、`summary.json` | 配准栈、网络 |
| 4 | `atmosphere` | `run_atmosphere_step` / `run_atmosphere` | `data/atmosphere/atmosphere.json`、逐对校正相位 | 干涉图 |
| 5 | `inversion` | `run_inversion_step` / `run_inversion` | `products/`、`inversion.json` | 干涉图；大气可选 |

### 6.3 前置阶段自动展开

`pipeline._expand_steps` 的规则：

- 请求 `atmosphere` 但干涉未就绪 → 自动加入 `interferometry`。
- 请求 `inversion` 但干涉未就绪 → 自动加入 `interferometry`。
- 请求 `interferometry` 但网络未就绪 → 自动加入 `network`。
- `atmosphere` **不是** `inversion` 的强制前置：反演可以直接使用原始解缠相位。
- `coregistration` 由 `run_network` 自己检查；如果配准栈存在但配准参数指纹变化，会重新配准。导入时标记为 `already_coregistered` 的栈是例外：只要 `data/processed/slc_coreg.npy` 存在，就直接复用，不再重采样。

单阶段 API 还做了一层前置补齐：

- `POST /interferometry` 缺网络 → 运行 `network, interferometry`。
- `POST /atmosphere` 缺干涉 → 运行 `interferometry, atmosphere`。
- `POST /inversion` 缺干涉 → 运行 `interferometry, inversion`。
- 路线切换时 → 运行 `network, interferometry, atmosphere, inversion`，并保留配准。

### 6.4 阶段清理与 stale 计算

每个阶段开始前调用 `purge_downstream(root, stage)`：

| 阶段 | 删除的本阶段及下游产物 |
| --- | --- |
| `coregistration` | `data/processed`、`data/network.json`、`interferograms`、`data/atmosphere`、`products` |
| `network` | `data/network.json`、`network.png`、`interferograms`、`ds_coherence.png`、`data/atmosphere`、`atmosphere.png`、`products` |
| `interferometry` | `interferograms`、`ds_coherence.png`、`data/atmosphere`、`atmosphere.png`、`products` |
| `atmosphere` | `data/atmosphere`、`atmosphere.png`、`products` |
| `inversion` | `products/arrays`、`geotiff`、`csv`、`report`、`exports`、`inversion.json`、`validation.json`、`geocode.json`、反演图件 |

清理实现：

- 目录先重命名到项目内 `.trash/`，再删除；避免 Windows 下“目录非空”与并发读取冲突。
- 文件或目录删除最多重试 6 次，退避 `0.05 s × 次数`。
- 删除后从 `project.json` 的 `steps_run` 中移除本阶段及下游记录，并移除 `pipeline` 记录。
- 上游阶段产物保留，例如重跑 `network` 不清除配准图和配准 JSON。

`ProjectStore.status()` 计算 stale：

- 读取当前参数，合并默认值，补大气默认值。
- 对每个阶段读取 `steps_run[stage].params_hash`，与当前指纹比较。
- stale 向下传播：配准 stale → 网络 stale → 干涉 stale → 大气 stale → 反演 stale。
- 没有记录指纹的阶段不会被判 stale；旧项目或手工删除 `steps_run` 后，状态可能显示“已完成”但无法证明参数一致。

### 7.2 新建空项目与导入

空项目：

```text
POST /api/projects {source: "empty", technique: "ps"}
  → 创建 project.json，无 stack
  → 201
```

导入到已有项目：

```text
POST /api/projects/<id>/import/preflight
  {path: "...", dem_path: "...", meta: {...}, deep?: false}
  → deep=false（默认）：_probe_source 轻量预检
      头部探测 + 最多 4M 像元连续块抽样，不加载整栈
  → deep=true：_read_source 完整读取，与正式导入同样校验
  → 识别、校验、生成 warnings 与 preflight 摘要
  → 不写任何文件
  → 200 {"ok": true, "preflight": meta}

POST /api/projects/<id>/import
  {path: "...", dem_path: "...", meta: {...}}
  → import_stack
  → 完整读取并校验全部像元（不受预检级别影响）
  → 识别输入类型
  → 校验形状、有限值、日期、地理参考、配准标记
  → 写临时目录 data/stack.tmp.<id>
  → 旧 data/stack 改名为 data/stack.old.<id>
  → 临时目录替换为 data/stack
  → 删除备份
  → _clear_derived 清理干涉图/产品/网络/大气
  → 若 already_coregistered：写 data/processed/slc_coreg.npy 与 coreg.json
  → reset_derived(keep_coreg=already_coregistered)
  → 更新 project.json 的 source/demo/stack（含 warnings 与标记）
  → 200 {"ok": true, "stack": meta}
```

创建导入项目：

```text
POST /api/projects {source: "import", path: "...", dem_path: "...", meta: {...}}
  → 先 create 一个项目
  → 再 import_stack
  → 任一步失败则删除半成品项目
  → 201 或 400
```

支持输入：

| 输入 | 识别方式 | 说明 |
| --- | --- | --- |
| 单个 `.npy` | 文件后缀 | 视为 SLC 栈；2D 自动加一维 |
| 单个 `.npz` | 文件后缀 | 读取 `slc`、可选 `dem`/`mask`/`dates`/`meta` |
| 原生目录 | 含 `stack.json`/`meta.json`/`slc.npy` | `meta.json` 提供日期、基线、平台等 |
| ENVI | `.hdr`/`.dat`/`.img` | 调用 `read_envi` |
| GeoTIFF 目录 | 目录内 `.tif/.tiff` | 按文件名提取日期；尺寸不一致按最小公共范围裁剪 |
| Sentinel-1 SAFE | 含 `measurement/` 或 `.safe` 子目录 | 实验性，单 swath，复数 int16 TIFF |

导入校验：

- 维度必须是 `(n_dates, rows, cols)`。
- `n_dates >= 2`，`rows >= 4`，`cols >= 4`。
- 非复数输入会警告并转成零相位实数，结果只能作为演示。
- 有限值比例 `< 50%` 直接拒绝；`< 99.9%` 警告。
- 全零 SLC 拒绝。
- 日期必须是 `YYYY-MM-DD`；重复日期拒绝；乱序自动重排并同步重映射 `bperp_m` 和 `ref_index`。
- 缺失日期按 12 天间隔补齐，但 `dates_source` 标记为 `inferred` 并给出警告，避免把推断日期当成真实观测日期。
- 缺 DEM → 零 DEM，并警告地形相位/DEM 误差不可用。
- DEM 尺寸不一致 → 重采样；非有限值 → 置 0；常数 DEM → 警告。
- 缺掩膜 → 用首景振幅的 3%–99% 分位生成，并去掉 2 像元边界。
- 掩膜全无效 → 拒绝。
- 缺 `bperp_m` 或数量不一致 → 置零并警告；DEM 误差估计应关闭。
- 缺 `corner_lon`/`corner_lat` → `geo_referenced=false`，预检和体检都警告成果使用像元坐标；坐标恰好为 0,0 时可用 `geo_referenced=true` 显式覆盖。
- GeoTIFF 目录会读取首景的 `ModelPixelScaleTag` 和 `ModelTiepointTag`，作为地理参考的兜底来源。
- `already_coregistered`（兼容 `coregistered`、`pre_coregistered`）为真时，导入器把 SLC 栈硬链接/复制为 `data/processed/slc_coreg.npy`，并写 `model: "pre-coregistered"` 的 `coreg.json`；`run_network` 和显式配准阶段都跳过二次配准。
- `dry_run=True` 默认执行轻量预检（见下节），`deep=True` 时执行与正式导入相同的完整读取、校验和警告生成；两者都不写 `data/`、不清理下游，用于 `POST /api/projects/<id>/import/preflight`。

#### 预检分层（P3-3）

预检的目标是让用户在覆盖当前栈之前看到尺寸、日期、基线、地理参考和警告，同时避免把 1 GB 级 SLC 读两遍。默认 `deep=false` 时按输入类型分层：

| validation | 适用输入 | 实际读取 | 能发现的问题 |
| --- | --- | --- | --- |
| `full` | 小于抽样预算的 `.npy` / 原生目录 | 头部 + 全部像元（样本覆盖全量） | 与正式导入相同的有限值/全零检查 |
| `sampled` | 大于 4,000,000 像元的 `.npy` / 原生目录 | 头部 + 最多 4M 像元的 8 个均匀连续块 | 抽样有限值比例、全零；警告带“抽样检查：”前缀 |
| `header` | `.npz` / ENVI / GeoTIFF 目录 / SAFE | 文件头、成员索引、元数据；不读 SLC 像元 | 结构、维度、日期、元数据；数据质量由正式导入完整校验 |

- 抽样预算 `PREFLIGHT_SAMPLE_ELEMENTS = 4_000_000`，complex64 约 32 MB；按文件行序均匀取 8 个连续块，避免跨步采样把整个文件分页读入。
- DEM 与掩膜是辅助数据，预检仍完整读取，用于尺寸、非有限值和常数告警。
- 预检响应额外返回 `validation`、`sample_elements`、`total_elements`、`sample_fraction`；正式导入始终完整读取并校验，不受预检级别影响。
- `deep=true` 强制使用完整读取器，便于对比和排查；`dry_run=True` 且 `deep=false` 时不会调用完整加载器。
- 1.02 GB（8 × 4000 × 4000 complex64）实测：轻量预检 0.19 s / 峰值 RSS +115 MB，深度预检 2.43 s / +1536 MB，正式导入 4.57 s / +1536 MB；轻量预检比深度预检快 12.8 倍、比正式导入快 24.2 倍，警告与深度预检一致（本机、文件已在系统缓存中）。

### 7.3 作业生命周期

```text
提交
  → queued
  → running
      → 进度/阶段/日志持续写 job JSON
      → 用户取消 → cancelling → 下一次进度回调抛 JobCancelled → cancelled
      → 异常 → failed（error 字段含异常类型和信息，日志含 traceback 前 8 层）
      → 正常完成 → done（progress=1.0，result=JSON 安全摘要）
服务重启
  → 读取 jobs/*.json
  → 原 queued/running/cancelling → interrupted
```

状态值：`queued`、`running`、`cancelling`、`done`、`failed`、`cancelled`、`interrupted`。

关键约束：

- `MAX_JOBS = 300`：启动时只保留最近 300 个 job JSON。
- 日志每个作业最多 300 条，单条最多 2000 字符；连续重复消息不重复记录。
- `GET /api/jobs` 默认 30 条，`limit` 被限制在 1–200。
- 同一项目只允许一个活跃 exclusive 作业；`JobBusyError` 转成 HTTP 409，响应里带当前 `job`。
- 取消是协作式的：只有下一次 `progress()`/`check()` 才生效；正在执行的单个 NumPy/SciPy 调用不会被打断。
- 作业完成后迟到的进度回调不会把状态改回 running。

### 7.5 报告与导出

报告：

```text
POST /api/projects/<id>/report
  → generate_report
  → build_markdown
  → build_docx
  → products/report/report.md
  → products/report/report.docx（python-docx 不可用时为 None）
```

Markdown 结构：

1. 项目概况（路线、来源、平台/轨道、影像数、时间范围、尺寸、波长/入射角）。
2. 处理链与参数（配准、网络、干涉、大气、反演、关键参数 JSON）。

ZIP：

- 入口：`GET /api/projects/<id>/export?mode=results|full`，默认 `full`。

- 两种模式都跳过 `products/exports/` 自身，避免递归打包。
- 只收录 `.npy`、`.tif`、`.tiff`、`.png`、`.csv`、`.json`、`.md`、`.docx`。
- `GET /api/projects/<id>/export/summary` 返回两种模式的未压缩字节数、文件数和推荐项，前端据此展示体积。
- 压缩方式：ZIP_DEFLATED，压缩级别 6。
- Windows 下目标 ZIP 被占用时，改用带时间戳的新文件名。

CSV：

- `series_r<row>_c<col>.csv`：列 `date, disp_mm, velocity_mm_yr, temporal_coherence, residual_mm, valid`。
- `points.csv`：列 `row, col, lon, lat, velocity_mm_yr, displacement_mm, temporal_coherence, residual_mm, dem_error_m`。
- 编码 `utf-8-sig`，便于 Excel/WPS 直接打开中文。

### 7.6 服务重启与恢复

- 启动时 `JobManager._compact`/`_load_existing` 扫描 `workspace/jobs/job_*.json`。
- 原 `queued`、`running`、`cancelling` 统一改为 `interrupted`，`finished_at` 取原 `updated_at`。
- 项目数据不会回滚；已经写入的阶段产物仍然存在，`steps_run` 仍保留。
- 重新提交时，阶段清理会删除半成品下游，重新生成。
- 没有断点续跑：不会从中断的干涉对继续，而是从该阶段开头重跑。

基线来源按以下顺序确定：

1. 输入 `meta` 或接口覆盖中显式给出非零 `bperp_m`；

3. 两者都没有时置零，并在导入警告和项目体检中提示。

轨道估计示例（`meta.json`）：

```json
{
  "dates": ["2023-01-03", "2023-01-15"],
  "start_times": ["2023-01-03T05:23:45.123456", "2023-01-15T05:23:45.123456"],
  "orbit_dir": "D:/orbits/S1A"
}
```

导入器会递归查找 `.EOF`，优先使用覆盖成像时间的精密轨道（`POEORB`），其次 restitution 轨道；基线法向量取参考轨道速度与位置的叉积，因此符号与飞行方向一致。SAFE 导入会读取 `annotation` 中的首行时间、入射角和像元间距，但仍不处理 burst 拼接、去斜或 TOPS 配准。

找到本地 EOF 时，导入器还会原子写出 `data/stack/orbits.json`：

```json
{
  "schema": "insar-studio/orbits/v1",
  "ref_index": 0,
  "dates": ["2023-01-03", "2023-01-15"],
  "orbits": [
    {
      "epoch": "2023-01-02T23:59:00+00:00",
      "times": [0.0],
      "positions": [[-1234567.0, -4321000.0, 5678000.0]],
      "velocities": [[1200.0, -3400.0, 5600.0]],

```

`times` 是相对 `epoch` 的秒数；地理编码只读取 `orbits[ref_index]`，并要求轨道覆盖参考影像首行到末行时间。文件缺失、记录数不足或轨道不覆盖成像时段时，`products/geocode.json` 会写 `unavailable` 或明确原因，而不会猜测坐标。

### 8.7.1 地理编码

`core/geocode.py` 在反演产品写完后执行一次后处理：

1. 从 `data/stack/orbits.json` 读取 `orbits[ref_index]`，用与基线估计相同的局部重心多项式插值轨道位置和速度。
2. 对地图网格按行分块，逐块用带限幅的牛顿迭代求解零多普勒方程 `(P - S(t)) · V(t) + λ f_d R / 2 = 0`；`f_d` 缺省为 0，可用 `doppler_centroid_hz` 传常数。每个分块约 512 字节/像元的预算，默认 16 MiB、最多 10 万像元；大网格使用最多 4 个线程并行，结果流式写回预分配的 float32 数组。
3. 由解得的方位时间计算雷达行 `row = (t - t0) / Δt_az`，由斜距计算列 `col = (R - R0) / Δr`。
4. 用雷达坐标采样 DEM，更新地面高程，最多迭代 3 次，收敛阈值 0.5 m；再换算到多视后的产品行列并做双线性采样。
5. 地图网格优先使用 `geo_referenced=true` 时导入的经纬度网格；否则由场景四边、入射角和距离/方位像元间距推导北向上网格，最多 2000 万像元。
6. 结果写入 `products/geotiff/geo/<产品名>.tif`，坐标统一为 EPSG:4326，角点语义与 `write_geotiff()` 一致。

`products/geocode.json` 是机器可读状态文件：

| 字段 | 说明 |
| --- | --- |
| `status` | `done`（覆盖率 ≥ 50%）、`partial`（0 < 覆盖率 < 50%）、`failed`（异常或零交集）、`unavailable`（元数据不足） |
| `method` | 固定为 `range-doppler` |
| `reasons` / `warnings` | 降级原因和近似说明；`unavailable` 时至少一条原因 |
| `grid` | 实际使用的地图网格、边界和 CRS |
| `coverage` / `valid_pixels` | 地图网格中成功反演到雷达产品的比例和像元数 |
| `dem_iterations` / `max_height_update_m` | DEM 迭代次数和最后一次最大高程更新量 |
| `lookup_blocks` / `lookup_block_rows` / `lookup_workers` | 查找表分块数、每块行数和使用线程数 |
| `lookup_seconds` | 查找表求解耗时（秒），不含 GeoTIFF 写出 |
| `files` | 已写出的地图坐标 GeoTIFF 相对路径 |

地理编码失败不会让反演失败：雷达网格产品仍然有效，`inversion.json["geocoding"]` 和项目体检会报告状态。GeoTIFF 使用 PackBits 压缩和最小地理标签；PackBits 不依赖可选编解码器，避免部分 `imagecodecs` 版本写出的 zlib/deflate 文件无法回读。

本机合成几何的大网格基准（`build_lookup()`，不含 GeoTIFF 写出）：

| 网格 | 配置 | 耗时 | 说明 |
| --- | --- | --- | --- |
| 1000 × 1000 | 单块、单线程 | `23.8 s` | 修改前的逐像元路径量级 |
| 1000 × 1000 | 32 块、4 线程 | `3.7 s` | 分块改善缓存局部性，约 6.4× |
| 2000 × 2000 | 125 块、4 线程 | `14.5 s` | 输出数组约 50 MB |
| 5000 × 5000 | 834 块、4 线程 | `89.4 s` | 输出数组约 325 MB，峰值 RSS 增量约 418 MB |

以上是合成几何和无 DEM 的查找表基准，实际耗时会受 DEM 采样、磁盘和并发作业影响；大网格场景建议给进程留出至少 1 GB 余量。

## 9. 处理算法

### 9.1 配准

流程：

1. 参考影像：`ref_index`，默认 0。
2. 对参考和待配准影像做 `log1p(abs())`，按 1%–99% 分位归一化。
3. 以 `tile=64`、步长 `tile/2` 分块；跳过标准差 `< 0.015` 的块。
4. 对每块调用 `skimage.registration.phase_cross_correlation(..., upsample_factor=20, normalization=None)`。
5. 跳过非有限偏移和超过 `tile/2` 的偏移。
6. 以 `std(ref)*std(mov)` 为权重，做 MAD 稳健剔除（阈值 3.5×MAD，MAD 下限 0.08）。
7. 按 `model` 估计变换（输出坐标 → 输入坐标）：`affine` 允许旋转/剪切/尺度，`similarity` 只允许旋转 + 统一尺度 + 平移，`translation` 只估计整体偏移；若 RMS `> 0.75 px` 或参数非有限，回退平移。`coreg.json` 记录实际采用的模型、矩阵、RMS（`rms_px` 与 `affine_rms_px` / `similarity_rms_px`），相似变换还记录 `scale` 和 `rotation_deg`。
8. 用三次样条（`skimage.transform.warp`，平移快路径用 `ndimage.shift`）重采样复数 SLC 的实部和虚部。
9. 在中央 3/5 区域计算配准前后相干性，输出 `coherence_before`、`coherence_after`、`coherence_gain`。

输出：

- `data/processed/slc_coreg.npy`
- `data/processed/coreg.json`
- `products/figures/coreg_coherence_gain.png`

边界：

- 不做 burst 级配准、频谱分带配准、地形相关配准。
- 对低纹理区域，分块可能不足，自动回退整景相位相关或平移。
- 配准参数 `model`、`tile`、`upsample` 会影响阶段指纹。

### 9.2 网络

SBAS 和 DS 使用同一套小基线枚举；PS 使用星形+相邻；D-InSAR 单对。详见 5.2–5.5。

网络统计：

- `redundancy = n_pairs / max(n_dates - 1, 1)`。
- `connected_components` 用并查集计算。
- `max_temporal_days`、`mean_temporal_days`、`max_perpendicular_m` 来自实际保留的对。

### 9.3 干涉

对每个干涉对 `(ref, sec)`：

1. 截取到 `multilook` 的整数倍，复共轭相乘：`ifg_full = sec * conj(ref)`。
2. 多视：复数块平均，得到 `ifg`、`ref_m`、`sec_m`。
3. DEM 多视，掩膜多视（块内有效比例 > 0.5）。
4. 地形相位：`topo = (4π/λ) * bperp_diff / (R * sinθ) * dem`。
5. 去地形：`ifg *= exp(-1j * topo)`。
6. 相干性：`γ = |Σ ifg| / sqrt(Σ|ref|² * Σ|sec|²)`，窗口 `coherence_window`。
7. 滤波：按 `filter` 选择 Boxcar/Goldstein/Gaussian/NL-Means/none。
8. 缠绕相位：`wrapped = angle(filtered)`。
9. 有效掩膜：`mask & (coh >= min_coherence) & isfinite(wrapped)`。
10. 解缠：按 `unwrap_method`，传入相干性和 `unwrap_coherence_min`。
11. 参考像元：优先使用全项目统一参考像元；若该点无效，回退到该对最稳定像元；减去参考相位。
12. 去趋势面：`remove_ramp=true` 时，用高相干像元拟合低阶多项式；`ramp_order=1` 为 `φ = a*x + b*y + c`，`ramp_order=2` 额外包含 `x²`、`y²` 和 `x*y` 项。
13. 位移：`disp_mm = unwrapped * λ / (4π) * 1000`。
14. 保存数组和 `meta.json`。

注意：

- `remove_ramp` 支持 `ramp_order=1`（平面）和 `ramp_order=2`（二次曲面）；默认使用平面，二次曲面需显式选择。二次项会更强地吸收长波信号，研究宽尺度形变时应谨慎。
- 相干性窗口是像元窗口，不是多视后的窗口；多视在相干性之前完成。
- 滤波只影响缠绕相位和解缠输入；原始复数干涉图不单独保存。

### 9.4 滤波

| 方法 | 实现 | 参数 | 特点 |
| --- | --- | --- | --- |
| `boxcar` | 复数实部/虚部分别均值滤波 | `boxcar_size`，奇数 1–31 | 简单稳健，边缘用 nearest |
| `goldstein` | FFT 幅度谱平滑比值的 `alpha` 次幂作为增益，DC 不放大 | `goldstein_alpha` 0–1.5，`goldstein_patch` 8–128 | 保留强散射频谱峰，抑制斑点 |
| `gaussian`/`gauss` | 复数高斯低通 | `gaussian_sigma` 0.3–12 | 平滑但可能糊边 |
| `nlmeans`/`nl-means`/`nlm` | 非局部均值 | 复用相关参数 | 保边，速度慢 |
| `none` | 不滤波 | — | 用于对比或低噪声数据 |

### 9.5 解缠

#### 质量引导（默认）

1. 以相干性和相位梯度平滑度构造质量。
2. 以高质量像元为种子，按质量从高到低区域生长。
3. 相邻相位差取缠绕主值，累加得到连续相位。
4. 对多个连通分量做整体平移对齐到主分量。
5. 输出 `unwrap_info`：`method=quality_guided`、`valid_fraction`、`components`、`main_component_fraction`、`coherence_min`。

#### SNAPHU（可选）

- 调用外部 `snaphu` 可执行文件。
- 未安装、调用失败或输出不可读时，自动回退质量引导，并在 `unwrap_info` 中记录回退原因。
- `snaphu_exe` 可通过参数指定，最长 260 字符。
- `doctor` 会显示 SNAPHU 是否可用；不可用不影响默认流程。

#### skimage 最小二乘

- 使用 `skimage.restoration.unwrap_phase`。
- 适合连续、低噪声相位；不处理断点。
- 无效像元先最近邻填充，解缠后再置 NaN。

### 9.6 大气

#### GACOS

3. 对干涉对 `(ref, sec)` 计算 `delay_pair = delay(sec) - delay(ref)`。

5. 保存 `atmosphere_pair_mm.npy` 和 `unwrapped_atmcorr.npy`。
6. 统计校正前后稳健相位离散度，输出降低百分比。
7. 演示项目用真值大气生成模拟 GACOS，并做真值诊断。

- 邮箱只保存在本次请求内存和响应中；项目内 `last_request.json` 只记录 `email_masked`、批次结果和脱敏 URL。

本地 GACOS：

- 目录递归查找 `.ztd`、`.tif/.tiff`、`.npy`。
- 用日期字符串（`YYYYMMDD` 或 `YYYY-MM-DD`）匹配文件名。
- 同一日期多个匹配时取文件名最短的。
- `.ztd` 可配 `.rsc` 读取角点和步长；GeoTIFF 读取地理标签；`.npy` 无地理信息时按缩放重采样。

自定义在线 GACOS（`gacos_source=online`，非官方接口）：

- `gacos_url`、`gacos_email`、`gacos_token`、`gacos_timeout`、`gacos_dem` 可配置。
- 客户端向 `gacos_url` POST JSON：`email`、`token`、`bbox`、`dates`、`dem`、`format=ztd`。
- 若响应是 JSON，读取 `products` 数组（或直接数组），逐项取 `date`/`url` 下载并缓存到 `data/gacos/online/`。
- 若响应不是 JSON，把响应体当作单文件缓存。
- 没有硬编码第三方端点；不同部署需要自行配置。
- 在线失败会抛错，不会静默使用空屏。

官方产品导入的安全边界：

- tar/zip 拒绝路径穿越、绝对路径、符号链接、设备/非普通条目和加密 zip。
- 限制压缩包条目数（4000）、展开体积（2 GiB）、上传体积（512 MiB）和下载体积（1 GiB）。
- 下载只允许 http/https 公网地址，逐跳校验重定向；拒绝私网、回环、链路本地、组播和保留地址。
- 解压与下载临时文件位于 `data/gacos/.tmp/`，导入结束后清理。

#### 经验高程校正

- 对每个干涉对，用高相干像元（`coh >= 0.45`，至少 150 个）拟合：
  `φ = a0 + a1*x + a2*y + a3*h + a4*h² + a5*h*x + a6*h*y + ...`
- 默认 `empirical_order=1`；`order>=2` 加二次项；`order>=3` 加三次项。
- 稳健重加权最小二乘，默认 3 次迭代。
- 从相位中减去拟合屏。
- 适合没有 GACOS 但地形起伏明显的区域；过度校正会吃掉真实长波形变。

#### 关闭

- `atmosphere_method=off`：不校正，保留原始解缠相位。
- 反演阶段仍可用 `aps_method=spatiotemporal` 做时间高通 APS 分离。

#### 反演阶段 APS

- 对时序相位拟合线性 + 年周期 + 半年周期模型。
- 残差经空间高斯平滑（`aps_sigma_px`）作为 APS 候选。
- 迭代 `aps_iterations` 次，每次从干涉相位中减去屏。
- 只适用于短周期、空间相关的大气扰动，不能替代外部天气模型。

### 9.7 时序反演

观测方程（每个像元、每个干涉对）：

```text
Δφ_k = (4π/λ) * [d(t_sec) - d(t_ref)] + (4π/λ) * B⊥_k * h_err / (R * sinθ) + APS_k + ε_k
```

未知数：

- 每个日期的 LOS 位移 `d(t)`；首日期固定为 0。
- 可选 DEM 误差 `h_err`。

实现：

1. 构造时间差分矩阵 `A`：`A[k, ref] -= 1`，`A[k, sec] += 1`。
2. 若 `n_dates >= 3` 且 `regularization > 0`，加入二阶差分正则 `D`，`G = [A; D * λ]`。
3. 干涉对权重：`clip(mean_coherence, 0.04, 1.0)²`；闭环 flagged 对再乘 0.35。
4. 像元权重：PS 路线使用 PS 权重；其他路线为 1。
5. 稳健迭代：先解一次，计算残差中位数，按 `1/(1+(med/(3σ))²)` 更新对权重，限制在 0.04–1.0；默认 3 次。每轮同时重建观测向量 `Y` 和正规方程权重 `W`，避免两者使用不同轮次的权重。
6. 分块求解正规方程，块大小由 `inversion_block_pixels(n_dates)` 在 512–4096 像元之间选取（48 景为 3640）；每块 `GtWG` 加 `1e-9` 对角岭。`Y` 保持 `float64` 只存干涉对行，权重、残差和模型不再整幅物化。
7. 覆盖率 `coverage = 有效观测数 / 干涉对数`；`coverage >= 0.45` 才进入有效掩膜。
8. 参考像元：`reference_mode=auto` 用稳定像元；`manual` 用 `reference_row/reference_col`，越界或无效时回退。
9. 强制所有日期减去参考像元的历史。
10. 位移：`disp = X * λ / (4π) * 1000`。
11. 残差：`resid = phase_corr - A @ X`。
12. 时序相干性：由残差相位计算的稳定性指标。
13. 速率：对时间序列做最小二乘线性拟合，乘 365.25 转 mm/yr；同时输出拟合 RMSE。

DEM 误差：

- 仅在 `estimate_dem_error=true` 时启用。
- 由于自由逐日相位与基线项共线，先用低阶时间基（线性 + 年 + 半年）约束形变，再估计 DEM 误差列，剥离后恢复完整时序。
- 输出 `dem_error_m.npy`、`dem_error.png`，并记录条件数；条件数 `> 1e4` 时提示基线-时间相关性较强。

### 9.9 DS 相位链接

详见 5.4。实现细节：

- 去地形相位使用逐景 `bperp_m`。
- 多视后尺寸为 `rows//m`、`cols//m`。
- 局部相干矩阵在 `ds_patch` 窗口内用 `uniform_filter` 逐像元滑动估计，窗口重叠率为 100%。
- 特征分解 `np.linalg.eigh`，取最大特征值对应向量。
- 链接相位以参考像元为相位零点。
- DS 相干性 = 最大特征值 / 迹。
- 重建干涉对时，`wrapped = angle(linked[sec] * conj(linked[ref]))`。
- 有效掩膜：`base & (coh >= min_coherence)`；若有效点少于 20，回退到 `base & isfinite(wrapped)`。

### 9.11 真值校验

仅当项目存在 `data/stack/truth.npz` 且 `products/inversion.json` 存在时运行。

时序路线指标：

| 指标 | 计算 |
| --- | --- |
| 位移 RMSE | 预测与真值逐日期、逐像元差的均方根 |
| 位移偏差 | 预测减真值的均值 |
| 位移 P95 | 绝对误差的 95 分位 |
| 逐日 RMSE | 每个日期的 RMSE 列表 |
| 速率 RMSE | 速率图与真值速率的 RMSE |
| 速率偏差 | 速率差的均值 |
| 速率空间相关 | 有效像元上的 Pearson 相关 |
| DEM 误差中位数/相关 | 估计 DEM 误差与真值 DEM 误差的中位数和空间相关 |
| 大气诊断 | 校正前后成对残差 |

D-InSAR 指标：

- 位移 RMSE、偏差、P95、空间相关。
- 真值同样减去参考像元的历史。
- 若大气方法为 `off`，真值加上大气真值差分，避免把未校正大气算进误差。

分级：

- `优秀`：位移 RMSE `< 3 mm`。
- `良好`：`< 6 mm`。
- `可用`：`< 12 mm`。
- `需检查`：`>= 12 mm`。

缓存：`products/validation.json`；按 `technique` 和 `created_at` 复用；`POST /validate` 强制重算。

## 10. API 参考

### 10.1 通用约定

- 所有 API 返回 JSON，文件下载、CSV、ZIP 和 PNG 除外；JSON 编码 UTF-8，`ensure_ascii=False`。
- 错误体固定为 `{"error": "中文说明"}`；409 额外带 `job`；调试模式下的 500 额外带 `traceback`（最多 6 层）。
- `_json_error()` 的默认状态码是 `400`。业务代码显式使用 `404`、`409`、`500`、`502`。
- 除页面 `GET /` 外，其余 46 条规则都在 `/api/` 下。`/run` 与 `/run-all` 是同一处理器的两个装饰器，因此 Flask 中算两条规则、一个实现。
- 所有 JSON 接口统一走 `_json_body()`：空体对可选接口返回 `{}`；坏 JSON、数组、字符串或 `null` 返回 400；`Content-Type` 不是 `application/json`（或 `+json`）返回 415；超过 JSON 上限返回 413。解析使用 `utf-8-sig`，容忍 BOM。
- JSON 请求体默认上限 4 MiB（`DEFAULT_MAX_JSON_BYTES`），可用 `INSAR_MAX_JSON_BYTES` 覆盖，支持 `K/M/G/T` 后缀。`MAX_CONTENT_LENGTH` 仍为 512 MiB（`GACOS_MAX_UPLOAD_BYTES`），只用于 GACOS 官方产品的 multipart 上传；两条限制互不替代。
- 项目 ID 只允许小写字母、数字、下划线。`ProjectStore.path()` 会再次确认解析后的路径位于项目根目录内；非法 ID 抛 `InvalidProjectId(ValueError)`，由 Flask errorhandler 统一映射为 400，合法但不存在的 ID 才返回 404。详见 L21。
- 资产和下载路径由 `safe_join()` 校验：解析后必须仍在项目目录内；`..`、绝对路径、跨盘路径和指向项目外的符号链接都会被拒绝。
- 时间戳格式为 `YYYY-MM-DD HH:MM:SS`，日期格式为 `YYYY-MM-DD`。
- API 没有版本前缀（如 `/v1`）；版本只出现在 `/api/health`、`/api/capabilities` 和页面模板中。

`run` 的 `steps` 语义有三个容易踩坑的地方：

1. `steps=[]` 会被 `_expand_steps()` 当成“未指定”，实际运行全部五个阶段。

### 10.10 作业接口行为

- 提交后立即返回 202，作业在线程中执行；客户端应轮询 `GET /api/jobs/<job_id>`。前端轮询间隔约 1000 ms。
- 状态机：`queued → running → done`，异常分支为 `failed`，取消分支为 `cancelling → cancelled`，服务重启把未完成状态改为 `interrupted`。
- 同一项目只允许一个活跃 exclusive 作业；全局最多同时执行 `INSAR_MAX_CONCURRENT_JOBS` 个作业，默认 2，夹到 1–32。超出槽位的作业保持 `queued` 等待，取消排队作业不会执行。
- `GET /api/jobs` 返回最近作业，默认 30 条，`limit` 夹到 1–200；列表中的日志只保留最后 3 条，详情接口返回完整日志（最多 300 条）。
- 取消是协作式的：`cancel()` 只设置事件并把状态改为 `cancelling`，真正的停止发生在下一次 `ctx.progress()` 或 `ctx.check()`。单个长时间 NumPy/SciPy 调用、SNAPHU 子进程或网络请求不会被立即打断。
- 服务启动时扫描 `workspace/jobs/job_*.json`，按 mtime 从旧到新加载；内存记录与文件均以 `MAX_JOBS=300` 为上限，活跃作业永不被裁剪。原 `queued`、`running`、`cancelling` 改为 `interrupted`，`finished_at` 取原 `updated_at`。
- 作业结果里的 `result` 经过 `json_safe()` 处理；日志单条最多 2000 字符，连续重复消息不重复记录。

### 10.11 资源接口边界

- `GET /asset/<path>` 用 `send_file(..., max_age=60)` 返回文件，浏览器按扩展名推断 MIME；它不提供目录列表。
- `GET /download/<path>` 强制 `as_attachment=True`，下载名取文件名。
- 两个接口都只要求“文件存在且在项目目录内”。如果项目内放了凭据文件、原始数据或报告，它们都能被读取。这是本地单用户工具的设计取舍，不是多租户隔离。
- `safe_join()` 使用 `Path.resolve()`，因此符号链接会先解析再判断；指向项目外的链接会被拒绝。
- 干涉对图片由 `_render_pair_image()` 按字段读取数组并用 Matplotlib 渲染，结果写入 `workspace/cache/figures/`；缓存键包含项目 ID、对编号、字段和源文件 mtime。

### 11.4 启动与端口

```powershell
cd D:\path\to\insar-studio
python -m insar_studio serve --open
```

- 默认只监听 `127.0.0.1`，首次可用端口从 8765 开始。
- `--port 0` 交给操作系统分配；`--strict-port` 在指定端口被占用时直接失败。
- `server.py` 使用 `werkzeug.serving.make_server(..., threaded=True)`，单进程多线程。
- 启动时创建 `workspace/`、`workspace/projects/`、`workspace/cache/`、`workspace/logs/`（`jobs/` 由 `JobManager` 创建）。
- 按 `Ctrl+C` 停止；已写入的项目文件保留，运行中的作业在下次启动时标记为 `interrupted`。

### 11.5 命令行

| 命令 | 作用 | 关键行为 |
| --- | --- | --- |
| `python -m insar_studio serve` | 启动 Web 服务 | 支持 `--host`、`--port`、`--open`、`--no-browser`、`--strict-port`、`--debug` |
| `python -m insar_studio demo --name NAME --technique sbas` | 创建演示项目并跑全流程 | `--no-run` 只生成数据；路线可选 `sbas`、`ps`、`ds`、`dinsar` |

`run` 会覆盖已有产品，但保留演示数据。批量回归时可以组合 `demo` 与 `run`。

### 11.6 工作区与迁移

- 工作区是纯文件目录，没有数据库。复制整个 `workspace/projects/<id>/` 到另一台机器即可迁移项目；前提是路径、依赖版本和项目内相对路径保持一致。
- `project.json` 的 `schema` 字段目前只写不校验。没有迁移器，也没有版本升级钩子；读取旧项目时依赖字段缺失时的默认值。
- `data/stack/meta.json` 的 `slc_path`、`dem_path`、`mask_path` 是相对项目根目录的路径，由 `safe_join()` 解析。手工迁移时不要改成绝对路径。
- 项目 ID 由 `prj_<秒级时间戳十六进制>_<6 位随机十六进制>` 组成；同一秒内创建多个项目仍靠随机后缀区分。
- 删除项目是直接 `shutil.rmtree()`，没有回收站。需要保留时先复制目录或导出 ZIP。

## 12. 性能、容量与并发

### 12.1 本机实测基线

测试环境：Windows，Python 3.11.4，NumPy 1.24.3，单进程 Flask；演示数据 24 景、220 × 260；结果来自 `1.2.0` 最终回归。

| 路线 | 干涉对 | 全流程耗时 | 位移 RMSE | 速率 RMSE | 项目目录大小 |
| --- | ---: | ---: | ---: | ---: | ---: |
| D-InSAR | 1 | 4.2 s | 2.0363 mm | 不适用 | 45.5 MB |
| SBAS | 80 | 17.3 s | 1.8469 mm | 2.1370 mm/yr | 78.6 MB |
| DS | 80 | 18.1 s | 2.5174 mm | 3.5937 mm/yr | 81.4 MB |
| PS | 45 | 33.6 s | 1.8651 mm | 3.4372 mm/yr | 133.4 MB |

耗时包含配准、网络、干涉、大气、反演、地理编码和产品写出，不含报告和 ZIP 生成；随机器、磁盘和杀毒软件变化。`pytest` 全量 213 项通常 40–80 秒，不含四套完整演示回归。

#### 12.1.1 大栈基准（48 景 × 700 × 700）

除 canonical 的 24 景小栈外，另用独立工作区生成 48 景、700 × 700 像元的合成栈（`slc.npy` 0.188 GB），SBAS/DS 使用 `multilook=2`，PS 使用单视，三套分别跑完整五阶段：

| 路线 | 干涉对 | 总耗时 | 配准 | 干涉 | 反演 | 峰值 RSS 增量 | 位移 RMSE | 速率 RMSE | 速率相关 | 评价 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| SBAS | 160 | 295.7 s | 37.0 s | 195.5 s | 55.2 s | 689 MB | 1.9608 mm | 2.0934 mm/yr | 0.9687 | 优秀 |
| PS | 93 | 698.2 s | 37.7 s | 473.1 s | 174.6 s | 1625 MB | 3.5364 mm | 3.2480 mm/yr | 0.9137 | 良好 |
| DS | 160 | 321.9 s | 37.1 s | 222.7 s | 54.0 s | 942 MB | 2.8070 mm | 2.2456 mm/yr | 0.9360 | 优秀 |

PS 反演阶段的进程峰值从旧实现的约 5.2 GB 降到 1.65 GB，主要由观测向量保持 `float64` 但不再复制整幅权重、残差和模型立方体带来；`estimate_inversion_peak(93, 490000, 48)` 给出 1.91 GB，比实测高约 16%。三套大栈均无轨道状态向量，地理编码状态为 `unavailable`；PS 因为单视、低相干像元多，评价为“良好”，SBAS/DS 为“优秀”。这组数字用于观察规模趋势，不是真实 SLC 的精度承诺。

### 12.2 计算复杂度

| 环节 | 主要复杂度 | 说明 |
| --- | --- | --- |
| 网络枚举 | `O(n²)` | 即使 `max_pairs` 很小，仍会先枚举所有日期对 |
| 干涉 | `O(P · R · C · w²)` | `P` 为对数，`w` 为相干性/滤波窗口；逐对读写数组 |
| 配准 | `O(n · R · C · tile²)` | 分块相位相关，块间有重叠步长 |
| DS 协方差 | `O(n² · R · C · patch²)` | 每个日期对都要做局部均值滤波；按行块计算，峰值缓存受预算约束 |
| DS 特征分解 | `O(R · C · n³)` | 每个有效像元一个 `n × n` 复矩阵 |
| 时序反演 | `O(R · C · p · n²)` 量级 | 按 `inversion_block_pixels()` 动态分块，512–4096 像元（48 景为 3640）；每块批量求解正规方程，不逐像元做 SVD |
| 报告/ZIP | `O(文件数 + 总字节)` | 同步执行，压缩级别 6 |

### 12.3 内存

- `core/memory.py` 统一提供内存检测、预算和阶段前检查。`available_memory_bytes()` 在 Windows 读取 `ullAvailPhys`，Linux 读取 `/proc/meminfo` 的 `MemAvailable`，macOS 读取 `SC_AVPHYS_PAGES`；`usable_memory_bytes()` 保留 10% 且至少 256 MiB 余量，避免把系统、浏览器和页缓存挤掉。
- 设置环境变量 `INSAR_MEMORY_BUDGET_BYTES` 可以覆盖自动检测值，支持纯字节数或 `K/M/G/T` 后缀（例如 `16G`）。检测不到可用内存时，预算检查自动放行，不阻塞任务。
- 各阶段在分配大数组前调用 `ensure_memory_budget()`。预计峰值超过可用物理内存的 90% 时抛出 `MemoryBudgetError`，错误信息给出阶段、预计峰值、可用内存，并建议增大 `multilook`、减少日期/对数、关闭 APS 或 DEM 误差，或改用更大的机器。估算是近似的，只用于拦截明显不可能完成的任务，不预留内存。
- `load_stack()` 用 `np.load(..., mmap_mode="r")` 打开 `slc.npy`，原始栈不强制整体读入内存。
- `coregister_stack()` 用 `np.lib.format.open_memmap()` 直接写 `data/processed/slc_coreg.npy`，不再先用 `np.empty_like` 在 RAM 里建完整输出。配准峰值主要来自单景的 `warp` 输入/输出和参考振幅，约 `3.5 × rows × cols × 8` 字节；完整配准栈由操作系统按页缓存。
- 干涉阶段用 `downsample_complex_pair()` 按行块完成复共轭、干涉图和多视，避免全分辨率 `ref`、`sec` 和 `ifg` 同时驻留；块高由 `choose_block_rows()` 按预算计算。
- 参考像元选择改为流式累加振幅的一阶/二阶矩，不再把各采样时刻的整幅振幅堆叠成三维数组；闭合差统计的 wrapped 缓存改为最多 6 个数组的 LRU，避免大网络把全部缠绕相位留在内存。
- 去 ramp 只为采样像元构造坐标，不再生成全图 `mgrid`；趋势面按行块计算并从相位中减去，全图 `float64` ramp 不再存在。
- DS 不再保留全量 `(n_dates, n_dates, rows//m, cols//m)` 相干矩阵。`core/ds.py` 用 `COVARIANCE_BUDGET_BYTES = 256 * 1024 * 1024`（256 MiB，约 268 MB）计算行块高度，只为当前块分配 `(n, n, block_rows, cols)` 的 `complex64` 协方差并立即做特征分解；特征分解工作数组另受 `EIGEN_BUDGET_BYTES = 64 MiB` 约束，每批处理固定数量的像元。24 景、110 × 130 多视网格可整块处理，约 66 MB；60 景、500 × 500 多视网格的块高约 18 行，协方差缓存约 247 MiB（259 MB），而旧实现的全量矩阵约 6.7 GiB（7.2 GB）。
- DS 的成对相干性不单独保存为 `(n_pairs, rows, cols)` 全局栈；重建干涉图时由 `pair_coherence()` 按对重算，内存只与单幅多视网格成正比。
- DS 仍保留多视后的 `slc`、`diag`、`linked` 三份 `n_dates · R · C` 数组，以及分块特征分解的工作数组；这些随像元数线性增长，不再随历元数平方增长。
- PS 的 `amplitude_dispersion()` 按行块累加振幅的一阶/二阶矩，不再把约 12 个采样时刻的整幅振幅堆叠成三维数组；峰值内存与块高和影像宽度成正比。
- 反演在载入相位栈前调用 `estimate_inversion_peak()`，把相位、相干性、布尔掩膜、`float64` 观测向量 `Y`、逐日数组和分块正规方程工作区一起计入。分块高度由 `inversion_block_pixels()` 按日期数在 512–4096 像元之间选取（48 景为 3640），避免 `n × n × block` 的临时数组随时序变长而失控。93 对、49 万像元、48 景的 PS 大栈实测进程峰值 1.65 GB，估算 1.91 GB；旧实现约 5.2 GB。
- 稳健重加权每一轮同时更新观测向量 `Y` 和正规方程权重 `W`。旧实现只在循环外构造一次 `sqrt_w_full`，后续迭代虽然更新了 `w`，正规方程仍在用上一轮权重；修正后 canonical SBAS 的位移/速率 RMSE 从 `2.0812 mm / 3.1170 mm/yr` 降到 `1.8469 mm / 2.1370 mm/yr`，PS 从 `1.9285 mm / 3.6669 mm/yr` 降到 `1.8651 mm / 3.4372 mm/yr`，DS 基本持平。大栈 SBAS 的位移/速率 RMSE 略升（`1.857→1.961 mm`、`1.838→2.093 mm/yr`），但速率空间相关从 `0.957` 升到 `0.969`；保留修正是因为它让观测向量与正规方程在数学上保持一致。
- ZIP 导出不把文件读入内存，但会同时打开目标文件和遍历项目目录；压缩过程受磁盘 I/O 限制。
- `_json_body()` 在读取前检查 `Content-Length`，读取后再核对实际长度；默认 4 MiB 上限，超限返回 413，不会把超大 JSON 整体留在内存里。`MAX_CONTENT_LENGTH=512 MiB` 只对 GACOS multipart 上传生效（L27）。
- 内存估算没有覆盖 Python 对象、Matplotlib 图件、文件系统缓存和内存碎片；实际峰值可能高于估算值。真正的大栈仍应在目标机器上用 `stress/` 的规模测试记录 RSS。

### 12.4 磁盘

- 每个干涉对至少写 `wrapped.npy`、`coherence.npy`、`unwrapped.npy`、`displacement_mm.npy`、`mask.npy` 和 `meta.json`；GACOS 还会写 `atmosphere_pair_mm.npy` 与 `unwrapped_atmcorr.npy`。
- 反演产品再写逐日位移、速率、相干性、残差、DEM 误差、APS、有效掩膜、GeoTIFF、图件、报告和 ZIP。
- 演示四套项目合计约 339 MB；真实项目按对数、像元数和产品数量线性增长。
- 重跑阶段会先删下游再写新结果，峰值磁盘占用接近“旧产品 + 新产品”。磁盘不足时 `health.py` 在可用空间低于 2 GB 给警告、低于 200 MB 给错误，但不会阻止任务提交。

### 12.5 并发模型

- Flask 使用 `threaded=True`，每个请求一个线程；没有请求队列、连接池上限或速率限制。
- 每个作业一个守护线程。`JobManager` 保证“同一项目一个 exclusive 作业”，并用 `BoundedSemaphore` 限制全局同时执行的作业数，默认 2，可用 `INSAR_MAX_CONCURRENT_JOBS` 覆盖并夹到 1–32。超出的作业保持 `queued`，不会同时争抢 CPU、内存和磁盘。
- 作业线程与请求线程共享进程和 GIL；NumPy/SciPy 的部分运算会释放 GIL，但 Python 层的逐像元循环、JSON 读写和 Matplotlib 绘图仍会竞争。
- 没有跨进程锁。两个服务进程指向同一个 `workspace` 时，阶段清理、`.trash` 重命名和产品写入可能互相破坏。
- `workspace/cache/figures/` 的图片缓存没有加锁；并发渲染同一对图片时可能重复写同一个文件，但写入是覆盖式的，最坏结果是重复计算。

### 12.6 项目列表缓存与分页

项目库不再在每次侧栏刷新时读取全部 `project.json` 并递归统计每个项目。`ProjectStore` 维护两层进程内缓存：

- **目录清单缓存**：保存目录扫描结果和已读取的 `project.json`，默认 5 秒（`PROJECT_LIST_TTL_SECONDS`）后过期。
- **摘要行缓存**：只为实际请求到的页计算 `status()`、目录体积和栈指标，同样 5 秒过期；`create`/`save`/`update`/`delete`/`reset_derived` 会调用 `invalidate()` 立即清空两层缓存。

`GET /api/projects` 先按缓存滤、排序和分页，再只计算当前页的摘要行，避免为大项目库付出全量成本；`refresh=1` 供任务完成、阶段完成和外部进程写入后强制重扫。CLI 的 `ProjectStore.list()` 仍返回全部项目，行为不变。

本机 300 个项目（其中 30 个各含 50 个产品或数组文件）的基准：首屏 60 项约 `0.16 s`，缓存命中约 `0.003 s`，第二页约 `0.09 s`，强制刷新约 `0.16 s`，完整 300 行约 `0.41 s`。这些数字只用于判断量级，真实项目体积和磁盘状态会影响结果。

摘要行不再递归遍历项目目录统计体积。侧栏和项目列表本来就不显示体积，之前的 `rglob("*") + stat()` 只是在每次冷启动或缓存失效时白白扫描全部产品文件。现在摘要行只读取各阶段的小型 JSON 元数据：

- 31 个项目、合计 3.6 万个成果文件：冷启动从 `4.70 s` 降到 `0.098 s`，6 秒 TTL 过期后的刷新从 `4.52 s` 降到 `0.060 s`；缓存命中 `3 ms`。
- 项目概览默认不再返回成果文件清单，`GET /api/projects/<id>` 对 6000 文件项目从 `974 ms` / `567 KiB` 降到 `4 ms` / `4 KiB`。
- 成果页仍需要完整清单，`GET /api/projects/<id>/results` 按需返回；`product_files()` 改用 `os.scandir` 并对每个目录项只做一次 `stat`，6001 个文件约 `255 ms` / `567 KiB`。
- 目录在扫描过程中被任务删除时返回空结果或跳过该目录，不会把项目变成 404；符号链接按目录项本身处理，不跟随到项目外。

### 12.7 前端大数据承载

用独立压力工作区（200 个项目 + 1 个 1000 对项目 + 300 条作业记录）和真实 Chromium 无头浏览器测量（1440×900，本机）：

| 场景 | 实测结果 |
| --- | --- |
| 200 项目首屏（冷启动） | `1.08 s`，加载 60 项；`/api/projects` 冷启动 `217 ms` / `51 KiB` |
| 200 项目首屏（热缓存） | `0.90 s`；列表缓存命中 `8 ms` |
| 侧栏加载全部 201 项目 | `0.56 s`，无卡死；搜索在服务端执行 |
| 打开 1000 对项目 | `0.68 s`（概览接口 `156 ms` / `232 KiB`） |
| 网络步骤渲染 | `0.47–0.59 s`；1000 条 SVG 线 + 1000 行表格，约 1.1 万 DOM 节点，JS 堆 10 MB |
| 干涉步骤渲染 | `0.27–0.45 s`；1000 个下拉选项，JS 堆 10 MB |
| 3000 对项目 | 概览接口 `208 ms` / `488 KiB`；网络步骤 `1.18 s` / 3.3 万 DOM 节点；干涉步骤 `0.78 s`；JS 堆 10 MB |
| 作业接口 | `/api/jobs?limit=200` `3.9 ms` / `98 KiB` |

结论：1000 对以内无需为干涉对清单或下拉框加分页；3000 对仍可用，但网络页首次渲染已超过 1 秒。暂不预先加入虚拟滚动，避免复杂度换不来实际收益；若真实项目普遍超过 3000 对，再对表格行做分块渲染或虚拟化，网络图本身保留完整。

压力项目中未生成干涉图时，`peaks` 和 `pairs/<id>/image` 会返回 404；前端已把图片错误降级为“该场尚未生成”的空状态，`peaks` 失败也静默处理，不产生未捕获异常。

### 12.8 地理编码大网格

`build_lookup()` 不再一次性为整张地图网格分配中间数组，而是按行分块求解：

- 每块默认按 16 MiB、约 512 字节/像元估算，且不超过 10 万像元；
- 地图网格大于 25 万像元时默认使用最多 4 个线程；分块结果按完成顺序流式写回，未写回的分块最多 `workers × 2` 个；
- 输出 `row`/`col`/`height_m` 为 float32、`valid` 为 bool，20M 像元约 260 MB；
- `geocode.json` 的 `lookup_blocks`、`lookup_block_rows`、`lookup_workers` 和 `lookup_seconds` 记录本次求解配置与耗时。

线程只并行求解查找表；DEM 采样和 GeoTIFF 写出仍在调用线程中执行。分块和线程数不改变最终坐标，只影响峰值内存和耗时；不同分块得到的结果差异应小于收敛阈值。

### 12.9 性能瓶颈排序

1. PS 全流程最慢：canonical 中 45 对却比 80 对的 SBAS 更慢；48 景 × 700 × 700 大栈中 PS 93 对耗时 `698.2 s`，其中干涉 `473.1 s`、反演 `174.6 s`，而 SBAS 160 对为 `295.7 s`、DS 160 对为 `321.9 s`。PS 使用单视，逐对数组和选点开销都更大。
2. DS 协方差矩阵已按 256 MiB 预算分块，但特征分解工作量仍随历元数立方增长，60 景以上大栈依然慢；PS 选点还要逐对累加相干性，数组尺寸和多视设置会明显影响耗时。
3. 逐对读写大量 `.npy` 文件，磁盘 I/O 和杀毒软件扫描会显著拉长耗时。
4. 报告和 ZIP 同步执行，项目很大时 HTTP 请求会长时间占用一个工作线程，前端表现为“点击后没反应”。
5. 项目列表与项目概览已不再递归统计体积或返回文件清单，冷启动成本主要剩目录扫描与小型 JSON 读取；成果页的完整文件清单仍需遍历 `products/`，文件数特别多时首次打开会慢一些。项目体检仍会遍历项目文件。
6. 地理编码查找表已改为分块 + 多线程，但输出 GeoTIFF 数量随日期数线性增长；大网格长时序仍受逐产品双线性采样和磁盘写入限制。

## 13. 安全设计

### 13.1 默认攻击面

- 默认只监听 `127.0.0.1`，设计前提是本机单用户。
- 没有登录、会话、角色、API key、CSRF token、CORS 白名单、TLS 和速率限制。
- 任何能访问该端口的本机进程都可以创建、修改、删除项目，提交任务，读取项目内任意文件。
- 因此不要把 `INSAR_STUDIO_HOST` 设为 `0.0.0.0`，也不要用反向代理把它暴露到公网。

### 13.2 路径安全

- 项目 ID 白名单：只允许小写字母、数字、下划线；`ProjectStore.path()` 解析后必须位于项目根目录。
- 资产/下载：`safe_join(root, relative)` 解析后必须仍在项目根目录；越界返回 400。
- 干涉对编号：正则 `[A-Za-z0-9_-]{1,64}`，避免把 `../` 或路径分隔符带进 `interferograms/<pair_id>`。
- 导入路径是用户提供的本地路径，没有限制在项目目录内；这是导入功能的必要能力，但也意味着 API 调用者可以让服务读取本机任意可读路径。导入后的数据会复制到项目目录。
- 下载文件名经过 `safe_filename()`，只保留字母、数字、点、下划线、短横线，截断到 180 字符，避免路径分隔符和超长文件名。

### 13.3 凭据处理

- `public_params()` 会递归删除键名包含 `password`、`secret`、`token`、`authorization`、`credential` 的项，以及 `gacos_email`、`username`、`user`、`email`；`project.json`、`ProjectStore.save()`、`PATCH /api/projects` 和报告参数表都使用过滤后的参数。
- `core.utils.atomic_write_json()` 是所有 JSON 落盘的统一出口，写入前会递归调用 `redact_secrets()`：凭据字段保留键名、值替换为 `***`。因此 `data/processed/coreg.json`、`interferograms/summary.json`、`products/inversion.json`、作业记录和缓存文件都不会出现明文凭据。
- `JobManager` 在内存中保存作业结果前也会脱敏，`/api/jobs/<id>` 不会把请求里的 GACOS/下载凭据原样返回。
- 报告和 ZIP 从已脱敏的引擎摘要读取参数，且报告参数表再次走 `public_params()`，因此导出物中不含明文凭据。
- 前端把 GACOS 邮箱/令牌和下载账号放在请求体里，不写入 localStorage；但浏览器开发者工具、代理日志和错误文本仍可能看到请求体。不要在不信任的机器上输入真实凭据。
- `debug=1` 时 500 响应带 traceback，可能暴露本机路径和变量名；共享环境不要开启。

### 13.4 输出转义

- `app.js` 提供 `esc()`，对插入 `innerHTML` 的项目名、备注、消息、图件 URL 等做 HTML 转义。
- 这不是模板引擎的自动转义，而是手写字符串拼接；任何新增的插值点都可能漏转义。外部审查应把“项目名/备注/标签/日志/外部错误文本”作为 XSS 输入逐项测试。
- 项目名和备注在后端被截断（120/20000 字符），标签最多 20 个、每个 40 字符，但没有做 HTML 字符过滤；安全依赖前端转义。

### 13.5 明确没有的防护

- 没有认证和授权，也没有“只读模式”。
- 没有 CSRF 防护；依赖浏览器同源策略和“只监听本机”的部署前提。
- 已启用 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy` 和 CSP；`script-src` 为 `'self'`，但 `style-src` 仍允许内联样式，因为前端会动态生成 `style` 属性。
- 没有请求频率限制；作业有全局并发上限，JSON 有 4 MiB 上限，GACOS multipart 有 512 MiB 上限。
- 没有审计日志；作业日志只服务于进度显示。
- 没有数据加密；项目文件是明文 `.npy`、`.json`、`.tif`、`.csv`、`.md`、`.docx`、`.zip`。

### 13.6 部署建议

1. 保持 `127.0.0.1`，需要远程访问时使用 SSH 隧道或带认证的反向代理。
2. 不要在项目目录放私钥、口令文件或与处理无关的敏感资料；`asset`/`download` 能读取项目内任意文件。
3. 在线 GACOS 和下载凭据用一次性会话输入，不要写进项目备注或参数。
4. 处理不可信数据前，先在隔离目录和独立工作区运行；导入格式解析没有做模糊测试。
5. 定期备份 `workspace/projects/`；删除项目不可恢复。

## 15. 系统化测试建议

### 15.1 测试目标与分层

测试要回答四个问题：

1. **能不能跑通**：四条路线、五阶段、七步界面在干净环境里能否从数据到报告完整走通。
2. **结果对不对**：合成真值回归是否稳定；真实数据是否有合理的相干性、有效像元和速率量级。
3. **坏输入会不会破坏系统**：非法参数、坏文件、坏 JSON、路径穿越、并发冲突、进程中断是否只产生可解释的 4xx/失败作业，而不是半写产品或静默错误。
4. **边界在哪里**：多大的栈、多少对、多少项目、多长时间会触发内存、磁盘、线程或浏览器上限。

建议分六层：

| 层级 | 目标 | 主要手段 | 是否已有 |
| --- | --- | --- | --- |
| L0 静态与契约 | 语法、导入、路由数量、CLI 帮助 | `compileall`、`node --check`、路由枚举、`--help` | 部分有 |
| L1 单元 | 算法与工具函数 | pytest、合成数组 | 有多项 core 测试 |
| L2 集成 | 单路线全流程 | pytest + 临时项目 | 有 4 项（四条路线） |
| L3 API 契约 | 状态码、请求体、副作用 | Flask test client / HTTP | 有 46 项（含 GACOS 官方接口、安全头、导出、错误语义与列表分页） |
| L4 前端 E2E | 七步交互、轮询、下载 | 浏览器自动化 | 本次仅人工验收 |
| L5 非功能 | 压力、故障、安全、兼容 | 压测、故障注入、模糊测试 | 基本空白 |
| L6 真实数据验收 | 真实栈的可用性 | 外部预处理数据 + 已知参考 | 未在本版本执行 |

### 15.10 判定标准与记录模板

建议把“通过”拆成五个独立判定，避免用“跑完了”代替质量结论：

| 维度 | 判定 |
| --- | --- |
| 功能 | 请求返回预期状态码；作业最终 `done`；所有声明产物存在且可解析 |
| 数值 | 合成演示的 RMSE/相关不低于建议门槛；真实数据与已知参考的差异可解释 |
| 稳定性 | 无未捕获 500；无半写 JSON；失败后重跑可恢复；进程重启不损坏项目 |
| 资源 | 峰值内存、耗时、磁盘在预算内；不产生孤儿进程/临时目录 |
| 安全 | 路径不越界；脚本不执行；凭据不出现在不应出现的位置；错误不泄露堆栈（非调试） |

合成演示的建议回归门槛（不是对外精度承诺，可按机器和依赖版本调整）：
